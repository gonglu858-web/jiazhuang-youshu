## 2. 工具用法

```bash
# 生成窗口候选（window ∈ P/E/X；plan 为业务计划 JSON，见 §3）
node miniapp/scripts/package-business-test.cjs --window P --plan <plan.json绝对路径>

# 校验既有候选目录（manifest/来源绑定/变换复核）
node miniapp/scripts/package-business-test.cjs --check <候选目录绝对路径>
```

- 输出目录固定在 `artifacts/schedule-sandbox/business-test/` 下（工具强制，已 gitignore，可随时重建）。
- 每次构建产出 19 个候选文件 + 19 个关闭包文件 + `manifest.json`（内容寻址，无时间戳，重复构建字节一致）。
- **关闭包**与候选同轮产出：manifest 内含候选文件清单、来源 SHA-256、变换步骤与计划摘要，独立可检查。

## 3. 计划 JSON（business-test-plan/1）

必填字段：`schema`、`window`（P/E/X）、`synthetic: true`（本地准备一律合成）、
`businessRoundId`（4–64 位字母数字-_）、`windowNo`、`appId`（固定）、`envId`（固定）、
`users`（owner/manager/worker 的 userId+source）、`projectReadyMarker`、
`windowStartsAt`/`windowExpiresAt`（≤ 2 小时上限）；E/X 还须 `projectId` 且**必须等于**
`p_sbx_ + sha256(businessRoundId)[0:32]`（project-guard 同算法，绑定不符即
`BTP_PLAN_PROJECT_INVALID` 拒绝）。

三个窗口的语义（动作收窄由工具对 `gate.js` 做受审锚点替换实现）：

- **P（成员准备）**：`createProject`/`assignManager`/`createInvitation`/`approveInvitation` 等
  准备动作；phase 固定 prepare，执行期动作清单不可达。
- **E（基本安排）**：`createSchedule`/`updateSchedule`/`cancelSchedule` 等安排动作 + 只读；
  phase 固定 execute，管理动作不可达。
- **X（专用 V07 移出）**：`cancelSchedule`/`removeMember` + 只读；前端 driver 变换为
  `TEST_CASES = Object.freeze(V07_CASES)` —— **仅 V07-A/B 可运行**，V06 开放用例被
  `TEST_DRIVER_UNKNOWN_CASE` 零发送拒绝（不附带开放 V06）。

所有变换均为「唯一锚点替换」：锚点缺失（`BTP_TRANSFORM_ANCHOR_MISSING`）或多处命中
（`BTP_TRANSFORM_ANCHOR_AMBIGUOUS`）即拒绝构建；替换前后与源文件钉定 SHA-256
（`package-sandbox-registration.cjs` 的 `PINNED_FACTS`，38 文件）逐一核对，源漂移即
`BTP_SOURCE_DRIFT` 拒绝。
