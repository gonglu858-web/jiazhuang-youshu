## 3. 工具用法

```bash
# 生成窗口候选（window ∈ P/E/X；plan 为业务计划 JSON，见 §4）
node miniapp/scripts/package-business-test.cjs --window P --plan <plan.json绝对路径>

# 校验既有候选目录（从独立受审来源+严格计划重建精确制品逐字节比对）
node miniapp/scripts/package-business-test.cjs --check <候选目录绝对路径>
```

- 输出目录固定在 `artifacts/schedule-sandbox/business-test/` 下（工具强制，已 gitignore，可随时重建）。
- **check（R1）**：不信任自报清单——manifest.planSha256 锚定 plan.json，重跑 readPlan 核对
  planDigest，再按 manifest 字段一致性 → 钉定来源重建预期制品逐字节比对 → 精确文件集
  （空清单、多余/缺失/重复/路径越界、同步改哈希的动作扩大、synthetic 模式篡改均拒绝）。
- **时钟（R2）**：build/check/复用/续建各边界重读当下时钟；真实模式过期
  （`BTP_WINDOW_EXPIRED`，含 expires==now 边界）、时钟无效（NaN）、时钟错误、窗口未开
  均独立记录并停止；合成模式跳过。异常时报告本次准确已写事实（`error.written` 相对路径
  数组 + `error.wroteFiles`），不虚报。
- **冲突（R3）**：全部冲突预检（`precheckOutDir`：符号链接/目录占位/多余文件 →
  `BTP_OUT_CONFLICT` 零写）通过后才写，逐文件排他新建（flag:'wx'）；保留合法续建
  （只补缺失）与完整复用。

## 4. 计划 JSON（business-test-plan/1）

必填字段：`schema`、`window`（P/E/X）、`synthetic`、`businessRoundId`、`windowNo`
（须以窗口号开头）、`appId`、`envId`、`users`（owner/manager/worker 的 userId+source）、
`projectReadyMarker`、`windowStartsAt`/`windowExpiresAt`（≤ 2 小时上限）；E/X 还须
`projectId` 且**必须等于** `p_sbx_ + sha256(businessRoundId)[0:32]`（绑定不符
`BTP_PLAN_PROJECT_INVALID` 拒绝）。未知字段拒绝。

**真实模式（R5）**：`synthetic: false` 时须附可核对的参与者证据与 P 项目回读证据——
`participantEvidence[role] = { kind:'readback-record', recordSha256(64hex) }`；
E/X 另须 `projectReadback = { source:'readback', projectId, businessRoundId,
projectReadyMarker, recordSha256 }` 全字段绑定，缺任一项或字段不符即拒绝
（来源声明与证据均计入 `planDigest`，来源文本变化即摘要变化）。

三窗口语义不变：P 准备（phase=prepare）、E 基本安排（phase=execute）、
X 专用 V07 移出（`TEST_CASES = Object.freeze(V07_CASES)`，仅 V07-A/B，V06 零发送拒绝）。
所有变换仍为「唯一锚点替换」（缺失/多处命中即拒），替换前后与钉定 SHA-256 逐一核对，
源漂移即 `BTP_SOURCE_DRIFT` 拒绝。**组装（R4）**：候选含 4 个组装钉定文件，app.json
pages 收窄为唯一页面入口，project.config.json 根为 `frontend/` + `server/`，
输出即完整小程序项目。
