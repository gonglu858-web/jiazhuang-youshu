## 1. 结论

**真实 CLI 登录及本轮指定的云身份/环境关联只读核验通过。** 查询确认当前授权角色所属云账号与目标环境归属账号一致，环境正常、上海地域、关联微信 AppID 与项目固定值一致。

这关闭的是“CLI 能否真实登录和读取指定身份/环境信息”的缺口，不代表 P4 初始化授权、本地数据库 SDK 已使用相同凭据、人员允许名单已建立、平台事务或部署通过。

## 2. 登录隔离与实际经过

- 源码确认：当前包的登录存储以 `os.homedir()/.config/.cloudbase` 为根；不是只由 CLI 安装目录决定，不能仅移动工作目录就声称隔离。
- 使用独立目录 `C:/Users/30591/.codex/tmp/cloudbase-readonly-cli-3.8.4/auth-session-20261007`。仅对子进程设置 USERPROFILE，并在启动 CLI 前用 Node os.homedir() 验证确实指向此目录。未改系统/用户永久环境变量。
- 子进程移除继承的 CLOUDBASE_、TCB_、TENCENTCLOUD_ 认证/配置变量及 NODE_OPTIONS，再显式设置上海地域、NO_UPDATE_NOTIFIER=1、TCB_DISABLE_REPORT=1；工作目录同为上述新目录。未读取原有登录缓存或密钥值，未复制 MCP 凭据。
- 执行官方 `login --flow device -r ap-shanghai`，用户在官方网页完成授权。设备授权码只用于当次登录，不写入本报告。
- CLI 输出 login succeeded 后出现可选使用数据收集问题，管道输入结束导致进程 exit 1。没有将这一退出码冒称正常成功，也没有重新登录或同意采集。后续签名 API 成功证明此次登录态已可用。每次后续命令仍显式禁用报告。
- 官方登录会保存其自己的本地认证状态；这属于此次用户允许的登录，不是业务数据库写入。本轮未运行 secrets get、未输出或保存原始密钥/Token/OPENID。
