## 2. 两条可选路线

### A：准备固定候选文件只读核验（建议）

先准备并审查驱动及离线反例，不立即执行。唯一目标为C:\Windows\System32\conhost.exe，不接受CLI/环境覆盖，不遍历目录、不查询同名文件。目标是取得“检查时这个固定文件”的可核对事实，以决定是否值得继续研究来源，绝不把静态检查命名为已退出成员真实性证明。

拟收集：固定目标存在/类型/链接判定、一次受控文件读取的大小和SHA-256、可离线确认的签名核验状态。公开证据只输出固定目标标签、必要文件摘要及状态；不输出任意路径、证书原文、用户名、命令行、环境或原始错误。SHA-256是新收集的系统文件指纹，须作为范围变化明确告知用户；摘要本身不是可信基线。

签名核验的具体API/工具尚未选定。实现前须核对权威接口语义及本机已有可用能力：禁止联网取证书/撤销信息、修改证书库/缓存、提权、改ACL或安装工具；不能承诺任意现成签名命令天然零网络/零写。如果无法证明可满足离线边界，停止并明确缺项，不用跳过验证后仍宣称可信。未获独立受信预期时不把现场读到的摘要反写为“预先受审摘要”。

文件与句柄一致性要求：预检、持有句柄、从同一数据来源计算摘要、签名判定与被验字节的对应关系分别设计；不能先验一个文件再重开另一个内容而声称已绑定。若平台只能按路径验签，需要披露对应关系局限并停止升级为强绑定结论。符号链接/重解析、读取失败、文件变化、签名不明或状态不一致均失败闭合。

下一节点交付为本地驱动草案/离线正反例及固定一次查询页；查询本身在审查后独立执行，异常即停、不重试。不启动候选、不启动helper或Node树，不推进父链查询。

### B：不扩大取证范围，先补齐C#合成验证

保持所有系统文件/进程查询停止，先为实际C#分类器及Capture设计合成边界测试：使用真实受审源码、固定底层替身，覆盖大小写/路径形状、状态失败、创建时间与Job变化、只读一次路径、未知保留、秘密不回显及句柄收尾。不将JS模型冒充C#执行。

先准备并审查测试方案及驱动，编译/执行另按固定配置分节点。不得借反射或抽取源码绕过既有宿主/策略限制，不修改产品身份权限或历史源码。此路线提高实现证据质量，但不能解释本机两个额外进程，四成员阻断仍在。

## 3. 父链阶段暂不实现

无论选择A或B，都不立即增加父链API。下一份父链方案必须先定义证据目标：观察到的父标识、父进程身份一致性、父创建时间与存活/句柄关系、属于本Job的证据、关系来源可信度。单个父PID、事件先后、同名文件、当前重新打开旧PID均不足；系统报告的父标识也不自动等同于真实创建因果。

范围上限仍是新受控Job内已确认成员及已持有身份；不为追溯额外枚举全系统、读取任意命令行、日志、WMI/ETW会话或认证缓存。若候选关系必须越出Job才能解释，标UNKNOWN并停止，另给用户选择。不能先扩大采集再补授权。

具体接口/结构布局/权限与版本兼容性尚未定，不在本方案虚构已经存在的可靠方法。实际API选型应有权威文档依据与本地结构验证，离线替身必须涵盖PID复用、已退出、权限拒绝、关系变化、跨Job、容量/时限及清理失败。采样不完整不补造父链。任何后续实测须新版本、新证据且单次执行，结果后停止。
