目标是区分：计数读取/结构解释问题、固定Node父子之外确有成员、成员身份仍不完整。不得先认定多出来的是控制台宿主或安全软件；不得以名称相似、微软签名或总数恰4作为放行条件。

## 3. 最小诊断设计

### 3.1 先检查计数解释

离线核对现有Accounting的字段类型、偏移、对齐、总长度与调用信息类别；用非对称值的合成原始缓冲区验证Marshal读取，避免把Total、Active、Terminated错位解释。原实现的结构检查不等于真实系统计数已被独立证实。

拟新增的Windows接口、结构及常量必须在实现审查中附可核对的受信定义来源；不能凭接口名称猜布局。未完成定义核对时只交付阻断说明，不编译。上述是本地准备验收要求，本轮未调用这些接口或完成其运行验证。

### 3.2 固定Job内观察

保留固定Node路径/完整摘要、原normal参数逐字节、环境净化、挂起创建→加入Job→恢复、KillOnJobClose及严格计数2门槛；不以延长Node子进程存活、额外创建观察子进程或改变控制台启动标志制造通过。

建议在分配/恢复前为本次新建且不可继承的Job关联私有完成端口，以获取成员进入/退出提示；结合该Job的成员PID列表和Accounting采样交叉核对。完成端口事件是线索，不作为完整审计日志保证：不得假设无事件就是无进程，也不得仅以队列暂空认定所有事件收齐。

成员观察仅允许来自该Job成员列表或该Job事件提供的PID；再核验目标属于本Job。只申请最小查询/同步权限，尽可能持有句柄直到最后核对。记录PID与创建时间区分PID复用；打开失败、退出过快、成员归属无法确认、前后身份变化均标记unknown，不改为成功。

已有根句柄优先复用，不按根PID重新打开替代。根外成员若在可查询前已退出，应保留“事件观察到但身份未取得”，不能通过同PID后来出现的进程补齐。生命周期、事件数和Job累计数之间有差异时明确记录，不把重复事件简单相加成进程数。

### 3.3 身份与父子关系分开证明

身份取证候选是基于持有句柄的映像路径与创建时间查询；只读、不得附加调试器、注入、读取内存/环境/命令行或令牌。完整路径只在内存用于固定路径比较，不输出用户目录；证据使用FIXED_NODE、OTHER_IMAGE、UNKNOWN等固定标签。仅路径匹配不称为完整映像真实性证明，固定Node现有持有文件摘要证据另列。

成员归属Job不等于父子关系。原脚本设计为一父一子，只证明设计意图。目标父PID取证接口若需要未批准的全系统进程枚举/日志/新增宿主，应先停止扩展；本轮准备不默认允许Toolhelp全进程快照、WMI、ETW系统会话、任务列表或事件日志查询。

如不能在上述边界内可靠取父子关系，字段必须为UNKNOWN，并将“来源链未闭合”列为阻断；不要仅凭相同映像、时间接近或PID大小构造父子链。可在后续方案提出固定合成Node自报PID/PPID/子PID，但这改变原参数和时序，是另一个实验，不混入本次保留原normal参数的复现。

### 3.4 不扩展文件读取

不得按发现的任意映像路径读取文件/计算摘要/验证签名。只有预先批准并钉定的输入可以读文件；未认识的成员先归OTHER_IMAGE。需要更细分类时另行约定具体目标及只读字段，不把动态路径当成文件读取授权。证据不含原始路径、任意错误文本、真实账号、凭据或私密内容。

## 4. 判定、限额与收尾

分列三个事实：诊断程序运行是否正确、成员证据是否完整、原normal是否满足严格2成员条件。来源记录更完整也不能将4成员的原normal标为通过；L2执行放行始终false，传输始终未运行。

建议上限：仅一个受控辅助程序直接启动；normal运行期沿用5秒，错误收尾2秒，父层期限10秒；输出总量128KB，成员记录最多16个唯一身份、事件最多128条。达到任一上限即失败并收尾，不截断后称证据完整。不无限等待短命进程或漏事件。

结束前依次核对根退出、Job活动数0、输出读取线程结束、观察线程结束、所有进程/Job/完成端口/管道/文件句柄释放。保持对自己创建且分配成功的Job终止权限；不得按名字或全系统PID清理。未分配根按既有持有句柄清理，收尾不明立即停止；不启动后续诊断或传输来验证是否清干净。

新增观察失败不得遮盖原失败或清理失败；原生回执、驱动校验、最终ok/exit须一致。最终唯一判定位于全部读取、摘要、观察线程和收尾之后；之后只序列化新文件。默认stdout，指定--out仅允许冻结的新路径且wx新建。旧失败JSON不得覆盖。

## 5. 离线验收矩阵

使用真实交付代码及最底层OS替身；不得只用字符串存在检查代替状态机行为。C#若只能静态核对，需将动态缺口单列，不能把JS模型通过写成C#运行通过。

- 计数字段：非对称缓冲区、错误长度/布局/调用失败、Total与Active区别；已退出成员仍计入累计数。
- 成员流：恰两个固定成员对照；四成员且身份已知仍原normal拒绝；成员不足/重复/乱序/丢事件/成员列表与累计数不符均不伪造完整性。
- 身份：短命退出、访问拒绝、PID复用、打开前后归属变更、创建时间缺失、父链缺失、陌生路径，均unknown或失败；未知不转已批准系统辅助进程。
- 能力：任意程序/模式/参数/PID/路径/输出位置拒绝；无公共进程、网络、系统枚举、权限或策略修改通道；被catch守卫命中实际决定失败。
- 时效与容量：期限、事件/身份上限、stdout/stderr限额、观察线程未结束、Job清理失败、句柄关闭失败；失败不能继续传输。
- 证据：摘要漂移、回执缺失/矛盾、晚期意外、未知字段、最终成功与退出矛盾均拒绝；旧字节及AGENTS修改保护。
