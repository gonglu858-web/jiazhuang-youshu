位置：`CodeBuddyI1提前准备分离证据v2-20261018.cjs:18`、48–50、140–144、395–399。

### R2 / C2-b（P1，证据）：子回执没有统一校验、汇总及决定成败

位置：同脚本105–106、306–316、377–383、397–399；测试E5的p4/p5等同类分支。

makeRunner只JSON.parse；p4、p5只断言业务返回，不校验回执。childUnexpectedTotal直接写死0，ok没有子回执项。F子反例只生成parentWouldFail布尔值，没有让真实父判定出口失败。

三个独立反例均被错误接受为ok=true/exit0：

1. 仅给`--plan`子进程加被catch的https.request：实际回执unexpected长度1，最终childUnexpectedTotal仍0。
2. 仅让该子进程不写回执：实际receipt=null，父证据仍通过。
3. 子回执仅有`{unexpected:[]}`（故障探针时为非空数组），缺pid/exitCode：全部仍接受。

修复：所有runner结果在统一入口核对结构、预期子pid、实际退出状态、回执缺失/畸形、守卫计数、超时/启动失败；预期CLI业务exit1不豁免回执检查。实际逐次累计子意外/回执失败，参与最终ok和退出码。专门敏感性子运行独立分组，必须演示被测父出口真实exit1，不能只计算“会失败”。E5覆盖同规格失败出口。输出上限按实际接收字节截断并记录，错误/超时/截断都不得被调用方忘记处理；自反例runner也需同等控制。

### R3 / C2-c（P1，证据）：脚本路径白名单仍允许绕过受控runner

位置：同脚本36–41。

cp.spawn只检查Node路径与脚本首参数，不要求守卫preload、回执或预期参数。独立副本在业务阶段直接spawn本包CLI且不附preload，受审守卫放行且不计数；Codex外层阻断（未启动此子进程），受审证据仍父意外0/ok=true/exit0。

修复：公共child_process API默认拒绝，只有私有受控runner持有原始spawn并构造固定命令、参数、preload和回执，禁止依靠“同脚本名”豁免。还需对齐原任务网络面：父进程缺Socket.prototype.connect，子preload缺dns.promises同名API。不得为测试真实调用这些网络面；以外层兜底阻断验证守卫敏感性。正常本地CLI应仍可运行。

### R4 / C1-a（P2，产品CLI）：空字符串值仍触发默认输出

位置：`miniapp/scripts/package-participant-identity-check.cjs:1127–1139`。
