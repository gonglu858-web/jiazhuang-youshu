## 4. R2/R3：写前预检、检查与复用

输出只在 `artifacts/schedule-sandbox/registration-<安全编号>/`，
不允许指向源目录、旧关闭包、祖先或链接。
写入前枚举制品整棵树：顶层只允许 manifest 和 package，
子目录及文件按明确白名单检查（含空目录）。

- 无 manifest 的半成品也完整检查；已有冲突、链接、额外项、非普通文件均**零新增、零覆盖**。
- 合法半成品仅复用与期望逐字节相同的文件；用独占写入只补缺项，最后写 manifest。
- 已有 manifest 的包若缺项，拒绝补写；同目录复用比较**完整语义计划**，
  包括 synthetic、用途、开始记录、截止和来源。相同计划复用不改任何字节。
- 真正进入写入阶段后注入的 EIO 会返回未完成、保留已写半成品；不递归清理。
  排除故障后再预检，匹配的已写内容可合法续建。
- 检查器从独立来源与已校验完整计划重算全部服务端和两份前端文件，
  不信前端自报哈希。manifest 全契约比较：文件集合/重复/多余/缺失、
  字节数/哈希、来源、差异、动作、用户、关闭绑定、依赖和固定状态。
- deploymentAuthorized=false / cloudExecuted=false 是清单事实，**不是授权句柄**。
  仅检查生成时间格式；它不是可信时钟或审批记录，不增加签名或授权体系。

检查只读，不补文件、不修复清单。每类反例直接调用实际 build/check，
并比较目录快照、原字节和零新增；不是靠旧缺陷脚本“不再复现”替代闭合证明。
