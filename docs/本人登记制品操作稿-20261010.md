## 1. 登记实际会做什么（服务端硬约束）

| 项 | 事实 |
| --- | --- |
| 允许动作 | **仅** `identify`。原 prepare 允许 15 个动作，登记制品里已收窄为 1 个 |
| 首次登记写入 | 测试 `users` 一条 + `registerIdentity` 审计一条（同一事务） |
| 明确不做 | 不写 primary、不取号、不建项目、不复制旧用户、不加角色、不安排施工 |
| 会读取 | 测试 primary（判断是否管理员）、本轮项目记录（如实记录，不宣称只访问两个集合） |
| 已有合法账号 | 零新增、不重复审计 |
| 停用 / 归属不符 | 拒绝，且**不覆盖**原记录、不自动修复 |

「最多新增 1 条用户 + 1 条审计」是**预期**，实际以平台提交/回读为准；不把成功响应或
调用次数当作写入条数。

## 6. 使用工具（本地，默认零副作用）

新增 `miniapp/scripts/package-sandbox-registration.cjs`（**不修改**旧打包器，
只复用其安全能力）：

```
# 默认检查模式：零云调用、零凭据获取、零写盘，只列缺项
node scripts/package-sandbox-registration.cjs --check

# 生成：必须显式 --mode build 并提供完整计划文件
node scripts/package-sandbox-registration.cjs --mode build --plan <plan.json>

# 检查指定产物：重算与受审源转换结果的一致性，不信 manifest 自报通过
node scripts/package-sandbox-registration.cjs --check --target <目录>
```

工具**不含** deploy / execute / login / upload / preview 操作，也没有 shell 拼接。
计划字段白名单：固定目标、单一完整用户名单、轮次、开始/截止时间、来源版本、用途；
禁止任意环境/函数/集合/运行时/依赖/源码路径。占位字符串、空名单、非唯一用户、
超 30 分钟窗口、真实计划过期、来源漂移一律拒绝。

输出限定 `artifacts/schedule-sandbox/registration-<安全编号>/`。同目录同内容可复用；
**不同内容拒绝覆盖**；缺文件、额外文件、路径逃逸、链接、伪造 manifest 一律拒绝。
**不递归删除**；真实写盘失败保留半成品并明确未完成。
