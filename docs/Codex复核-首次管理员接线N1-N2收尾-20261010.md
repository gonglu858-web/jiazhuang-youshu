## 2. N1 剩余：异步核对回调缺 await（P2）

位置：`miniapp/scripts/lib/sandbox-primary-execution-host.cjs:1423–1441`。

原接口允许异步回调；新增实现用 `injected = o.inject(...)`，没有 `await`，随即运行 AFTER_INJECTED_RECONCILE 和 finalizeDeadline。返回对象中的 raw 仍是 Promise，async 函数不会自动等待对象内部的 Promise。

独立证据：

1. `N1-async-injection-completes-too-early` 用可手动放行的事件屏障：宿主已返回，回调尚未结束，rawIsPromise=true。随后放行回调并推进时钟至过期，已返回 expiredAtStage 仍为 null。不是按 now() 次数猜阶段。
2. `N1-async-valid-callback-result-lost` 在 executeOnce 传合法异步 present 结果，最终却 unconfirmed、reconcileConfirmed=false；原正常异步契约被误拒。

本问题影响离线注入路径，**不推翻已验证的默认 P4 两读时效路径**，也没有在本次样本中升级为错误成功。静态上，同一 try/catch 也捕获不到异步 rejection；本轮未制造未处理 rejection 进程崩溃，不声称该崩溃已经实测。

最小修正：等待回调真正完成，将成功、异步拒绝都纳入既有异常处理与后置时效检查；不扩大注入权限、不新增生产调用入口。补异步有效正向、事件屏障后过期、异步拒绝三例，确认无 Promise 流入净化、无未处理 rejection。默认 P4 路径保持不变。

## 3. N2 剩余：聚合检查仍不完整（P1）

位置：host `1311–1326` 的 contradictions 构造、后续保存 COMPLETED 分支。

### 3.1 observed 的资格状态没有纳入成功条件

目前观察确认只检查 state=present 与两条存在性；没有要求已净化 primaryStatus=active。

实测两例：键/摘要、bootstrap 和其它字段全部沿用成功对照，只分别改 observed.primaryStatus 为 disabled、或删除该字段。两例均 `initialized=true/observationConfirmed=true/resultPersisted=true`，保存 **COMPLETED**；最终报告仍保留 disabled/null 状态。两例未发任何数据库读写，只验证父层对损坏 worker 协议的接受，不声称真实 worker 或真实账号曾产生此状态。

`projectReconcile` 已有 STATUS_NOT_ACTIVE 检查，但不能替代 `projectWorkerOutput` 对 worker 正常返回路径的检查。

### 3.2 initialized 与 UNKNOWN outcome 同时成立仍被接受

当前只有 `out.outcome==='initialized' && bs.outcome!=='initialized'` 这一单向检查。将顶层和 bootstrap.outcome 同时改为 UNKNOWN，保留两层 initialized/granted=true，仍保存 COMPLETED（`N2-still-completed-unknown-outcome`）。

最小修正：在现有聚合点按**合法结果组合**统一定义条件，明确初始化成功、已有记录观察、失败/未知各自应有的 outcome/布尔/观察状态。未知或缺失不能承载“已初始化”的肯定事实；active 必须由观察状态支撑。不只是继续针对样本堆叠不相干的 if，也不要要求所有合法的已有记录分支均 initialized=true。

验收：本报告三个样本贯穿 executeOnce 到保存载荷；非 active/缺状态不能确认，UNKNOWN 与 initialized 冲突不能保存 COMPLETED；真正提交成功但回读失败仍保留可绑定的提交事实，正常完整链与合法已有记录分支不被误伤。只改本轮 host 与相称测试，不改 worker、P4、适配器来迁就断言。
