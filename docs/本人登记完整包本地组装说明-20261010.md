## 9. 组装完整性

沿用既有目录边界，不扩大成通用发布框架：

- 输出限定 `artifacts/schedule-sandbox/registration-full-<安全编号>/`，
  不可逃逸、不可与输入登记制品/受审关闭包/源目录/任何既有制品重叠，同命名空间内禁止互相嵌套；
- **整棵树写前预检**：额外文件、额外目录（含空目录）、非普通文件、任何层级的
  符号链接或 Windows 目录联接一律拒绝；
- **输出冲突在任何写入之前发现**，实测零新增、零覆盖；
- 有 manifest 却缺文件 → 拒绝补写；无 manifest 且已有字节完全正确 → 只补缺项；
- 相同完整输入复用 → 不重写 manifest，零字节改动；
- check 模式**从受审来源与完整输入重算**内容，既验字节也验配置意义，
  **不信 manifest 自报哈希**；改字节并自报新哈希仍被拒；
- 缺失/多余/重复条目、改轮次/目标/窗口/合成标记、旧路由混入均拒绝；
- **无云调用、无自动安装、无修补**；写入期真实 I/O 失败保留可审查半成品，**不递归删除**。

## 10. 两种本地制品分类（synthetic / real-candidate）

组装器有两种**本地制品分类**（`artifactKind`）。它只是本地文件分类标签，
**不是权限凭据**，也不表示部署批准、本人身份已复核或云端已登记。

| 分类 | 选择方式 | 接受的计划 | 清单 schema | 时效口径 |
|---|---|---|---|---|
| `synthetic`（默认） | 不指定，或 `--artifact-kind synthetic` | 仅 `synthetic=true` | `sandbox-registration-full-assembly/1` | 沿用 `manifest.generatedAt`（历史可复验） |
| `real-candidate` | **必须**显式 `--artifact-kind real-candidate` | 仅严格 `synthetic=false` | `sandbox-registration-full-assembly/2`（**独立**） | **当前时钟**（`Date.now()`） |

### 10.1 合成模式（默认，原契约不变）

```text
node miniapp/scripts/assemble-sandbox-registration.cjs --mode build \
  --plan <合成计划.json> --input artifacts/schedule-sandbox/registration-<输入目录>

node miniapp/scripts/assemble-sandbox-registration.cjs --check \
  --input artifacts/schedule-sandbox/registration-<输入目录> --target <组装目录>
```

默认仍拒绝 `synthetic=false`，保留 `ASM_PLAN_SYNTHETIC_ONLY` 防线。
合成清单沿用 `/1` 的**原受审契约与确定性字节**：`artifactKind` 与
`verificationKind` 是候选 `/2` 独有键，**不进 `/1`**。
真正由旧版本模块生成的 `/1` 包可被本版 check 与完整复用（默认或显式
`--artifact-kind synthetic`），且复用时 manifest 字节不变；
旧包字段被篡改仍被严格拒绝。

> 修复记录：此前 `buildManifest` 无条件给两种模式加入这两个键，
> 导致真正的历史 `/1` 包被误拒。现已恢复 `/1` 原契约；
> `/2` 的独有字段与严格检查独立处理，不靠「容忍缺字段」兼容，
> 也不修改旧制品补字段。

### 10.2 真实候选模式（显式选择）

```text
node miniapp/scripts/assemble-sandbox-registration.cjs --mode build \
  --artifact-kind real-candidate \
  --plan <真实计划.json> --input artifacts/schedule-sandbox/registration-<输入目录>

node miniapp/scripts/assemble-sandbox-registration.cjs --check \
  --artifact-kind real-candidate --plan <真实计划.json> \
  --input artifacts/schedule-sandbox/registration-<输入目录> --target <组装目录>
```

> 上面的命令**只是形态示意**：本轮不确定实际登记轮次、开始时间与截止时间，
> 因此**不填当次真实窗口，也不得当作可直接部署的指令**。
> 真正执行前需要 Codex 核对依赖/运行时、远端代码回读、费用余量与目标账号，
> 再由用户确认具体执行包。

边界与要点：

- **候选 check 必须提供外部完整 `--plan`**，不接受只凭 `manifest.plan` 自证
  （`ASM_PLAN_REQUIRED_FOR_REAL`）；模式不能由磁盘 manifest 悄悄开启。
- 候选模式**只接受** `synthetic=false`；合成计划改标记也不会被默许（`ASM_PLAN_SYNTHETIC_IN_REAL`）。
- 未知取值、缺值、重复指定一律在写入前拒绝；**不提供** `--force`／跳过检查／
  改目标／时钟覆盖等绕过开关。
- 两种模式**不能互相认领同一目录**：候选只认 `/2`，合成只认 `/1`，
  交叉使用返回 `ASM_ARTIFACT_KIND_CONFLICT`。
- 候选清单标注 `verificationKind=OFFLINE_CONTRACT_FIXTURE`，
  `deploymentAuthorized/cloudExecuted/uploaded/previewed` 恒为 `false`。

### 10.3 当前时钟时效（候选模式）

候选的 **build / check / 完整复用 / 合法半成品续建** 一律按**当前时钟**判定：

- `expires <= now` 即拒绝（`ASM_WINDOW_EXPIRED`；也可能先被生成器的
  `REG_PLAN_WINDOW_EXPIRED` 拦下 —— 同样严格，且更早）；
- **不得**用 `generatedAt`、文件时间或历史证据时间替代当前时钟。
  篡改 `generatedAt` 不能让过期包通过；
- **每个时效边界都重新读取当前时钟**，不复用调用开始时的那个数值。
  边界包括：来源/重算阶段、预检后与写前、复用返回前、续建补写前、
  写入完成后、返回成功前。同一阶段内传给原生成器的是该阶段的一致快照；
- 命令行**不传**固定时刻，生产路径一律走 `Date.now()`，
  避免提前固定一个数值使后续边界永远使用旧时间；
- **预检后/写前到期** → 零写、目录快照不变；
  **写入后才到期** → 保留已写产物，如实报告 `wroteFiles=true`、
  列出已写文件并标记 `expiredAfterWrite`，**不删目录、不伪称零写**；
- 窗口长度上限仍是 **≤30 分钟**。

> 修复记录：此前实现只在调用开始取一次时刻并在各阶段重复使用，
> 导致「组装进行中到期」被误报为成功。现已改为逐边界重读，
> 并以**实际事件**（读取受审来源文件、写完首个输出文件）推进受控时钟验证，
> 不用 `sleep`、不靠恒定 `nowMs` 自证。

### 10.4 windowStartsAt 不是服务端守卫

`windowStartsAt` **不是**现有服务端的“未到时不可调用”守卫。
候选包在窗口开始前生成，**不证明**部署后要等到开始时间才开放。
**启用时间须由未来部署流程控制**；本轮未改 `gate.js`，也不宣称其提供开始时间保护。

### 10.5 过期不等于关闭包失效

**登记候选过期只否定它当前可用，不代表关闭包失效。**
关闭依据独立受审关闭制品与实际字节回读；
**不把“整个登记候选仍在有效期”设为关闭的前置条件**，
关闭包也不靠重新开启登记窗口获得使用资格。本轮未新增关闭部署工具。

### 10.6 输出与既有保护

沿用 `registration-full-<id>` 受限目录、两项目各 24 文件共 49 文件、单页、
八文件逐字节来源、默认随机编号/显式编号复用。原目录重叠/链接/额外项/冲突预检、
独占写入、合法半成品续建与带 manifest 缺文件拒绝等要求全部保留。
服务端只允许 `identify` 的限制继续来自既有登记生成器，**未新增权限**；
旧入口与前端驱动保持关闭。

**不能把制品根整体上传**：顶层同时含两个项目、两个云函数版本。
清单只承认单项目根 `registration-project/` 或 `closed-project/`。
**云函数目录名即函数名**，部署时不得提交名为 `package` 的目录。

### 16.1 R1：各时效边界重新读取时钟

此前实现只在调用开始取一次时刻，之后各阶段重复传同一数值，
导致「组装进行中到期」被误报为成功。现改为：

- 引入时钟读取器，**每个时效边界各自读取当前时钟**，不复用启动时刻；
- 边界覆盖：来源/重算阶段、预检后与写前、复用返回前、续建补写前、
  写入完成后、返回成功前；同阶段内传给生成器的是该阶段一致快照；
- 命令行**不传**固定时刻（生产走 `Date.now()`），避免提前固定数值；
- 写后到期的返回中带 `expiredAfterWrite=true`、`wroteFiles=true` 与已写文件列表；
- 写入开始后引入跨 `catch` 共享的「已写事实」记录（`written` / `wroteSomething`），
  使**写入开始之后的任何失败出口**（含最终返回前检查）都带回真实写入事实，
  不再被外层统一返回成 `wroteFiles=false`。该表述已由第 17 节的实测确认，
  在此之前属过强声明。

**验证方式**：不传 `nowMs`，只在本进程替换 `Date.now` 与
`fs.readFileSync`/`fs.writeFileSync` 的旁路观察，在**读取受审来源文件**
或**写完首个输出文件**的实际事件处把时钟推进到截止时刻。
**不使用 `sleep`，不替换过期判断，不修改产品代码。**

实测：写前 2 次、写后 5 次、check 2 次、复用 2 次、续建 2 次时钟读取，
五条路径均按到期拒绝；写后保留 49 文件并如实报告；续建不补任何文件。

### 17.1 缺陷与修正

**缺陷**：最终返回前的检查落在外层 `catch` 之内。到期或时钟无效抛错后，
磁盘已写 49 个文件，返回却是 `wroteFiles=false` 且缺失 `written`。

**修正**：把 `written` / `wroteSomething` 提到 `try` 之外，作为跨 `catch` 共享的
「已写事实」，并让**所有写入开始之后的失败出口**共用同一投影：

- 「写后」与「最终返回前」两处时效复核统一走同一个循环与同一个失败投影；
- 外层 `catch` 在 `wroteSomething` 为真时也返回真实写入事实；
- 未写入的路径（预检失败、check 失败、完整复用失败）仍是 `wroteFiles=false`
  且不带 `written`；
- 附加 `reason`（`final-check` / `post-write-check`）与 `clockInvalid`，
  使**时钟无效**与**已过期**如实区分 —— 未知时钟不被描述成已证明的真实截止时间。
