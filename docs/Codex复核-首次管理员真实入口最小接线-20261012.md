## 2. R1 [P1] 真实来源模式仍接受执行依赖覆盖，且未与批准隔离

位置：`sandbox-primary-execution-host.cjs:701` 起；`sandbox-primary-approved-run.cjs:258` 起。

真实分支仅对 effectiveProfile 做字符串一致检查。`credentialDeps.fixed.nodeBin`、spawn、spawnWorker、now、baseEnv、isolationFixed 等仍原样进入执行链。凭据宿主会合并 `d.fixed`，入口也直接把测试依赖传入。注释“仅离线测试”不构成两种运行路径的隔离。

独立样本 `R1-mode-not-bound-and-runtime-overrides`：签发合成原句柄后选择 `fixed-real-source`，传入 `credentialDeps.fixed.nodeBin='SYNTHETIC_NOT_FIXED_NODE'`；该值确实到达合成 secrets spawn，仍一次凭据、4 次 API、两写一提交并返回 COMPLETED。句柄没有 credentialSourceMode 字段。真实认证目录在审查层虚拟化，此样本不执行外部程序，也不是取得生产授权。

影响：任务明确要求真实路径使用固定 node/CLI，且不给真实模式任意 spawn/worker/时钟/固定路径绕过。当前同一接口没有落实这一要求；离线签发能力与真实来源选择也没有明确绑定。

最小修正：在允许的 host/新入口范围内绑定来源模式，给真实候选路径固定依赖并拒绝调用方覆盖。为离线测试保留明确隔离的测试装配方法，可在模块装载/底层边界替换传输；不要把测试开关继续作为真实入口普通参数。保留已有 WeakSet、完整计划/主体、三期限等检查；不新增通用权限系统，也不要求抵御可修改同进程代码的攻击者。

## 3. R2 [P1] 新入口尚未完成其承诺的默认执行/持久化接线

位置：`sandbox-primary-approved-run.cjs:237-279`；host `849-867`、`911`、`939`；`runExecutionWorker:1166`。

入口自己创建 started，随后仍把调用方的 persistRoundStarted/persistResult 传给 host；也只转交 spawnWorker，未提供固定真实 worker 启动器。正向夹具固定传 `() => true`，故测试成功不能证明入口默认保存接线完成。

独立事实：

1. `R2-no-caller-persistence-callbacks` 删除两个回调，保留合成 CLI/SDK：磁盘 started 已存在，且已取 1 次合成凭据、调用 4 次 API，随后 ROUND_START_FAILED；事务零写。
2. `R2-no-worker-spawn-wiring` 仅删除 spawnWorker，保留两个回调：报告 workerStarted=true，但内部因 NO_SPAWN 返回 WORKER_FAILED、事务零写。这不能称为默认固定 worker 路径已接好。

最小修正：新入口自行连接排他 started 和不可覆盖终态保存，协调“入口已独占新建”与 host 回调，避免双重创建，也不能用无条件 true 代替保存。真实候选侧提供固定 node + 原 worker 路径 + 原私有 stdin 的启动器。外部参数不得替换这些能力；离线验证其实际调用参数而不启动云请求。轮次与 boundPlan.roundId 等可本地判定的条件提前检查，避免拿到凭据后才发现接线缺失。

操作说明 §5 目前给出的“受审进程只传句柄/模式/新轮次/结果目录即可全链执行”不成立，须随修正更新。

## 4. R3 [P1] 入口指纹只有记录，没有批准绑定/拒绝

fullFingerprint 把当前入口哈希写入 started/terminal，但 verifyControlledApproval 只绑定原 4 文件。入口从未拿自己的字节与批准时的预期值作比较；D-2 只断言有 64 位哈希，不是漂移反例。

独立样本 `R3-entry-drift-not-rejected`：签发后仅在文件读取边界模拟入口字节改变（未改磁盘源文件），仍取合成凭据、两写一提交、COMPLETED。批准指纹字段恰为 host/worker/P4/adapter 四项，无入口。

最小修正：把新入口实际内容哈希纳入不可变批准绑定，在凭据获取前和 worker 启动前核对；不得重新读取当前文件然后把新哈希当成新的批准值。保留 4 个原实现文件检查，补入口签发后漂移以及异步等待期间漂移反例。无需改 P4、worker 或 SDK 适配器。

## 5. R4 [P1] 终态落盘丢失关键事实，保存失败也丢失返回报告

位置：`sandbox-primary-approved-run.cjs:159-174`、`282-297`。

`saveTerminalExclusive` 只留状态、outcome、阶段等少数字段。host 已净化的 initialized/granted、commitFactEstablished、fullInitializationSuccess、observationConfirmed、observed、workerProcess、reconcile 等均未写入。调用方回调又可能只是返回 true，因此不能假定另有完整记录。

- `R4-terminal-drops-committed-facts`：真实应用/SDK 本地转换两写一提交，内存 initialized/observationConfirmed=true；落盘 COMPLETED 缺少样本列出的全部 7 类字段。
- `R4-save-failure-loses-returned-execution-report`：只在最终终态写盘处注入 EIO，两写一提交已经发生；runOnce 抛 APR_TERMINAL_SAVE_FAILED，错误没有 result 或 auditId，内存执行事实未返给调用者。started 保留只能证明曾启动，不能重建提交/退出/核对事实。

最小修正：对已净化宿主结果按必要字段再投影，保存提交事实、完整成功资格、未知/失败、子进程退出与只读核对等；不透传原始异常或凭据。磁盘保存失败时不伪造保存成功、不重试初始化，返回/抛出带固定错误码及净化执行事实的结构化结果，使受审调用者能保留未知或已提交事实。不要要求磁盘坏时“保证写盘成功”，也不自动另找任意目录落盘。

补测完整链的 worker 超时、提交后回读失败、终态保存失败；不能只手造 RESULT_UNKNOWN 对象调用保存函数。已验收 host 聚合和只读核对不重写。

## 6. R5 [P2] 交付测试的拒绝钩子仅存在于独立探针块

位置：测试 `686-724`；交付证据 `446` 起的敏感性块。

三个网络探针确有计数，不是字面量 0；但守卫在业务场景执行完之后才安装，随后恢复。注入传输能使正常路径离线，不等于意外真实调用受全程拦截。所谓“意外子进程拦截”只断言 runOnce 是函数，没有安装 child_process 拦截或实际敏感性探针。

最小修正：测试/新证据在加载应用并执行场景前安装全程网络与意外真实子进程守卫；若保留精确本地探针，显式允许精确命令，其余拒绝。实际删除传输注入或主动敏感性探针须证明能截住意外调用。计数分开记录敏感性探针与业务期间意外尝试。

真实登录目录的空目录副作用：未来经具体批准的真实获取使用既有工作目录机制可如实列入执行包，不据此要求改凭据宿主。但**离线审查/测试应使用文件系统虚拟化或受控装载替身**，不要反复往真实登录目录建目录。已有目录保留，不清理用户认证目录，也不为核对历史数量去读缓存。交付证据的“新增 1 个”只属于那次证据运行，不能推断所有测试累计只新增 1 个。

两处必须如实区分：

1. 外来 profile 拒绝确实零凭据/零子进程，但入口已创建 started；独立 `R5-profile-preflight-happens-after-started` 已证明。可本地判断的来源/轮次错误应在创建 started 前拒绝，或准确声明是“已预留轮次后失败”，不得说全是零 started。
2. “错主体摘要都在取凭据之前拒绝”过强。缺失/格式非法等可先拒；**格式正确但与当次 STS 不同**必须取得当次身份后才能比较。独立样本为 1 次合成凭据 + 4 API 后停 callerSubject、零事务写入，这是合理顺序。应更正文案，不能为了满足错误表述取消独立当次比较。

本轮没有证明真实事务/IAM/费用、生产 worker 自建 db 同批链，也没有生成真实批准。先前本人登记与关闭的已确认事实保持不变，无需用户再次扫码或登记。
