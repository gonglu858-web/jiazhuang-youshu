## 1. 目标与边界

第一批只服务 1 个真实装修项目，沿用[需求与业务规则](需求与业务规则.md)中已确认的角色、现场影像、验收、材料、增项、售后和五年档案规则。本方案回答三个问题：资料放在哪里，谁有权看或操作，误删与项目完工后如何恢复资料。

正式版方向已经确认为微信原生小程序＋腾讯云 CloudBase。以下“集合”指一类业务记录的逻辑分组；最终使用 CloudBase 文档数据库的具体模式、字段类型与接口，要在确定真实环境后再核对。这里没有任何实际环境 ID 或账号。

**建议的安全边界：**小程序仅展示经过授权的数据；所有涉及业务状态、成员、金额、验收和文件访问的请求都经过云函数。云函数从可信的微信登录上下文识别账号，重新检查项目成员关系与当前角色，再读写数据。前端传来的 `userId`、`role`、`projectId` 只当作待校验参数，不能当作权限凭据。业务集合和项目文件默认拒绝客户端直接读取、改写或删除；开发时再按实际 CloudBase 模式配置安全规则。CloudBase 的数据库和云存储都提供安全规则，但服务端访问仍须自己做业务鉴权，不能把“配置了规则”等同于云函数安全。[数据库安全规则](https://docs.cloudbase.net/database/security-rules) · [云存储安全规则](https://docs.cloudbase.net/storage/security-rules)

## 2. 建议的数据分组

每条项目记录至少带 `id`、`projectId`、`createdAt`、`updatedAt`、`createdByUserId`、`version`。修改或确认动作另外保存 `actorUserId`、`actorRole`、动作时间和当时的内容快照。账号使用内部稳定 `userId` 关联，微信 `openid` 只放在受限身份表中；成员姓名和当时角色另存快照，防止退出或换岗后历史署名变化。

| 逻辑分组 | 保存的关键内容 | 主要关联与用途 |
| --- | --- | --- |
| `users`、`project_members`、`invitations` | 微信账号映射、姓名；项目内角色／工种／生效与退出时间；邀请状态 | 登录后自动识别身份。未接受邀请不算成员；每项目仅一名当前主业主。 |
| `projects`、`schedules` | 项目状态、完工时间；阶段／工种日期、责任师傅、停工日、本次施工内容和预计完成日期 | 安排可调整，但已有施工记录保留发布时的安排快照。 |
| `site_records` | 师傅每日记录、管家巡检，位置、工种、说明、拍摄资料、当时安排 | 管家巡检不计入师傅的当日更新。 |
| `issues`、`issue_events` | 原始问题、关联阶段、整改任务、历次提交、业主意见、当前状态 | 当前状态便于查询；事件按时间保留，不覆盖以前的整改。 |
| `stage_cases`、`stage_events`、`waterproof_nodes` | 11 个阶段的当前状态、师傅申请、管家清单与提交、主业主结果；防水 5 节点及两次闭水时间 | 每次申请／退回／提交／确认单独留痕；竣工记录留存当时满足门槛的快照。 |
| `material_batches`、`material_events` | 每次进场批次、照片、视频、使用位置、业主确认／问题处理 | 补送另建批次；旧批次缺影像时不能确认。 |
| `extras`、`extra_versions`、`extra_amounts` | 增项当前状态、方案版本、价格与工期确认、施工和验收、取消／终止结算 | 金额单独存于受限分组；师傅任务只读取已批准的施工字段，不取得金额或完整版本历史。 |
| `design_assets`、`warranty_cases` | 效果图／施工图／全景的版本与空间；完工后独立售后记录 | 设计版本保留旧版；售后变化不改写竣工结论。 |
| `media_assets` | 文件 ID、项目及业务记录归属、照片／视频／文档类型、拍摄或上传时间、提交人、当前／已更正状态、旧版关系 | 数据库只保存文件元数据与引用，文件本体保存在私有云存储。 |
| `todos`、`notification_events` | 待办对象、责任人、状态；订阅消息授权与发送结果、去重键 | 待办以业务记录为准；微信消息失败不影响待办。 |
| `audit_events`、`archive_jobs` | 关键操作人、当时角色、前后状态及关联文件；备份、导出、恢复、归档、删除任务 | 历史只追加；文件不能靠删除业务记录来隐形消失。 |

这些名称是**逻辑草案**，不是已经创建的数据库集合。正式实施时可以合并或拆分，但金额隔离、历史不覆盖和项目归属不能丢。

### 查询与一致性

- 列表优先按 `projectId＋时间` 查询；待办按 `assigneeUserId＋status＋dueAt`，施工安排按 `projectId＋date＋trade`，阶段按 `projectId＋stageCode` 查询。正式建索引前，用 1 个试用项目的实际查询验证。
- 接口为每次提交生成请求编号；重复点击或网络重试返回同一结果，不多建批次、增项版本或验收记录。更新时核对记录 `version`，防止两人同时操作覆盖。
- “更新当前状态＋追加历史事件＋生成或关闭待办”须在可信服务端作为一个业务动作处理；如果底层选型支持事务，优先用事务保证要么全部成功、要么全部失败。CloudBase 文档数据库的事务能力以实际模式和运行时再核对。[CloudBase 事务操作](https://docs.cloudbase.net/database/transaction)
- 竣工通过时保存前 10 阶段、未结问题、材料批次和验收人账号的检查结果快照。状态被后续售后改变时，不能重算或改写旧竣工结论。

## 3. 权限表：谁可以做什么

权限按“**账号＋项目成员关系＋当前业务状态**”判断；同一账号兼任多个角色时合并可用功能，每次操作仍记录实际使用的角色。成员退出后立即拒绝新的项目读取和操作，历史署名不变。

| 身份 | 可查看 | 可提交或确认的关键动作 |
| --- | --- | --- |
| 负责人 | 自己管理的全部项目及其资料；增项金额 | 建项目、指定管家、维护设计资料；发起更换主业主；按已确认规则办理五年后的档案导出或删除。 |
| 管家 | 所负责项目资料及增项金额 | 安排施工和整改、邀请并核对成员、发布巡检、登记材料与增项、记录防水节点、提交阶段及竣工验收、跟进售后。 |
| 对应工种师傅 | 已加入项目的公开施工进度和设计资料；自己的任务 | 发布现场记录、整改、进场时间反馈、申请自己工种的阶段或已分配增项验收。不能看增项金额。 |
| 设计师 | 所参与项目进度、问题、材料、阶段与设计资料 | 维护效果图、PDF／DWG 施工图和全景链接；仅获负责人单独授权时可看增项金额。 |
| 主业主 | 自己项目资料及增项金额 | 确认整改、阶段、材料批次、增项价格／工期和完工；建立、确认售后问题；可授权家庭成员看增项金额。 |
| 家庭成员 | 已加入项目的普通资料；获主业主授权时可看增项金额 | 留言、反馈、新建售后问题；不做正式材料或阶段确认。 |

**必须在服务端检查的边界：**

1. 邀请通过前不得读取项目；已退出成员立即失权。仍有未完成任务时，先改派才能移出。更换主业主需负责人发起，且新主业主接受后才生效。
2. 阶段提交与确认必须是两个不同的稳定账号；切换角色不能绕过。主业主未操作时保持待确认，不自动通过。
3. 增项未由主业主确认价格和工期，不得加入师傅施工安排。师傅只看分配给自己的已确认任务；金额在数据库查询、云函数返回、消息和日志中都不能泄露。
4. 阶段仍有关联未结束问题时禁止确认通过；竣工另查 10 个已通过阶段、全部问题、应确认材料与资料门槛。仅靠页面禁用按钮不算完成校验。
5. 设计师维护设计资料的权限和负责人权限分别校验；不能因为设计师能上传图纸就赋予施工、材料或验收权限。
6. 不在小程序前端内置开发者密钥、管理员凭据或“负责人”账号白名单。第一位负责人如何建立身份，需在账号准备时单独确认。

## 4. 影像与文件

- 项目影像、施工图、报价单和档案均存私有文件区。数据库的 `media_assets` 记录文件 ID、归属与版本；列表接口只返回当前账号获准看到的元数据。打开文件时再核验项目成员及金额等细分权限，发放短期访问方式；不保存可长期传播的公开链接。CloudBase 官方文档说明云存储可设置安全规则，默认读取权限可能过宽，不能沿用默认值存放装修现场资料。[云存储 SDK 与默认权限](https://docs.cloudbase.net/storage/sdk) · [云存储基础权限](https://docs.cloudbase.net/storage/data-permission)
- 上传分“待提交”和“已提交”。先检查业务类型、拍摄来源、数量（最多 9 张照片）、视频时长（最长 60 秒）及相应最低影像要求；文件全部成功保存后才改变业务状态。上传失败保留当前选择与请求编号，供重试。服务端负责压缩／水印的最终处理结果，不能只信客户端写的拍摄时间。
- 已提交文件不覆盖同一路径、不直接删除。更正时新建 `media_assets` 版本，记录原提交人、更正原因和管家确认；旧文件标“已更正”并继续随项目档案保存。删除文件前检查其他业务记录或历史版本是否仍引用。
- 防水第 5 节点照片可被最终验收记录引用同一文件 ID，不重复上传；资料导出时仍要标明这两个业务关系。
- 效果图和 PDF／DWG 属设计资料，可上传；现场记录、材料与验收的拍摄来源限制分别遵守需求文档。720°全景保存外部链接及版本说明，不能把链接当成自有文件备份。

## 5. 备份、恢复与五年档案

**短期恢复与长期归档是两件事。**CloudBase 官方文档说明文档数据库有每日自动备份，但默认只保留 7 天；它适合短期误操作回档，不能单独满足项目完工后保留 5 年。回档会生成新集合，因此恢复后还需核对业务状态、文件引用和权限。[CloudBase 数据库回档](https://docs.cloudbase.net/database/backup)

首批真实项目的试用目标由用户委托助手确定：如需从独立备份恢复，**最多补录最近 1 小时的新记录和影像，24 小时内恢复项目核心资料访问**。这两个数字是正式试用的验收目标，不表示当前原型或 CloudBase 默认配置已经达标。归档文件第 2～5 年的取回时间另行核验。

建议的实施方案（具体服务、保存份数与费用尚待核对）：

1. **施工期间：**主存储成功后才向用户显示业务提交成功；至少每小时把新增或变更的业务数据与照片、视频、设计原文件复制到受限的独立备份位置，不能只备份数据库里的文件 ID。每天核对完整文件清单、数量和校验值。备份任务延误或失败时告警并修复，不能继续宣称满足 1 小时目标；保留滚动备份用于短期恢复。
2. **恢复演练：**正式试用前，在隔离测试环境中从独立备份恢复一个项目，核对成员权限、阶段状态、增项金额、历史记录和随机抽取的影像能否打开，并计时验证 24 小时目标；不得把恢复数据覆盖正在使用的真实项目。
3. **项目完工：**生成带清单与校验值的项目档案版本。完工后新增的售后记录独立追加到档案，不修改原竣工快照。第 1 年保持正常在线访问，第 2～5 年转为低成本归档；用户请求查看或导出时先恢复所需文件。
4. **满 5 年：**系统只提示负责人选择继续保存、导出或删除，不设置自动删除。执行前列出涉及的业务数据、影像、历史与备份副本；负责人选择后由后台任务分批执行并核对结果。备份副本按已确认的清理期限处理，后续恢复不能把已删除项目重新带回。主业主可收通知，但没有审批权。
5. **导出：**由负责人发起，以“项目名称＋导出日期”生成 ZIP，含总报告 PDF、分阶段影像、设计原文件、全景链接清单、Excel 明细及更正历史。导出文件本身也须私有访问、限期下载，并记录发起人与完成结果。

“第 2～5 年低成本归档”**不预设 CloudBase 云存储已自动提供该切换**。腾讯云 COS 有按生命周期转换为低频／归档存储的官方能力，但是否用于本项目、是否与当前 CloudBase 环境兼容、恢复时长和费用，都需在账号及预算阶段核验后决定。方案确定前不配置自动迁移或自动删除。[腾讯云 COS 生命周期](https://cloud.tencent.com/document/product/436/17031)

## 6. 正式实施前的核验门槛

- 用两个不同微信账号验证：管家可提交、主业主可确认；同一账号兼任两角色时拒绝自提自验。
- 用未加入、已退出、其他项目的账号尝试读取记录、文件和临时访问入口，均应拒绝；已退出账号的历史署名仍可在获准成员视角看到。
- 用师傅和未获金额授权的设计师／家庭成员检查接口响应、消息及页面，不能出现增项金额；有授权者仅看到自己参加项目的金额。
- 对材料、普通阶段、防水 5 节点、增项、竣工分别测缺影像、重复点击、断网重试和跨步骤操作；不应形成重复记录或跳过确认。
- 在隔离环境完成一次数据＋文件恢复，核对最多只需补录最近 1 小时的新资料、24 小时内恢复核心访问，并验证导出 ZIP 清单与实际文件一致。浏览器原型的 58 项业务检查及用户人工试用不能替代这些真账号、真机和云端检查。

## 7. 第一阶段开发实施建议【待确认】

本阶段的目标是用**测试项目和测试影像**验证第一条真实链路：微信账号进入项目 → 管家安排施工 → 师傅反馈可进场日期并现场记录 → 同项目成员查看。它是正式小程序的第一个开发与验收单元，**不是可投入真实客户项目的完整第一版**。本节是提请用户评审的实施建议；本地最小工程已经搭建并在模拟器运行，业务功能尚未开发。用户已自行支付微信认证费，后续已授权并完成免费环境开通及最小连接测试函数部署；未授权购买付费套餐或发布，后续业务实现仍按本节逐单元核对。

### 7.1 本阶段交付范围

| 单元 | 要做出的行为 | 后端和权限要点 |
| --- | --- | --- |
| 账号与项目成员 | 微信登录后自动显示本人在测试项目中的角色；负责人建立一个测试项目，管家核对邀请并配置工种；测试至少使用负责人、管家、师傅、主业主四个不同微信账号。 | 一人可兼任多角色，但前端不能自选或自授角色。首位负责人建议在本人登录后由一次性受控运维步骤核验并绑定账号，完成后关闭该入口；具体步骤在实施前核对。未接受邀请者不能访问项目。 |
| 施工安排 | 管家按起止日期安排施工阶段、工种、主要上传责任人、“本次施工内容”和预计完成日期；支持同一天安排多个工种、排除休息或停工日，以及临时调整日期或责任人。旧安排与已发布记录保留当时快照。 | 只对实际安排施工的日期／工种计算当天待更新；提前加入项目不产生催报。每个工种指定一位主要上传责任人，同工种其他已获授权师傅可补充记录，其当天的有效记录也计入该工种已更新。师傅能看其他工种的公开进度与计划，不能修改安排。 |
| 进场日期反馈 | 已加入项目的师傅查看前序工种进度后，反馈自己可进场的日期；管家结合现场情况确认或调整施工安排，项目成员可看到确认后的安排。 | 师傅反馈只是协调信息，不能自行改变施工日期或让未安排的工种产生每日上传任务。 |
| 师傅现场记录 | 从项目进入发布页时自动带入并醒目显示项目名称，按本人获授权的施工安排带入工种；师傅选择施工位置、写现场说明，现场拍摄至少 3 张照片或录制 1 段视频后发布；安排中的施工内容和预计完成日期只读显示。同一天可发布多条记录，保存成功后按时间排列并立即对同项目成员可见，无需管家逐条审核。 | 复用已确认的 13 个位置快捷选项及自由输入；每次最多 9 张照片、视频最长 60 秒。照片写入拍摄时间水印，视频显示录制时间。全部文件成功保存后才生成正式记录；失败可重试，重复点击不产生两条记录。 |
| 项目成员查看 | 管家、主业主、已加入项目的其他工种师傅能按日期查看施工记录、照片／视频和当前安排；不同项目与未加入者不可见。 | 项目列表、详情和媒体读取均由云端按微信账号及项目成员关系授权；不能只靠隐藏按钮。设计师与家庭成员若加入项目，可按已确认规则查看本阶段已实现的普通进度，设计资料和其他业务功能后续实现。 |

本阶段只需为 `users`、`projects`、`project_members`、`invitations`、`schedules`、进场日期反馈、`site_records`、`media_assets` 和必要的 `audit_events` 落地最小字段与索引。继续沿用第 2～4 节的隔离、历史和影像原则；具体集合、索引、接口、上传方式和安全规则须在真实 CloudBase 模式与目标环境确定后复核，不能把表中逻辑名称当成已建数据库。

### 7.2 实施顺序与停止点

1. **本地准备：**微信开发者工具、Git 基线、目标 AppID 与可运行的最小工程已具备；用户已提供微信认证通过截图。继续核对管理员微信、名称和后续类目／备案事项。不重复安装已有工具，不索取 AppSecret、验证码或密码；不用演示项目名代替品牌名。
2. **云端方案核对：**先确定微信小程序可用的 CloudBase 环境创建路径、开发环境 ID、所选数据库模式、首位负责人绑定方式、数据库／云存储／云函数的拒绝默认访问规则，以及测试环境的额度与费用。用独立开发环境和虚构项目数据；已有云环境先检查，不能直接选一个看似空闲的环境。
3. **分别获得授权后才操作：**原生最小工程已接入目标 AppID；需要创建或绑定 CloudBase 环境、开通套餐或产生费用时，先给出目标账号、环境、控制台显示的价格及影响范围，再执行对应动作。先实现可信身份与权限，再实现安排、拍摄、保存和查看页面。
4. **AI 自测与用户试用：**检查静态代码、业务校验和云端记录；用不同微信账号及真机跑第 7.3 节的路径。失败时记录第一条错误、环境与步骤，不沿同一路径反复尝试。测试通过后留 Git 版本点，并在进展文档记录用户人工试用来源。

### 7.3 验收清单

- 管家能按日期范围安排师傅施工，同日可安排多个工种，休息或停工日不产生当天待更新；师傅能看到安排但不能改“本次施工内容”及预计完成日期。调整安排后旧记录仍显示原安排快照。
- 已加入项目的师傅能查看前序工种进度并反馈可进场日期；反馈本身不修改施工安排，管家确认或调整后项目成员才能看到新的正式安排。同工种其他已获授权师傅的有效补充记录计入该工种当天已更新。
- 发布页自动带入并显示项目与工种；同一天可以发布多条记录，按时间排列。记录保存成功即对同项目成员可见，不等待管家逐条审核。
- 师傅现场拍 3 张照片，或录 1 段不超过 60 秒的视频，都能发布；相册／文件上传不能替代现场取证。少于 3 张照片且无视频、超过 9 张照片、超时视频均被拦截；现场照片有拍摄时间水印。
- 文件上传中断后，已选资料可重试；全部上传成功前不形成正式施工记录。重复点击或网络重试不产生重复记录。重新进入页面后，记录及文件仍能打开。
- 管家、主业主和已获准的其他工种师傅能看到新记录；未加入、已退出和其他项目的账号不能取得列表、详情或媒体。师傅不能自行变成管家或其他工种；至少用两个真实微信账号检查权限。
- 测试结果同时核对小程序页面、云端业务记录、文件及其归属。浏览器原型的 58 项检查只作为原型回归，不代替真机、真实账号或云端权限验证。
