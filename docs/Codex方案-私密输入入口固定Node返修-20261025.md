### 2.2 共用校验与启动链

优先在现有PS1内增加少量私有函数，不新增产品模块/依赖；两个分支调用同一套逻辑。现有Get-StoreArguments与Quote-Arg保持用途，参数中不加入完整编号。

1. 检查固定路径为本地绝对普通文件，固定程序及必要路径链无reparse/link歧义；缺失、目录占位、访问失败或解析不确定均固定分类停止。只做文件元信息/字节读取，不查改ACL、不枚举安装目录。
2. 使用已有.NET文件/SHA-256能力检查固定文件字节，避免按名称自动加载Get-FileHash模块。预期摘要来自内部常量，读取/计算异常拒绝；不得截短摘要或仅比较文件名/版本字符串。
3. UI创建之前先检查一次，失败不弹出要求输入编号的窗口。用户确认保存后、启动前重新核对，使用这次核对的同一固定路径；不能仅靠打开窗口时的旧结果。
4. 启动前复核期间将程序以只读、拒绝写/删除共享的句柄打开并保持到Process.Start返回，finally关闭；失败不启动、不传stdin。此措施减少校验到启动期间文件替换机会，不宣称能抵御所有同权限进程或保证操作系统装载原子性。
5. 两条分支使用共用的受控启动函数，仅有“实际保存”和“合成参数回显”两个固定用途。真实保存固定调用仓库内存储脚本的protect；合成回显保持固定`-e`内容，不调用存储/DPAPI。不得公开任意exe/script/options/启动回调接口。
6. FileName为校验后的固定绝对路径，UseShellExecute=false、CreateNoWindow=true；子进程的NODE_OPTIONS移除，仅影响该子进程，不修改系统环境。不得通过cmd、PowerShell或shell再间接搜索Node。原stdin/输出/错误通道、参数转义、取消与失败净化契约保持。

不新增按钮，不改变双次输入、尾号、交付勾选、默认遮挡或权限校验。启动失败保持固定提示/非零退出；不得输出实际输入、原始异常或系统候选路径。对输入值和检查句柄的异常收尾必须finally覆盖，不在失败后自动重试。

### 2.3 失败分类

为Node绑定增加固定、互不混淆的净化标签：声明参数不符、固定文件不合法、固定文件读取失败、摘要不符、启动失败。具体常量名由实现保持一致即可，不回显路径/摘要差异/输入内容。参数和文件校验失败均要求进程启动0次、stdin传输0次、存储/DPAPI/私密写入0次。
