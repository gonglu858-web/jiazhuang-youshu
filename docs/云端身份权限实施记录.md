### 主项目补充诊断：过滤参数与连接器对照（2026-09-24，尚未执行云端对照）

- 用户转述 CloudBase Agent 查询到两个 FLEXDB 内置模型及三个集合的 PRIVATE 权限；这是第三方智能助手提供的查询摘要，不等同于本任务直接取得的完整权限证据。用户随后提供的数据模型页面也为空，因此此前“在数据模型页即可见”的解释未通过人工核验。
- 主项目重新只读检查本机安装包内 `@cloudbase/cloudbase-mcp/dist/index.cjs`：`readNoSqlDatabaseStructure` 的 `listCollections` 调用仅传 `EnvId`、`MgoOffset`、`MgoLimit`；未传 `MongoConnector`、`Filters` 或 `ShowHidden`。同包管理 SDK 的 `getMongoConnector()` 使用 `{InstanceId:"flexdb", DatabaseName:Databases[0].InstanceId}`，其 `listCollections()` 会传连接器。这是静态代码证据，不证明网页实际请求参数或后端省略参数时的默认行为。
- 腾讯云官方 [ListTables 文档](https://cloud.tencent.com/document/api/876/127965)明确提供 `Filters`（HIDDEN、WEDA、WEDA_SYSTEM）、`ShowHidden` 及 `MongoConnector`。因此应检验“参数选择不同”与“系统表过滤”两个方向，而非继续让用户寻找集合或数据模型菜单。

- 当前会话无可调用的 CloudBase 通用 API 工具；浏览器状态读取一次返回 `nodeRepl.fetch request failed`，没有反复重试、提取登录令牌或修改安装包。上述对照尚未执行，可由已登录的 CloudBase Agent 在其工具支持官方 ListTables 参数时完成；不支持则直接报告能力缺口，不编造结果。本轮没有云端写入或放宽原有实施前置条件。

代码用服务端 `APPID` 与 `OPENID` 派生稳定内部用户 ID；`users` 的文档 ID承担同账号唯一约束，`project_members` 的文档 ID由项目 ID 与用户 ID 派生，`app_admins` 的首位负责人文档 ID固定为 `primary`。正式建索引时核对 `users.bindingCodeHash`、`invitations.tokenHash`、`project_members(projectId,status)`、`invitations(projectId,status)` 与 `audit_events(projectId,createdAt)` 的实际支持情况；邀请码状态／有效期检索需要同时确认。所有测试项目名称以“虚构测试”开头，不迁移本机示例数据。

腾讯云[事务操作文档](https://docs.cloudbase.net/database/transaction)说明事务中只支持按文档 ID 操作，不支持 `where` 条件查询；本地实现先在事务外定位编号，再在事务内按用户文档 ID复核编号与有效期。微信云函数 SDK 的[数据库类型定义](https://github.com/wechat-miniprogram/wx-server-sdk/blob/master/index.d.ts)列有 `runTransaction`，但**目标环境中的实际 SDK 和数据库事务能力尚未验证**；若缺失或调用失败，停止后续云端写入，不改用非原子成员授权。

负责人身份生效后，才建立虚构项目、用管家本人编号指定管家，再由管家发邀请；申请人需用本人微信取得编号，管家线下核对后提交编号，云函数比对编号与申请账号，批准前申请人不能读项目。使用四个不同的负责人、管家、师傅、主业主微信账号和一个未加入账号，验证跨项目、待批准、退出后和改请求参数越权均被拒绝；真机与云端记录要一起核对。
