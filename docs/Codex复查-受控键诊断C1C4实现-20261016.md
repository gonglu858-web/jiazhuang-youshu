## 3. R2 [P2] 诊断构造后缺少最终时效校验

位置：miniapp/scripts/lib/participant-identity-check.cjs:458–459、513。

collectKeyDiagnostic 只在 buildKeyDiagnostic 前检查一次时钟；随后失败结果直接附诊断。独立反例在第二次键枚举（构造诊断时）推进合成时钟：到 expires、NaN、抛错三路均仍返回诊断，clockReads始终1。正常时钟对照也能返回诊断；所有路径零DB且仍为 UNKNOWN。这证明最终出口缺少校验，不声称手机事件含 Proxy，也不声称真实平台已发生越窗。

修复：在最终附加/返回诊断前重查当前窗口；到期、未开始、非有限值、抛错均撤销诊断，保持原 PIC_REQUEST_INVALID/UNKNOWN/读取事实与净化文案，不变成成功、不读DB。固化构造前有效、构造后失效三反例及合法对照，不只测试初始已过期。

## 4. R3 [P2] 普通候选清单的诊断协议字段可被篡改后通过

位置：miniapp/scripts/package-participant-identity-check.cjs:838–841。

build 总会写 keyDiagnosticSchema/keyDiagnosticScope；checkDir 仅在 plan.keyDiagnostic===true 时核对二者。实际生成普通包后，将二者改为无关字符串，checkDir.ok仍true；恢复后正常对照true。该问题不会打开诊断，但违反清单声明精确绑定，不能把此包称为全部声明均已核对。

修复：对所有候选统一验证已声明的固定字段；或统一采用明确的关闭态省略契约并由 build/check 一致执行。缺失/错值在 true/false 两模式均有拒绝对照；独立关闭包检查不新增候选窗口依赖。

## 5. R4 [P2] 客户端将畸形诊断修补成可展示对象

位置：miniapp/scripts/templates/participant-identity-check/frontend/utils/identity-check-client.js:24–40。

candidateLabels 非数组会被改成[]，非法标签被静默滤除；计数与分桶之和不一致也未拒绝。独立合成响应 otherKeyCount=9、五桶全0、candidateLabels为字符串，客户端仍保留诊断。该反例没有原键名/值泄漏，但会把不符合协议的响应展示成取证事实，不能称为“无效即丢弃”。

修复：明确固定 schema 的有效范围；必需字段类型、候选标签/重复/数量、非负安全整数、分桶与总数的一致性须严格验证，违约整份诊断丢弃。额外字段可继续只投影丢弃，不能把无效必需字段修成默认值；明确截断时的计数约定。输出字段集与总长度保持有界。加畸形反例及合法对照，并走生成页验证无诊断展示、原失败事实与口令清除不受影响。
