## 2. N2：枚举合法不等于结果组合合法（P1）

位置：`miniapp/scripts/lib/sandbox-primary-execution-host.cjs:1371` 起的组合判断、`:917` 和 `:1049` 的成功保存分支。

`legalOutcomeFor` 只判断名称是否属于三个枚举。新增检查主要位于 `if (out.initialized === true)` 内：当 initialized=false 时，未知 outcome、与布尔值矛盾的 initialized outcome 等仍可搭配顶层 ok=true / observationConfirmed=true，被保存为 COMPLETED。`alreadyPresent` 也未禁止 granted=true，注释反而写成“可为 true”，与 P4 实际返回相反。

独立证据从同一合法成功载荷出发，保持本计划 auditId/inputDigest、active/present 观察，分别替换顶层与 bootstrap 的同名字段，贯穿真实 executeOnce 至保存回调：

| 样本 | outcome（两层相同） | initialized | granted | 实际结果 |
| --- | --- | --- | --- | --- |
| unknown-false-flags | UNKNOWN | false | false | observationConfirmed=true，COMPLETED |
| initialized-denies-flags | initialized | false | false | observationConfirmed=true，COMPLETED |
| audit-only-confirmed | auditAlreadyPresent | false | false | observationConfirmed=true，COMPLETED |
| already-present-claims-grant | alreadyPresent | false | true | granted=true，COMPLETED |

四例均无数据库读写，只是损坏 worker 输出协议的父层测试；**不声称真实 worker 或云端实际产生过这些组合**。其中审计已存在分支即使随后读到有效记录，也必须把“后续观察”与“本轮初始化已完成”分开，不能仅凭回执的确认布尔把 P4 的冲突停止结果提升为初始化完成。

这仍是上一轮 §3.2 要求的统一组合判断，不能以新增枚举函数已经存在为闭合依据。当前代码注释中的表格也没有被完整执行。

### 最小修正边界

只在现有 host 聚合点把以下真实契约落实为有限、可核对的规则，并同步注释与操作稿：

| 原始 P4 分支 | worker 正常化后的本轮初始化事实 | 保存/核对要求 |
| --- | --- | --- |
| initialized | granted=true、initialized=true，P4 返回本计划 auditId/inputDigest | 两层事实一致且精确绑定；观察完整 active/present 才可保存完整成功。回读失败仍保留已绑定提交事实，不抹为零写 |
| alreadyPresent | granted=false、initialized=false，既有记录观察不代表本次授予 | 不要求 initialized=true，不得制造 granted=true；使用真实输出做对照，允许保守停止/核对，不要求它伪装为初始化成功 |
| auditAlreadyPresent | granted=false、initialized=false，P4 因审计在而 primary 缺停止 | 保留冲突停止语义；后续观察单列，不能据此声称本轮完成初始化 |
| UNKNOWN、缺失、组合矛盾 | 不能据自报布尔形成完整成功 | 不保存 COMPLETED；保留可能执行过的未知事实，沿用既有只读核对和未知终态保存，不重试写入 |

同时核对顶层与 bootstrap 的 outcome、initialized、granted 是否相互一致，不能只检查“true 是否被支持”而放过相反方向的矛盾。不增加签名体系、架构或新业务；不改 P4/worker 来制造父层想要的字段。

## 3. N2 正向夹具：真实 alreadyPresent 与当前合成样本不一致（P2，同批）

`miniapp/tests/sandbox-primary-execution-host.test.cjs:2941` 的 N2-c4 手工构造 alreadyPresent、granted=true，并补上 bootstrap.auditId/inputDigest，断言 COMPLETED。这不是实际既有分支：

- P4 `sandbox-primary-bootstrap.cjs:433` 的已有 primary 分支返回 granted=false、existing，**不返回 auditId/inputDigest**。
- worker `normalizeBootstrapResult` 不会凭空补出这两个字段，initialized=false、granted=false。
- 新独立 `real-already-present` 使用真实 worker/P4/SDK 转换，预置本计划自洽记录：primarySet/auditSet/commit 均 0，abort=1；最终保留 alreadyPresent、initialized=false、granted=false，但由于缺 bootstrap 绑定字段走保守核对，status=FAILED、RESULT_UNKNOWN，合计四次只读（worker 两次、父层两次），核对 confirmed=true。

该对照证明“没有重复授予”，**不能据手工补字段的 N2-c4 宣称真实已有分支保存 COMPLETED**。本轮不要求放宽已关闭的提交绑定检查，也不要求已有记录必定保存 COMPLETED；保守停止可保留，但测试与交付应准确说明它的终态及依据。

修正 N2-c4：以真实 worker/P4 输出为正向，断言零写、不重复授予、真实字段与保存终态。另把 alreadyPresent+granted=true 作为损坏协议反例，不能继续当正向样本。保留正常新建、真实提交后回读失败、错绑定拒绝等已通过对照。
