## 2. 两种凭据来源模式（M1）

`executeOnce` 新增 `credentialSourceMode` 选项（`normalizeCredentialSourceMode`
可独立调用，供入口在任何写入前校验）：

| 模式 | profile 来源 | 行为 |
| --- | --- | --- |
| `offline-fixture`（**默认**） | 调用方显式提供的**合成** profile，且不得等于固定真实登录目录 | 既有安全闸语义不变；缺 profile 或指向真实目录即在取凭据前停止 |
| `fixed-real-source` | **只能**是受审只读观测器 `cliObserver.FIXED.authSessionDir`（本机唯一固定真实来源） | 调用方传入其它 profile 一律拒绝；不传则绑定固定值 |

要点：

- 模式只是**来源分类**，不是权限凭据。真实模式选择本身不构成授权；
  受控批准（WeakSet 句柄）、完整计划、目标、时效、实现/入口指纹、预期
  云主体摘要等检查**照常在任何凭据获取之前执行**。
- **没有路径别名绕过**：真实模式的 profile 比较是字符串同一（不换大小写、
  不去尾斜杠、不解析相对路径/junction）。测试 A-4 以合成 spawn 捕获实际
  传给 CLI 的 `USERPROFILE/HOME`，断言其**精确等于**固定真实目录。
- 未知模式值在任何写入之前拒绝（含 started 创建之前）。

**返修更正（R1）**：`credentialSourceMode` 现已**纳入批准不可变绑定**——
`issueControlledApproval` 在签发时把句柄与一种来源模式绑定，
`runOnce`/`verifyControlledApproval` 复核请求模式与绑定模式一致
（`REAL_MODE_BINDING_MISMATCH`，双向）。真实模式还**拒绝全部执行依赖覆盖**
（`REAL_MODE_OVERRIDE_REJECTED`，started 之前）：spawn、spawnWorker、
baseEnv、isolationFixed、credentialDeps、profileDir、credentialProfileDir、
credentialCwd、limits、workerLimits、reconcileReadOnly、reconcileDeps、
readOnlyDeps、now、fixedNowMs——固定来源、固定启动器（`FIXED.nodeBin` + 
`FIXED.workerPath`）与固定隔离根不接受任何别名或注入。

**副作用如实记录**：真实模式下凭据宿主会在固定登录目录内创建一个
`cloudbase-credential-fetch-<hex>` 空隔离工作目录（既有已验收宿主行为，
目录用途严格分离、不读取任何认证文件内容）。离线测试 A-4 因此在真实
登录目录新增了 1 个此类空目录；宿主不删除既有目录。

## 3. 最小单次入口（M2）：`sandbox-primary-approved-run`

导出：`runOnce`（完整编排）与若干可独立测试的纯函数
（`normalizeRunId` / `assertFreshOutDir` / `createStartedExclusive` /
`saveTerminalExclusive` / `checkPlanAndApproval` / `entryFingerprint` /
`fullFingerprint`）。

`runOnce({ runId, outDir, plan, approvalSource, ...注入点 })` 流程：

1. 轮次标识与结果目录校验（路径逃逸、外来文件即拒）；
2. 凭据来源模式校验（零写）；
3. **计划与批准交界**：`host.verifyControlledApproval`（内部先走 P4
   `validateApprovalContext` / `validatePlan` / `assertApprovedTarget`，
   复用原 `inputDigest` / `auditId`；不把含 `deadlineMs` 的归一化对象回传核心）。
   普通 JSON、环境变量、命令行开关不构成批准——只有宿主
   `issueControlledApproval` 签发的不可序列化句柄被接受；
4. **排他 started**：`wx` 独占新建，`await` 成功后才允许启动写 worker；
   同轮次再次运行得到 `APR_STARTED_EXISTS`，不覆盖、不再写；
5. `host.executeOnce` 全链（一次凭据、三阶段关联、额外 STS、原 worker
   私有 stdin、原 P4 事务、只读回读——全部复用已验收实现）；
6. **终态新建保存**：按宿主报告如实分类——`PLAN_READY`→`COMPLETED`、
   `resultUnknown`→`RESULT_UNKNOWN`、其余→`FAILED`；同状态重复保存得到
   `APR_TERMINAL_EXISTS`，不覆盖历史。终态载荷先经 **34 项白名单投影**
   （`projectTerminalPayload`）：保留字段始终出现（缺失为 null），白名单外
   字段一律不进盘。

**返修更正（R2）**：`runOnce` **不再接受调用方持久化回调**
（`persistRoundStarted`/`persistResult` 已从契约移除）。排他 started 的既有
记录核对（auditId/planDigest 一致性，不重复创建）与终态落盘均由**入口自接**：
宿主正常返回后入口复核终态确在盘上；不在盘则入口自行投影保存；保存失败抛
`APR_TERMINAL_SAVE_FAILED` 结构化错误（`e.execution` 携带净化执行事实、
`e.causeCode` 保留内层错误码），**保留 started 与执行事实、不伪造保存成功、
不重试初始化**。因此第 6 步的持久化不再依赖调用方返回值冒充。

结果目录规则：允许不存在/为空，或仅含本模块的 `started`/`terminal`
子目录（可重入，排他性由文件级 `wx` 保证）；含任何外来条目即拒
（`APR_RUN_DIR_INVALID`），不与外来文件混放。

指纹绑定：started 与终态记录都含 `fingerprint = { implementation（宿主 4 文件）,
entry（本入口文件自身 SHA-256） }` —— **新入口不遗漏于最终执行包指纹**。

**返修更正（R3）**：入口指纹现在是**批准绑定的活动校验**而非仅记录——
签发时把入口文件（`ENTRY_FILE = sandbox-primary-approved-run.cjs`）当时
SHA-256 写入句柄；`verifyControlledApproval` 在**取凭据之前**比较一次，
启动 worker 前再**复核一次**（漂移 → `FINGERPRINT_MISMATCH`，
`stoppedAt: 'entryFingerprintRecheck'`）。签发后入口字节变化在任何凭据获取
之前拒绝；异步等待期间漂移则不启动 worker、不写库、终态如实 FAILED。

## 4. 已验收语义保持（本轮未改）

- `alreadyPresent`：宿主保守停止（`status=FAILED`、`errorCode=RESULT_UNKNOWN`、
  宿主持久化 `recordType=RESULT_UNKNOWN`，绝不 COMPLETED）；本模块终态如实
  保存 `RESULT_UNKNOWN`（载荷含 `outcome=alreadyPresent`），零写零提交。
- 提交未知 / worker 超时 / 回读不完整：留 `RESULT_UNKNOWN`，不重试、
  不清理结果重跑。
- 已有 primary 无论同人或他人均停止，不覆盖。

## 5. 未来真实执行的方式（本轮不执行）

真实管理员初始化的未来流程：

1. **批准页**：向用户展示完整执行包——新轮次、完整原始 P4 计划、证据引用、
   执行人引用、计划与批准截止时间、确定性 auditId 与 32 位 inputDigest、
   完整计划摘要、入口与 4 个实现文件的实际 SHA-256、唯一测试目标与两条
   新增写清单、本次只读云主体摘要（`93cb27f6…`，尾号 7053）作为**待批准候选**。
2. **签发**：用户明确同意后，由**受审本机管理进程**核对人类确认，
   调用宿主 `issueControlledApproval` 生成**内存中的不可序列化句柄**。
   该信任边界须如实说明：代码无法独立证明聊天授权，宿主信任受审本机
   进程与操作者，不声称抵御同权限代码修改者。
3. **执行一次**：受审进程以该句柄调用 `approvedRun.runOnce`
   （`credentialSourceMode: 'fixed-real-source'`、独立新轮次、预确认
   可新建的结果目录）， started 独占创建后走宿主全链；终态如实落盘。
4. **留证**：started / 终态 JSON（含指纹与确定性 auditId）即本轮证据；
   失败或未知不得清理重跑。

本轮**未**生成真实批准、有效生产计划或真实写入窗口；本说明不构成执行指令。

## 7. 离线验证真实分支的模块级装配方式（R1/R5 返修新增）

真实分支（`fixed-real-source`）的固定依赖在**正常参数面不接受注入**（R1）。
离线测试/证据因此改用**模块级**显式装配：

```js
const host = require('.../sandbox-primary-execution-host.cjs');
const uninstall = host.installRealModeOfflineHarness({
  spawn: 合成CLI子进程,
  spawnWorker: 合成worker子进程,
  reconcileDeps: { db: 注入db },        // 只读核对传输
  workerLimits: { timeoutMs, maxOutputBytes } // 可选
});
try { /* approvedRun.runOnce({ credentialSourceMode: 'fixed-real-source', ... }) */ }
finally { uninstall(); }
```

- 装配器自身校验：未知字段或缺 `spawn` 即抛
  `REAL_MODE_OVERRIDE_REJECTED`；装配状态经
  `host.realModeOfflineHarnessActive()` 可查，宿主报告字段
  `result.realModeOfflineHarness = true` 如实标记。
- 这是**测试专用通道**，不是真实入口的普通参数；真实执行（无装配）时
  spawn 取模块装载时捕获的真实 `REAL_SPAWN`，worker 取固定 node + 固定
  workerPath。
- 真实登录目录与 SDK 隔离根的 fs 操作经文件系统虚拟化（受控装载替身）
  重定向到一次性沙箱：测试对 `REAL_AUTH_DIR`/`REAL_ISOLATION_ROOT` 的
  mkdir/exists/stat/readdir/readFile 等全部映射到临时目录并逐项验证，
  **真实目录零触达、不读内容、不清理既有目录**。早期「真实模式测试在真实
  登录目录创建空隔离目录」的副作用不再发生。

## 8. §7 文案更正（比较阶段如实表述）

复核报告 §7 指出原表述暗示全部不匹配都能在取凭据前发现，与实现阶段不符。
更正后的口径（与实现一致，测试 D-8/D-9/C-7 闭合）：

1. **可本地判断的错误提前拒绝**（取凭据之前、started 之前、零子进程零写）：
   来源模式未知/绑定不一致、执行依赖覆盖、批准/计划/目标/时效/轮次
   （`APR_ROUND_MISMATCH`）核对失败、入口漂移（R3）、预期主体摘要缺失或
   格式非法。
2. **格式合法但与当次 STS 不同的主体摘要**：只能在**取得当次身份**
   （1 次凭据 + 三阶段关联 + 额外 STS 核验）之后比较
   （`stoppedAt: 'callerSubject'`、`CALLER_SUBJECT_MISMATCH`，零事务写）。
   任何文档不得宣称此类不匹配全部在取凭据前发现。
