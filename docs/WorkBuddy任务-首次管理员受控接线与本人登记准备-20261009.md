## 4. L1：受控初始化宿主

### 4.1 默认关闭与批准边界

- 默认启动只做本地路径、版本、指纹和计划字段检查；不获取凭据、不联网、不启动写 worker。错误参数在这些外部动作之前拒绝。
- 原 `prepare-sandbox-primary.cjs --execute` 拒绝保持不变。本轮不增加公共 `--execute`、任意适配器/脚本/URL/集合/凭据参数，也不增加云路由。
- 新模块提供供未来 Codex 受审单次执行入口调用的函数；本轮仅在离线测试中调用完整链。最终真实入口由 Codex 在制品审查、本人登记、具体写批准之后制作并固定指纹；不是让 WorkBuddy 现在预填生产 approval。
- 区分：候选计划、批准上下文、当次云身份核验、事务结果。批准必须由未来受控入口依据真实用户确认绑定完整计划及文件指纹；普通计划 JSON 自报 `approvedBy`/`allowed:true`/`trusted:true`、环境变量或可序列化“已批准”标志不能独立触发真实路径。
- 不新建签名服务/批准数据库/通用权限系统。信任边界是受审的本地管理进程及其操作者，不宣称能防御拥有相同本机权限、可任意改代码的攻击者。测试依赖注入必须单独标合成，不能生成生产授权结论。
- 缺受控批准来源时，在获取凭据之前停止。不要实现“把配置开关改true即可完成验收”。也不要把整个接线写成无条件拒绝的空实现；离线必须能走到真实 P4 核心与真实 SDK 转换。

### 4.2 一批凭据、真实主体核验

- 复用固定凭据宿主和已验收隔离目录/有界进程工具。一次取得临时凭据，所有 CLI 关联与数据库 SDK 使用同一内存快照；过期停止，不获取第二批、不重试初始化。
- CLI 使用已审路径的子进程环境注入；worker 使用私有 stdin 一次传入随即关闭。不得笼统称“所有进程凭据均不进环境”，不得写凭据文件/命令行/日志。
- 复用三阶段身份/环境关联；`matched` 只说明归属关联，不能当管理员初始化许可。
- **现有投影只有云主账号完整摘要，实际 `UserId/PrincipalId` 只有尾号。** 不能用尾号匹配实际执行主体，也不能仅主账号相同就宣称是同一主体。
- 最小补足选定：在新宿主中、同一快照下增加一次固定 STS `GetCallerIdentity` 只读核验，复用既有固定参数构建、spawnBounded、JSON解析及 STS字段检查；只在内存取得 `Type/AccountId/UserId/PrincipalId`，计算完整身份元组摘要，与**执行前已受审的预期值**比较。不要修改旧观测器的输出契约，不重写计时器/签名。
- 元组摘要采用固定有序数组 `[Type,AccountId,UserId,PrincipalId]` 的 UTF-8 JSON SHA-256，严格保持字符串，不裁尾、不改大小写。原值不持久化。预期摘要本轮未取得批准，不得从本次执行响应自动“学习”为允许值；由 Codex 后续只读取证并结合登录来源审查，最终与写入范围一起确认。
- 角色会话变更若造成主体摘要不同，应当停止重新核对，不自动放宽为主账号相同。此项是明确的预期事实缺口，不要求用户手填云主体。
- 新宿主据当次核验构建封闭的 verifyCaller，严格检查固定环境、AppID、计划绑定及有效期，再交适配器使用。不得接受普通调用方传入的“成功结果”替代当次查询。读取成功不是 IAM 写权限证明；平台拒绝按失败停止，不做探测写。

### 4.3 固定事务接线

- SDK 使用本机已有固定路径的 node-sdk 2.10.0/database 1.4.1；`sdk.init({env,region,secretId,secretKey,sessionToken,debug:false})`，不安装，不用 `new sdk()` 或 token 别名。
- 先用 P4 的计划/批准校验、`inputDigest`、`auditId` 生成绑定值，再创建 SDK adapter；不自造第二套主键或摘要算法。
- worker 调用既有 `initializePrimary`：用户 active/派生一致；primary及本计划审计不存在；期限仍有效；事务内新增 primary和审计。只读测试 users，写集合只限测试 app_admins/audit_events。
- 真实目标不存在时零set/commit；不得从旧库导入用户、调用 identify补齐、自动创建集合或降级为逐条非事务写。
- 已有primary（同人/异人/disabled均包括）按既有核心零写停止，报告既有状态；不能把 `ok:true/outcome:alreadyPresent` 误报 `initialized`。审计已存在但primary缺失停止，不补写。
- 复用已验收错误/提交未知处理。只有确认成功提交才记录提交成功；失败后是否回滚只报告实见事实。SDK底层自动重试设置按所用固定实现查明、如实披露；包装层不自动重跑事务。

### 4.4 单次执行、超时与结果核对

- worker复用55秒/1MiB/exit后close宽限的既有进程工具，不能只kill而永不结束，也不将kill请求当成事务回滚。
- 真实执行前持久化新轮次 started 记录（不含秘密）；创建失败或同轮次已存在则不发写请求。结果文件新建保存；同轮次再次调用只进入核对/停止，不重新初始化。不扩成跨设备锁或通用恢复系统。
- 超时/退出异常/写结果丢失/提交未知：状态为待核对，保留轮次与确定性审计ID，不刷新凭据后重新写。使用仍有效的同批上下文作固定两条只读回读；凭据不可用则明确未核对，留待 Codex 另行只读接续。
- 即使提交返回成功也要回读 primary和本计划审计；回读失败不得抹去已提交事实，更不得重试写。可复用既有 `observePrimary`，按源码实参调用，禁止绕开其身份核验。
- 最终报告只投影固定错误码/状态/计数/摘要/合法请求ID，不透传原始error、message/stack、OPENID或凭据。P4自身字符串或note不能未经核对当作生产事实。区分合成演练/真实SDK本地转换/平台执行，未运行的平台项保留未知。
