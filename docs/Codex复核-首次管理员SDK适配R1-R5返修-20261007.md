## 2. 唯一剩余实现项 R2【P1】：检查完整插入回执，不能只判断任意一项命中

定位：`miniapp/scripts/lib/sandbox-primary-sdk-adapter.cjs:228–266`，重点第255行和261行。

当前 `updated===0` 时用 `upserted.some(...)`，只要一个元素匹配目标就通过；同时接受未经当前 SDK 核实的字符串元素。`updated===1` 则完全跳过 `upserted` 校验。

| 合成返回 | 实际结果 | 问题 |
|---|---|---|
| `updated:0, upserted:[{_id:目标},{_id:其它}]` | initialized，2写1提交 | 多条且含额外目标仍通过 |
| `updated:0, upserted:[{_id:目标},{_id:目标}]` | 同上 | 重复插入结果违背单文档形状 |
| `updated:0, upserted:[目标字符串]` | 同上 | 未核实的最终 SDK 元素形状被放行 |
| `updated:1, upserted:[{_id:其它}]` | 同上 | 已更新分支忽略错误插入主键 |
| `updated:1, upserted:false` | 同上 | 已更新分支忽略无效结构 |

### 最小修法与验收

1. 以已取得 `@cloudbase/database` 1.4.1 的 `dist/commonjs/document.js:108–112` 为依据：事务 set 返回 `upserted:[{_id:res.data.upsert_id}]`。这里的外层数组及对象元素由 SDK 构造；真实平台未测，不能据此猜测“SDK也可能返回字符串元素”。
2. 核对插入集合的结构、数量和每个有效插入主键。零更新必须是单个有效目标插入，不能用 `some` 放过其它记录/重复记录/字符串。已更新分支同样拒绝结构异常与任何错误主键。
3. **不要误拒正常已更新分支**：真实 SDK 在没有底层 `upsert_id` 时可产生 `[{_id:undefined}]`；需按当前包的转换结果区分“无插入占位”与“有效插入”，用离线真实包正向例守住。不要仅凭 `upserted.length` 推断实际新增数，也不要假定原夹具的 `[]` 就是该包输出。
4. 上表5类异常至少覆盖首写与第二写回执：均零commit；分别只发生1/2次set尝试并尝试回滚。不要要求回执异常时“零set”，因为请求已发出才能读到回执。
5. 保留真实包 `updated:1` 无新增键、`updated:0 + upsert_id:目标键` 两个成功分支，以及已有 primary 零写停止。SDK/传输仍合成，网络尝试须为0。

限改适配层的回执校验、对应测试和说明。P4核心、CLI、旧业务、其它已关闭项不动；不新增版本兼容框架或自动重跑工具。
