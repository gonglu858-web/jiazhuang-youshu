## 2. 修正依据

产品保存函数分别调用 `Write(PlainValue)` 与 `Write(换行)`。成功保存的合成边界应记录两次写入，拼接内容仍为一个合成值加换行，不是两次登记。N1_SAVE 与 N4_DRIFT 最终均经过成功保存，预期由 1 改为 2；其余计数保持。

计数代表各场景最后一次重置之后的状态，不能累加此前子例：

| 场景 | 最后计数阶段 | stdinWrites |
|---|---|---:|
| N1_SAVE | 成功保存 | 2 |
| N1_ECHO | 回显启动 | 0 |
| N2_DECL | 参数声明校验 | 0 |
| N3_FILE | 绑定摘要读取失败 | 0 |
| N4_DRIFT | 重置后的成功保存 | 2 |
| N5_STARTFAIL | 重置后的启动返回空值 | 0 |
| N6_TRANSPORT | 重置后的回显启动 | 0 |

另将已严格核验的策略行重建为固定 `{scope, policy}` 属性顺序，按固定作用域顺序比较。相同值仅因 JSON 字段或行排列不同不再误拒绝；未知字段、缺项、重复作用域及实际策略值变化仍拒绝。固定宿主、参数、摘要、超时、输出限额、顺序执行、异常停止与后置核对逻辑未扩大。
