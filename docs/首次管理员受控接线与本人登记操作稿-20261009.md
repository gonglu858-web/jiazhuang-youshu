## 2. 本轮新增文件与实际接口

### 2.1 `miniapp/scripts/lib/sandbox-primary-execution-worker.cjs`

固定 SDK + 已验收适配器 + P4 核心的子进程接线。实际接口：

```
run(payload, deps) → 通过 deps.emit(obj) 输出
payload = { credential{secretId,secretKey,sessionToken,expiresAtMs},
            plan, approval, verifiedCaller(bool), fixedNowMs }
  载荷字段**仅此五项**（白名单）；`sdkRoot` 等可改加载路径的键会被拒绝。
  另：`run(payload,{now?,db?,emit?})` —— `now` 默认 `Date.now`，`db` 仅离线
  合成测试注入（生产子进程入口不传），`emit` 默认写 stdout。
  子进程入口：`main()` 读**有界** stdin（≤64 KiB）、跑一次、写一次 JSON 后退出。
```

关键行为（均已离线验证或按源码核对）：
- `sdk.init({secretId,secretKey,sessionToken,env,region,debug:false})`；
  **不用 `new sdk()`、不用 token 别名、不安装**。
- 先用 P4 的 `validateApprovalContext` / `resolveNowMs` / `validatePlan` /
  `assertApprovedTarget` / `inputDigest` / `auditId` 生成绑定值，**再**创建适配器；
  **不自造第二套主键或摘要算法**。
- 调用既有 `initializePrimary`：用户 active/派生一致 → primary 与本计划审计均不存在
  → 期限有效 → 事务内新增 primary + 审计。
- `normalizeBootstrapResult` 严格对齐 P4 实际返回字段
  （`ok`/`outcome`/`granted`/`auditId`/`inputDigest`/`existing{userId,status}`）：
  `outcome` 只接受 `initialized` / `alreadyPresent` / `auditAlreadyPresent`；
  **只有 `outcome==='initialized'` 才记 `initialized`**，`alreadyPresent` 绝不误报。
- 只读回读复用既有 `observePrimary`（传 `adapter/plan/approval/nowMs`），
  **不绕开其身份核验**；`state` 只接受 `present/absent/inconsistent/unconfirmed`。
- 输出只投影固定错误码/状态/计数/摘要/合法请求 ID；P4 自身的 `reason`/`note`
  **不**未经核对当作生产事实透出。

### 2.2 `miniapp/scripts/lib/sandbox-primary-execution-host.cjs`

默认本地检查 + 受控宿主接线。实际接口：

```
parseArgs(argv)                → { ok, errorCode, reason: ARG_FORBIDDEN|ARG_UNKNOWN }
localCheck({cliEntry,cliBundle,plan?,approval?,now?})
                                → { status, checks[], credentialFetched:false,
                                    cloudCallAttempted:false, workerStarted:false, fixed }
issueControlledApproval({plan,approval,approvedBy,writeScope,expiresAtMs,
                        expectedSubjectDigest})
                                → 不可 JSON 序列化的受控批准句柄（受审入口专用）
computeImplementationFingerprint()
                                → { 4 个实现文件的**实际内容** SHA-256 }
verifyControlledApproval({approvalSource,plan,now})
                                → { ok, errorCode, planDigest, fullPlanDigest,
                                    approvedBy, expiresAtMs, expectedSubjectDigest }
callerTupleDigest({Type,AccountId,UserId,PrincipalId}) → 64位摘要 | null
verifyCallerSubject(snapshot, {spawn,baseEnv,isolationDir,limits})
executeOnce({plan,approval,approvalSource,now,roundId,spawn,spawnWorker,
             profileDir,credentialDeps,persistRoundStarted,persistResult,workerLimits})
runExecutionWorker({snapshot,plan,approval,verifiedCaller,fixedNowMs,cwd,spawn,limits})
projectWorkerOutput(parsed,processFacts,unknown) → 固定字段投影
```

四层区分（任务 §4.1 要求）：

| 层 | 本轮实现 | 能否靠自报字段获得授权 |
| --- | --- | --- |
| 候选计划 | `plan`（P4 校验，禁字段由 P4 强制） | — |
| 批准上下文 | `approval`（P4 校验） | — |
| **受控批准来源** | 由 `issueControlledApproval()` 签发的**不可序列化句柄**，登记在模块私有 `WeakSet`；绑定完整计划（P4 `inputDigest` + 覆盖全部字段的规范化摘要）、批准人、写范围、有效期、预期主体摘要，以及**四个实现文件的实际内容哈希** | **否**：复制、展开、自造同形对象一律因不在登记表而被拒；`controlled:true` 这类可序列化标志已不再是授权依据 |
| 当次云身份核验 | `verifyCallerSubject` 在**同一快照**下发一次固定 STS，比较**批准绑定**的 `expectedSubjectDigest` | **否**：预期值缺失即在取凭据之前停止，不得从本次响应自学习 |

**R4 修正后的授权边界（必须如实表述）**：本模块**不**防御拥有相同本机权限、
可改代码或可读本模块内存的攻击者 —— 信任边界仍是受审管理进程及其操作者。
它解决的是「普通计划 JSON / 环境变量 / 可序列化标志 / 复制品不能充当授权」
这一具体缺口。**测试入口签发的句柄不构成生产授权**；真实批准本轮不生成。

**R4 关于指纹与轮次**：文件指纹只覆盖**实现文件**（4 个），不覆盖 CLI 安装包
（后者由已验收凭据宿主单独核对）；`persistRoundStarted` 自本轮起是**必需**能力，
必须 `await` 成功且 `roundId` 与计划**完全一致**，否则零写 worker。

**安全闸**：若凭据 profile 未给或等于本机真实 `authSessionDir`，
在取凭据**之前**停止 —— 避免离线测试触及真实登录目录。
