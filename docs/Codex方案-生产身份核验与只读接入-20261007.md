# 生产身份核验与只读接入：最小方案

日期：2026-10-07。状态：**方案已整理，接入尚未实现、未执行真实核验**。

本轮只读本地源码、查阅公开官方资料并写本文与交接记录。未读取凭据值、未调用云账号接口、未安装、未初始化、未建资源、未部署或启用。已验收的 SDK R1–R5、P4 核心、旧 U/T 与打包器不重开。

## 1. 要解决的两个问题

1. **云端操作者是谁**：本机程序使用的腾讯云身份是否属于本次获准的账号，是否能读取指定环境。工具已经登录不代表本地 SDK 使用同一身份。
2. **管理员准备给谁**：完整微信内部 userId 是否对应指定小程序内的有效账号，并且是用户指定的目标。尾号、姓名、请求体 actorId 都不能替代此核验。

这里的“生产身份”指真实身份来源，不表示要初始化旧业务管理员。目标仍只限独立副本 `schtest_v1_`；不操作 A/B/C 或旧业务集合。

只读成功仅说明“身份及指定记录在观察时可核对”，**writeAuthorized 永远为 false**。首次初始化仍须另一份具体执行包，并在实际写事务内重新核验。

## 3. 选定路径：先查清凭据来源，再做有界只读

### N0：接入载体核对（下一步先做）

Codex 只核对现有工具的能力说明、已有 SDK/API 调用载体及可用认证方式的非敏感元数据，形成一张接入卡：

- 可复用载体名称、版本、来源；是否支持 STS 与指定环境只读查询；凭据由谁管理、如何在宿主内提供、是否有已知有效期。
- 预期云主账号与允许的实际操作者/角色从受信管理记录取得；未知时保留空，不能把第一次接口返回值自动登记为获准名单。
- 是否能让身份核验和数据库读取使用同一批凭据。MCP 自己登录、另一进程 SDK 自己登录，不视为已绑定。
- 优先复用已存在的受限、短期认证方式；不扫描登录缓存、浏览器配置或密钥文件，不要求用户把 SecretKey、Token、OPENID 发进聊天。
- 若现有载体不支持：停止接入，明确缺的是“官方调用载体”还是“用户登录/授权”。只提出一个最小补齐动作及其范围，不让 WorkBuddy 先搭假核验器，也不退化为未经审查的手写签名。

**N0 不安装、不新建密钥/角色、不登录新账号、不改 IAM。** 需这些操作时另交具体方案。当前工具能力不足以宣称 N0 已通过。

### N1：真实云调用者与环境核验（N0 成立后）

1. 宿主取得一次受控凭据上下文，禁止把密钥、令牌放进参数文件、命令行、日志、证据或 Git。凭据轮换/过期则重新核验，不能沿用旧 allowed 结论。
2. 使用该上下文调用官方 STS `GetCallerIdentity`（2018-08-13）；核对返回身份类型、所属账号及实际主体，与接入卡的预期值精确匹配。未知身份类型、不匹配、缺字段或请求失败均停止。
3. 同一上下文核对固定目标：AppID `wxfb4db1615ac15531`、环境 `cloud1-d8gcq5ag39d847723`、地域 `ap-shanghai`。环境/AppID 关联须来自受信环境资料，不能把请求里填的固定字符串当返回证据；查不到关联则未确认。
4. 仅尝试获准的只读查询，记录实际可读范围。STS 成功不推出 IAM 可读或可写；一次读取成功也不推出所有资源权限成立。
5. 禁止调用方覆盖 endpoint、env、region 或启用跨账号回退；客户端构建方法、固定官方目标、超时与重试设置须在 N0 接入卡明确。每项业务查询单次发起；底层可能重试须如实记录，不能宣称只有一次网络请求。

MCP 可独立补充环境/资源观测，但只能标注其自己的来源与时间，不能冒充同一 SDK 凭据的验证结果。首次初始化不以副本 primary 已存在作为云操作者的认证前提，避免循环条件。

### N2：副本记录最小只读核对（N1 成立后）

先查集合是否存在与权限信息；存在才查记录。缺集合记 NOT_EXISTS，权限拒绝或网络失败记 UNCONFIRMED，不能当作“没有管理员”。不为得到完整报告补建集合。

| 目标 | 查询边界 | 结论 |
|---|---|---|
| schtest_v1_users | 只取已明确目标 userId 的一条记录 | 核对主键、active；身份派生一致性需在受控进程内核对 |
| schtest_v1_app_admins | 固定 primary 一条 | 记录缺失、已有目标、已有其他人、disabled/结构异常分别报告；均不写入 |
| schtest_v1_audit_events | 仅有效既定计划的确定性审计主键一条 | 无有效计划则 NOT_APPLICABLE，不列全表、不编造轮次、目标或批准上下文 |

补充边界：

- 目标记录缺失时停止到“账号尚未具备核验条件”。不调用 identify、requestBindingNumber 或其它业务函数补记录；这些路由可能写 users/审计。
- 派生公式沿用已验收核心 `u_ + sha256(appId + ':' + openid).slice(0,40)`。仅受控宿主读取目标记录必要字段，OPENID 在内存完成比对后不输出、不落盘；不能通过会完整返回原始记录的工具将 OPENID 带入聊天。如果暂时只能安全查公开字段，则身份派生项记未确认。
- 派生一致仅说明存储记录一致，不能单独证明现实中的“这个微信属于某人”；目标必须有受信微信登录产生记录的来源依据，以及用户对该完整 userId 的指定。旧项目存在该人不等于副本已有该人。
- 普通 get 为非原子观测，记录各自时间，不把三条读取称为同一快照。未来实际初始化仍需原子“仅不存在时写入”。
- 现有 adapter.readOnlyGet 仅开放 primary 与本计划审计，不支持 users。**不放宽它、不把读取改走写事务。** 后续独立只读宿主可为目标 users 提供精确主键读取；未实现前不宣称该通路已通。
- observePrimary 要求有效计划及批准上下文；前期缺这些内容时只报告普通资源观测，不伪造 approval 来调用它，也不修改已关闭的核心契约。

## 4. 只读能力与输出要求

后续实现只能暴露以上固定的读取方法，不接受任意集合名、任意查询表达式或客户端自报 allowed。只读宿主不导入/调用 initializePrimary，不提供 startTransaction/set/update/remove/commit/rollback 执行路径；原 CLI 的 --execute 拒绝保持不变。

这是程序级范围限制。若所用云凭据本身有管理权限，不能把代码白名单说成平台级只读隔离；权限是否可以进一步收窄须核对实际支持，调整 IAM 不在当前范围。

证据仅输出：独立 runId、工具/SDK 版本、固定环境、观察时间、请求 ID、脱敏云身份、身份匹配布尔值、指定内部 userId、记录状态、未完成项、writeAuthorized:false。完整主体若需匹配只在受控宿主内处理；不保存密钥/令牌、原始 OPENID、签名头、完整响应或原始异常体。输出使用新文件，不覆盖旧证据。

状态至少区分：本地契约通过 / 真实调用者已核验 / 指定环境可读 / 目标身份一致 / 记录观测未完成。不得只给一个“全部通过”掩盖未知项。只读请求仍可能产生日志或计费，不能据“无业务写入”承诺免费。

## 5. 最小开发包与验收门槛（N0 接入卡具备后才下发）

WorkBuddy 后续只新增一个只读宿主模块、一个默认禁止真实连接的本地入口及相称测试；具体文件名和官方调用方法由 N0 接入卡固定。本轮不开发、不派发代码任务，不改 P4、适配层、云函数、页面或关闭配置。

验收只围绕这六件事，不重跑未变化的旧业务全量：

1. 正确身份+固定环境+指定记录可输出最小报告，始终 writeAuthorized=false。
2. 缺凭据上下文、未知/错主体、过期或切换上下文、错环境/AppID/地域、客户端伪造核验成功：停止后续读取。
3. 集合缺失、文档不存在、拒绝访问、坏响应、超时分别报告；不补记录、不重发业务动作。
4. 越界集合/主键/任意 URL 被拒；测试监测所有写方法、事务入口及函数调用为零。
5. 原始 OPENID、Token、SecretKey、自由异常文本不出现在 stdout、报告或文件；使用合成敏感串测试。
6. 本地合成调用、真实签名读取、平台事务分别标注；只有另行完成真实只读核验才能写“真实接入通过”。

N0 若未成立，WorkBuddy 保持待命。不得为了交付测试数量先实现一个只能接受合成 allowed:true 的“生产核验”。
