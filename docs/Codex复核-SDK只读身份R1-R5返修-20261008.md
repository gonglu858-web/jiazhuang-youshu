## 2. S1 [P1] 统一 users 从 worker 到最终报告的实际契约

位置：worker:429；observer:886、913–990、1090–1140。

两个独立问题叠加：

1. worker 输出 `userStatus`，父进程净化器读 `status`。
2. `interpretWorkerOutput` 对 targetUser 调用 `sanitizeWorkerRecord(..., null)`：不保留任何状态，默认又要求 primary 才有的 userId，先降为 UNCONFIRMED。随后 `interpretTargetUser` 用正确 users 规则再次净化，已无法恢复丢失字段。

**实际复现**：两个 get 均成功，worker 的 userStatus=active、派生一致；完整解释链却得到 target.status=UNCONFIRMED、userStatus=null。仅把 worker 输出改名为 status 的对照仍失败。因此不能只改字段名，必须处理首次净化所用记录类型与目标键上下文。

最小要求：

- 给 primary/users 明确且一致的字段契约，让两层处理不丢失正常值或失败原因；users 不要求不存在的 userId 字段。
- 检查结果不可把明确 false 重算为通过。交付当前声称“必须严格 true”，但实现仍有 `!== false`；统一实现、测试与文案，不能同时声称两种契约。对 worker 未输出的字段不要凭空要求其布尔标记。
- 正向必须从真实 worker main 的实际输出，经过 `interpretWorkerOutput`、`interpretTargetUser` 到整体编排报告。合成凭据仍须 proven=false，整体可为 INCOMPLETE，但两条合法记录应各自 OBSERVED。
- 保留缺字段/disabled/错键/派生不符等反例；不得用只直接调用 interpretTargetUser 的手写对象代替整条正向链。

## 3. S2 [P2] 收紧剩余错误码、请求标识及记录键的输出边界

位置：observer:868、922、936、950–954、1280–1293；worker normalizeReadResult 的 requestId。

已复现三个残留：

- worker JSON 的任意 errorCode 字符串被解释器接受，后续进入顶层 errorCode 和说明。
- NOT_FOUND 的任意 docId 被保留到 primary 最终报告。
- SDK 返回的任意字符串 requestId 经真实 worker 主入口原样输出。

合成标记均保留成功。**这不是已发生真实秘密泄漏的证据**，而是声明“两层净化”尚有自由文本出口。前轮覆盖 userId/status/reason 的标记测试不能代表所有字段。

最小要求：已知错误码有限映射，未知用固定失败码；记录键只能是请求目标，否则 null/固定异常；requestId 采用已核实的格式白名单，未核实则省略或仅摘要，不能为了保留原值臆造平台格式。两层分类白名单不因 expectation=null 失效。保持诊断所需固定字段，不新增通用脱敏框架。

补测错误码、非 OBSERVED 记录键、请求标识三种标记，覆盖 worker stdout 和最终报告。不能仅在测试中删掉标记字段而不经过实际处理。

## 4. S3 [P2] 有效期在 worker 输入与父进程收尾处闭合

位置：worker:359–363；observer:1268–1304。

- **实测**：worker stdin 缺 expiresAtMs，stillFresh 返回 true，仍执行两条 get，credentialExpiredDuringRun=false。过期的有效数字对照执行零 get。缺失不是“尚未过期”；无限大等非法截止值也不应充当有效期限。
- **静态结论**：父进程 await runWorker 返回后，没有用当前时钟再次 assertCredentialFresh，仅使用 worker 的布尔报告。worker 最后检查之后到父进程汇总之间的过期没有覆盖。本轮未模拟这一时段，不将其写成动态实测。

最小要求：worker 第一条 get 前要求有限、可用的截止时间；缺失/非法直接停止零读取。父进程在 worker 返回及失败路径收尾核对期限；过期保留部分事实并注明不完整，不能依赖 worker 旧布尔值。保留原始失败原因与退出事实，不重新获取凭据、不调整55秒常量、不改已关闭计时器。

补测有效期限正常两读、缺失/非法零读、两读之间过期、worker 最后检查后父进程收尾前过期；最后一种使用受控时钟即可，不用真等到期。
