## 2. 剩余问题，按严重程度归并

### R4 / P1：父进程在子核验之前冻结结论，故障证明不决定出口

定位：[核验 v6](证据/CodexL2单根对照离线核验v6-20261031.cjs)第 580–582、594–619、635–640 行。

`ok/exitCode` 在七次 controlledReentry 之前计算。随后只把 faultOutcomes 放进报告，没有将 passed 与实际子结果汇总纳入最终结论；运行时 HEAD、AGENTS 读取及摘要也在其后。独立实际父脚本反例：

| 底层注入/对照 | 实际父结果 |
|---|---|
| 正常七类子场景，均按预期 exit1 | ok=true/exit0；reentry.completed=0、failed=7（预期故障被记成失败，却未进入最终判定） |
| 七次均返回 exit0/ok=true/意外0 | 七项 passed=false，父仍 ok=true/exit0 |
| 七次均 exit1 但 stdout 不是 JSON | 七项不通过，父仍 ok=true/exit0 |
| 末尾读取 AGENTS 时发生一次被 catch 的 HTTPS 尝试 | guard.unexpected=1，父仍 ok=true/exit0 |

验收：将子场景核验、所有末尾读取/摘要与必要收尾完成后，形成唯一父结论。区分“预期业务 exit1 的有效故障证明”与“启动失败/超时/无效回执”；核验实际退出状态、信号/错误、stderr、回执类型与字段对应，任一失败进入父 ok=false/exit1。不能只添加 wouldFail，不能再增加第二个互相矛盾的成功标记。保留七个真实故障出口与正常对照，并加入上述父出口反例。

同一根因下两项必须一起完成：

- 第 73 行私有 runner 仅传 `{shell:false}`，没有显式 timeout、受审输出限额或环境约束，也没有将 spawnSync 抛错归入结构化失败。当前调用对象真实选项已在证据列出。使用固定程序/参数及有界等待、输出、异常处理；不得把“私有”当作边界已经受控。保持公共进程 API 默认阻断。
- dns.promises 仅包 lookup/resolve，resolve4 仍遗漏。独立 VM 中调用实际入口形状 resolve4，被外层兜底拒绝一次，受审 guard.unexpected=0、29/29 全过、父成功。应按承诺的网络面列出并覆盖底层可直接联网入口，至少涵盖 dns 回调/Promise 家族及其他未覆盖入口；不能靠本次只注入 resolve 来声称完整覆盖。反例只在独立离线替身环境执行，禁止触真实 DNS/网络。
