## 2. R1 / P1：token 映射函数存在，但实际接线没有调用

位置：

- `miniapp/scripts/lib/cloudbase-cli-credential-host.cjs:267,349,375`：解析结果返回 `token`；提供了 `toSdkCredentialFields`。
- `miniapp/scripts/lib/cloudbase-sdk-readonly-observer.cjs:1585–1596`：直接返回宿主 snapshot，没有归一化。
- 同文件 `:585,790`：CLI环境和worker stdin均取 `snapshot.sessionToken`。
- `miniapp/tests/cloudbase-sdk-readonly-observer.test.cjs:2328`：所谓“同批传递”直接构造已经有 sessionToken 的快照调用 runWorker，跳过了本轮新增宿主。

独立复现加载真实编排器与真实宿主，仅用 EventEmitter 替代子进程。实际进入允许候选宿主的分支：凭据命令1次、三条CLI关联均被调用，但三个 `TENCENTCLOUD_SESSIONTOKEN` 均未匹配合成token；worker stdin也没有匹配的sessionToken。关联响应为合成成功，故能继续观察到worker；不声称真实平台会在缺token时成功。

**最小修复**：在单一交界处把宿主结果归一为既有快照契约，保留时效字段；两种获取路径应得到同一内部结构。不改worker来兼容第二套凭据结构，不放宽身份验证。增加实际 `runReadOnlyObservation → host.fetchTemporaryCredential → CLI三阶段 → worker` 测试，凭据命令必须经过真实新宿主，仅底层spawn替身；断言获取一次、每处三字段一致、无第三份来源、失败零后续发送。不要继续以分别测试映射函数和手写快照代替接线测试。

## 3. R2 / P1：获取工作目录没有落实隔离

位置：`miniapp/scripts/lib/cloudbase-cli-credential-host.cjs:302–309`。

`cwd = opts.cwd || d.fixed.credentialFetchCwd || profile` 默认复用既有登录profile。编排器并未创建获取专用的新cwd，也未检查配置发现路径；`buildFetchEnv` 的 cwd 参数没有用于任何检查。H1已确认CLI会向上发现项目配置，项目凭据可影响选择，因此仅固定profile与清理环境变量不足以完成身份来源约束。

本次用新建的**合成**profile，其中放置合成package.json：真实宿主未拒绝，spawn收到的cwd仍等于profile。只证明本地防线缺失，不声称现有真实登录目录已被污染。

**最小修复**：获取阶段创建独立的新工作目录，保持官方登录profile仅作为认证来源；检查CLI实际采用的向上配置发现路径，不以“叶子目录为空”代替整个发现范围安全。默认不得回退profile或项目根；异常/污染在启动凭据命令前停止，不删除或读取真实认证内容来“清干净”。模块测试可注入合成路径，但不得新增CLI任意cwd/profile参数。覆盖新cwd正向、叶子与祖先配置污染、目录创建失败及与后续关联profile用途不同。

## 4. R3 / P2：获取事实被写死，异常诊断未经投影

位置：SDK observer `:1352,1368,1371`。

1. 成功和失败分支均固定 `fetchSubprocessAttempted:true`。本次默认未开启候选路径，获取调用为0，报告却为true；指纹失败等前置拒绝也会遇到同类问题。
2. `fetchDiagnostics: error.detail || null` 把异常附加对象原样带出。注入getter抛出含 `detail.stdout` 的合成标记后，该标记出现在报告中。这是合成故障边界复现，不是已确认发生的真实密钥泄漏。
3. 宿主成功返回的 `fetchDiagnostics` 未进入成功报告；解析失败则没有带已发生的进程事实，不能稳定区分“未启动”和“已执行但输出不合规”。

**最小修复**：由实际启动点记录 attempted，并在解析前后保留固定退出/计数事实；报告只逐字段重建布尔、有限计数、退出码及固定错误分类，不直接传播 error.detail/code 的任意值。不记录原输出、任意异常文本或路径内凭据。覆盖前置拒绝=未尝试、模拟获取=明确模拟、实际宿主合成启动=已尝试、解析失败=保留退出事实、恶意异常附加对象=净化。

相应表述一并更正：

- “凭据不进环境”仅适用于SDK worker；三条公共CLI关联**通过子进程环境变量**接收凭据，这正是已审查的CLI注入路径。
- 默认门槛是候选路径尚未放行/前置未齐，不是用户没有给予只读授权；不要以此让用户重复授权。
- 源码保留的“公共CLI离线身份选择本轮未完成”旧注释，与新增true字段矛盾，删除或标历史。
- 本地 `publicEntryIdentityProven` 若保留，应只表明有固定范围离线证据；不得把 `additionalBehaviorsKnown:true` 或“secrets契约全部通过”扩大到尚未解决的刷新分支。
- 当前 `proven` 所有返回均false、汇总没有升级分支，这是关闭状态，不能说开一个 `allowRealCredentialFetch` 就能得到完整生产证明。真实接续前仍须明确实际观察事实如何形成；本轮不靠改常量true完成验收。

## 5. R4 / P1：复现脚本未完全拦截真实 CLI 启动

位置：`docs/证据/WorkBuddyH1H2H3-真实凭据获取最小接线复现-20261008.cjs:356–377`。

H3-4只传了合成 `fetchCredential`，未传spawn替身；随后真实编排器会继续执行 `runCliAssociation`，使用默认spawn启动官方CLI。这个分支**不需要** allowRealCredentialFetch，因为前面走的是合成getter。合成凭据不等于没有网络请求，公共CLI还有自动服务检查。

因此文件 `:422` 的固定 `realNetworkCalls:0` 不能作为调用观测证据。Codex本轮仅静态核对该缺口，**没有运行该WorkBuddy脚本**，也不推断其历史运行是否已请求到平台。交付的14/14只表明其断言通过，不能证明网络隔离完整。脚本还创建临时目录并由编排器创建隔离目录，`wroteFiles:false` 应收窄为未写历史证据/业务文件，不能泛指所有文件系统写入。

**最小修复**：保留原脚本/JSON作历史，另建安全复现入口；每个进入编排器的场景均注入受控进程，并对意外默认CLI/worker启动设置兜底拒绝。仅本地Node主目录检查可按精确命令允许。对拒绝/请求次数作实际计数，不用字面量0代替观察。离线公开CLI审查如需运行，继续独立使用传输封闭夹具，不把普通编排测试当成出网隔离。

新证据至少补两种敏感性：删除H3-4的spawn注入时兜底能抓住；删除R1实际归一化时完整候选链能失败。新结果另存；旧JSON不改成“匹配的新结论”。

## 6. H1差异裁决与尚未完成项

1. 原始证据脚本与JSON哈希匹配交付，合成网页登录正向、两次CheckTcbService、locale空替身、双配置目录和配置发现等可按原范围引用。本轮未重跑公共CLI夹具。
2. `Initialized=false` 仍产出凭据是已观察到的固定版本行为，**不得把它报告成失败或修改官方CLI来迎合原任务假设**。本次修正任务口径：凭据可获取不等于服务已就绪；不要求secrets命令自己一定停止，但绝不允许InitTcb/开通，后续只读目标核验须自行成功，不能凭快照认定环境可用。不为此新增自动开通或写入路径。
3. 可刷新分支尚未产出完整快照，因此不能写“H1全部前置通过”。后续仅按固定源码对齐合成refresh响应，再离线验证输出与缓存写回类别；若仍受阻，给出明确缺口，真实路径保持关闭。无需为了证明“可能写缓存”去操作真实登录目录。
4. 报告中的 `checkAuthImpl=DescribeEnvs` 是静态字段，而正向requests列表只有两次CheckTcbService；宿主注释“再发DescribeEnvs”不能当本场景实测次数。交付须分开静态可能行为与实际调用轨迹。
5. 生产同批链、IAM、真实库、目标userId来源、费用/余量仍未通过。既有只读授权不消除实现前置缺口；本轮不获取真实凭据。
