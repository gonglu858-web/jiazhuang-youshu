## 2. S1 [P2] exit提前完成，丢弃尚未读完的输出

位置：`miniapp/scripts/lib/cloudbase-readonly-observer.cjs:452` 的 `onExit`。

注释写“最终收尾仍交给close”，实现却在exit有code时直接finish。进程退出事件并不意味着stdout/stderr已关闭；当前finish移除data监听，后续已在管道中的内容会丢失。

本次真实模块、合成事件顺序复现：

| 顺序 | 现实现结果 | 应有结果 |
|---|---|---|
| 输出 `{"ok":` → exit(0) → 输出 `true}` → close(0) | 在close前完成，只保留前半，解析失败 | 收全有效JSON |
| 输出 `{"ok":true}` → exit(0) → 输出 `UNEXPECTED_TAIL` → close(0) | 在close前完成，尾部丢失，解析器接受 | 收全后拒绝未知尾部 |

这两个小对象仅演示读取与解析控制流，不宣称它们能通过STS字段校验；同样的截断会作用于真实完整响应。

**最小修法**：正常exit只记录退出事实/code/signal，不把stdout已经读完当作既成事实；正常结果待close后完成并解析全部受限输出。保留总超时/总输出上限及失败立即停止后续查询。exit后close迟迟不来仍必须有界失败；不要另建进程管理框架。

补测：上述两种exit→尾部data→close顺序、普通完整输出→exit→close、exit后无close。不得只发close而声称覆盖真实退出顺序。核对processExited、terminationConfirmed与注释语义一致，不靠伪造事件确认成功。

## 3. S2 [P2] 收尾移除error监听，晚到error可变成未捕获异常

位置：同文件 `finish:372–386`。

当前finish把child的error监听一并移除。超时/超限只是请求kill，进程未确认退出时仍可能随后发error。Node事件对象无error监听时会抛错，这不是“安全丢弃晚到事件”。

本次分别在timeout和overflow完成后发送合成error：两次均errorListeners=0、emit抛错。证据脚本外围catch保护自身；实际异步事件若无对应处理，可能使宿主异常退出，原始错误文本也可能经未捕获异常路径输出。

**最小修法**：完成后仍安全接收/吸收相关晚到error，不追加原始输出、不改最终报告、不二次kill、不重试或发后续请求。仅移除会累积数据的处理器，不把“所有监听都为零”作为正确性的验收目标。采用小范围幂等收尾即可，不要求无限等待。

补测：timeout、overflow、error首次结束后，重复或晚到error均不抛异常、不打印合成敏感标记，返回报告保持原状且无后续调用。真实事件API替身应使用EventEmitter，避免把error当普通自制回调而漏掉此行为。
