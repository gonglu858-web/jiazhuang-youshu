# 装修进度验收微信小程序：需求与业务规则

更新日期：2026-09-22（北京时间）

阶段：本地交互原型已试用；微信原生小程序最小工程已在开发者工具模拟器运行，业务功能与云端尚未开发或上线。

本文件整理此前对话。标为“已确认”的内容来自用户明确表达、选项选择或后续确认；页面字段和展示方式另列为讨论稿，不等同于已实现功能。

## 1. 产品目标与使用范围【已确认】

- 第一版面向用户自己的装修团队及其业主，入口为微信小程序。
- 以一套房子的装修项目为中心，集中展示现场进度、问题处理、验收、人员、材料、增项变更和设计资料。
- 由施工师傅每天现场拍摄照片或视频，业主同步查看装修情况。
- 出现问题后，管家检查并安排师傅整改，最终由主业主验收。
- 不同工种提前了解前后工序的进度，反馈可进场时间，由管家协调安排。
- 用户尚无完整统一的施工阶段、验收表和整改流程，需要共同梳理。

当前业务范围不包括多家公司入驻平台、独立手机 APP、采购费用核算、库存和领用管理。上述能力未被选入第一版。

## 2. 人员角色与权限【已确认】

| 角色 | 职责与权限 |
| --- | --- |
| 负责人（用户） | 创建装修项目、指定管家、查看全部项目；上传项目效果图与施工图。 |
| 管家 | 管理负责的项目，安排施工师傅和施工时间，邀请并核对业主、家人、设计师和师傅身份；检查问题、安排整改、发布现场巡检进度；现场检查阶段清单并提交主业主验收；统一登记和维护材料及增项变更。 |
| 施工师傅 | 查看自己参与项目的施工安排、其他工种进度和设计资料；现场拍摄施工记录，提交整改记录；施工完成后申请阶段验收；反馈可进场时间。 |
| 设计师 | 查看自己参与项目的施工进度、问题、阶段、材料和设计资料；上传或更新效果图、PDF／DWG 施工图及 720°全景链接。不安排施工和整改，不确认材料或执行业主验收。 |
| 主业主 | 查看自己的项目、留言和提出问题；确认问题整改、阶段验收、每批进场材料，以及增项价格、工期和完工验收。每个项目指定一位主业主。 |
| 家庭成员 | 查看项目、留言、提出问题和补充资料；不承担正式验收或材料确认。 |

### 项目隔离

- 成员只访问自己获准参与的项目；负责人可以查看全部项目。
- 同一项目的不同工种可以互相查看施工进度，不按工种隔离施工动态。
- 提前加入的师傅可以看项目资料，但只有安排施工的日期才承担每日上传任务。

### 邀请加入

管家分享项目邀请链接或二维码 → 对方申请加入 → 管家核对身份与角色 → 确认加入。

申请通过前不展示项目施工记录和资料。负责人如何首次开通账户、管家如何首次加入等账号初始化细节，留到技术方案阶段确定。

## 3. 施工安排与跨工种协作【已确认】

### 施工安排

- 管家按日期范围安排施工工种和每日上传责任人，支持临时调整。
- 每个工种指定一位主要上传责任人，其他师傅可以补充记录；按工种判断当日是否更新。
- 仅对当天安排施工的工种检查是否上传；休息、停工日不催报。
- 管家处理停工、休息、延期和责任师傅变化，并让项目成员了解调整后的安排。

### 所有工种可提前加入

- 项目开始时即可邀请各阶段已经确定的工种和师傅，不必等到该工种进场才加入。
- 后续工种可查看其他工种当前做到哪里、最新现场照片视频、本次施工内容和预计完成时间。
- 师傅反馈自己可以进场的日期，由管家结合现场情况确认并更新施工安排。
- 预计完成时间用于协调，实际进场条件由管家确认；施工进度和业主验收状态分别展示。
- 工种先后关系按具体项目安排，允许同时施工，不强制所有项目使用同一固定顺序。

### 当前建议的排程细节【讨论稿】

- 以“项目＋工种＋施工日期”展示待上传／已上传；同工种其他师傅补充的当日有效记录也计入更新。
- 日期范围内默认安排施工，休息或停工日期单独排除。
- 安排填写施工阶段、工种、起止日期、上传责任人、其他参与师傅及施工内容。
- 调整日期或责任人时保留历史，既有记录继续显示实际上传人。
- 暂以小程序内待办展示任务；微信订阅消息等外部提醒尚未选型或验证。

## 4. 每日施工记录【已确认】

师傅进入项目 → 现场拍摄照片或视频并填写施工说明 → 发布 → 管家与业主同步可见。

- 由师傅负责日常更新，不要求管家逐条审核后才对业主发布。
- 管家可以另外发布“现场巡检进度”，选择关联施工阶段／工种、施工位置并填写巡检说明；发布后立即对同项目成员可见。
- 管家巡检属于补充记录，不替代对应工种师傅当天的施工记录，也不将师傅的每日更新任务标记为已完成。
- 施工记录显示上传人、工种、日期和现场内容。
- 本次施工内容和计划完成日期由管家在“施工安排”中维护，供后续工种协调进场；师傅发布日常记录时只读查看，不能编辑。
- 完成每日上传，不等于该工种已完工，也不等于阶段验收通过。

### 现场记录媒体规则【2026-09-17 用户已确认】

- 从项目进入时自动带入项目名称，并醒目展示，避免发错项目。
- 工种根据安排带入，施工位置由师傅在发布时选择或输入。
- 师傅发布现场记录时，施工位置提供全屋、厨房、餐厅、前阳台、后阳台、洗衣房、主卧、次卧1、次卧2、儿童房、书房、客卫、主卫快捷选项；支持多选和再次点击取消，选中结果自动写入位置输入框。输入框继续允许自由编辑和补充其他位置。
- 发布页面只读显示管家维护的“本次施工内容”和计划完成日期，不再要求师傅填写；新记录自动引用当时的施工安排。
- 用户界面中的该类目统一表达为“本次施工内容”，不再显示“剩余工作”。
- 每条记录用以下任一方式完成：至少拍摄 3 张现场照片，或至少录制 1 段现场视频；两种方式完成一种即可，也可以同时拍摄。
- 只保留“拍摄照片”和“录制视频”，不提供相册或文件上传入口。
- 管家发布现场巡检进度时使用相同影像要求和现场拍摄入口。
- 现场照片写入拍摄时间水印；现场视频显示录制时间，暂不把水印烧录进视频画面。
- 同一天可以发布多条记录，按时间排列。
- 记录保存成功才标记已更新；失败时保留已填写内容，方便重试。
- 整改结果从对应问题详情中提交，与原问题关联。
- 视频时长、文件大小、压缩方式、补报及编辑规则尚未确定。

## 5. 问题检查与整改【已确认】

### 主要流程

提出问题 → 管家检查 → 明确整改要求、责任师傅与时间 → 师傅整改并提交结果 → 主业主验收。

- 业主和家庭成员可提出问题；师傅的现场反馈也由管家检查和协调。
- 主业主通过后，该问题标记验收通过／结束处理。
- 主业主不通过，填写原因，由管家继续跟进，师傅再次整改并重新提交。
- 不默认增加“管家必须再次复查通过，才能交业主验收”的固定门槛。
- 问题原始资料、管家检查意见、各次整改结果和业主意见保留在同一问题记录中。
- “提出现场问题”和“问题整改”是现场媒体规则的两个例外：既可现场拍摄照片／视频，也可从相册或文件上传照片／视频。
- 现场拍摄的照片写入拍摄时间水印；从相册或文件上传的照片写入上传时间水印。视频分别显示录制时间或上传时间。
- 整改提交至少包含 1 张照片或 1 段视频；提出问题时媒体可选。

### 管家认为无需整改

管家提交检查说明和依据 → 主业主选择认可说明或仍有异议。

- 主业主认可后结束该反馈。
- 主业主不认可，继续交由管家处理。
- 不能由管家单方面以“无需整改”为由结束反馈。

### 业主一直没有操作

- 保持待主业主验收／确认，由管家联系跟进。
- 不自动通过，不默认加入家人代验收。

### 问题详情页面建议【讨论稿】

显示问题位置、描述、原始照片视频、提出人、负责管家、责任师傅、约定时间、整改结果、验收意见及时间线。

按角色和当前处理环节显示按钮：

- 管家：需要整改并安排处理／无需整改并提交说明。
- 责任师傅：提交整改结果、申请验收。
- 主业主：验收通过／不通过并说明原因；无需整改时使用认可说明／仍有异议。
- 家庭成员：查看、留言、补充信息。

### 登录身份与工种识别【2026-09-19 用户已确认】

- 正式小程序通过微信登录账号和项目成员关系自动识别身份，用户每次进入时不需要自行选择岗位。
- 管家邀请并核对师傅身份，同时为师傅配置负责工种；师傅不能自行切换成其他师傅或其他岗位。
- 一位师傅确实负责多个工种时，由管家为该成员配置多个工种权限，登录后显示其已获授权的任务。
- 同一个微信账号可以在同一项目兼任多个角色，例如“负责人＋管家”；登录后合并显示这些角色已获授权的功能。
- 每次业务操作必须记录实际使用的角色，历史记录同时保留人员身份和操作角色，不能因为后续增加或取消角色而改写旧记录。
- 阶段验收的提交人与主业主确认人必须使用两个不同的微信账号。同一账号即使同时具有管家和主业主角色，也不能先以管家身份提交、再以主业主身份确认同一次验收。
- 正式开发校验的是稳定的用户账号标识，同时记录操作角色；只切换角色不能绕过提交人与确认人分离规则。
- 成员退出项目后立即失去该项目访问权限；退出不会删除或改写其历史照片、问题、整改、验收和其他操作记录。
- 历史记录保留原人员姓名、稳定账号标识及当时使用的角色，后续换人不把旧记录改到新成员名下。
- 成员还有未完成任务时，管家必须先将任务改派给其他具备相应权限的成员，系统才允许将其移出项目。
- 每个项目仍只指定一位主业主。更换主业主只能由负责人发起，新主业主接受项目邀请后才正式生效。
- 新主业主生效后，原主业主默认转为家庭成员；需要彻底移出项目时再执行普通成员退出流程。
- 原主业主以前完成的材料确认、整改验收、阶段验收和其他历史记录保持不变，不转到新主业主名下。
- 本地原型顶部的角色按钮和师傅下拉框只用于在同一浏览器模拟多个真实账号，不代表正式小程序的登录操作。

### 待办与微信提醒【2026-09-19 用户已确认】

- 第一版以小程序内“待办”作为完整、持续可查的任务入口。
- 微信订阅消息只提醒关键事项，包括整改任务、阶段待验收、材料待确认、施工记录逾期和成员邀请。
- 发送微信订阅消息前必须由用户按微信规则主动授权；未授权、授权次数不足或发送失败时，不影响小程序内待办的生成、查看和处理。
- 微信消息只作为提醒，不直接代表任务已处理；最终状态以小程序内的业务记录为准。
- 整改任务、阶段待验收、材料待确认和成员邀请产生后立即提醒一次。
- 当天安排施工但师傅到 17:00 仍未发布施工记录时，提醒一次。
- 整改截止前一天 08:00、截止当天 08:00 各提醒一次。
- 同一事项一天最多发送一次重复提醒，避免频繁打扰。

### 现场影像大小与上传【2026-09-19 用户已确认】

- 每次业务提交最多拍摄或选择 9 张照片；原有各场景的最低照片数量和照片／视频组合要求继续执行。
- 每段视频最长 60 秒。
- 正式小程序自动压缩照片和视频，普通用户不需要手动处理文件大小；具体压缩参数在技术方案中按清晰度和存储成本确定。
- 上传失败时保留本次已经选择的内容，显示失败文件并提供“重新上传”。全部要求的文件上传成功后，才允许完成业务提交。
- 正式提交前，提交人可以删除或重新拍摄影像。
- 正式提交后，不能直接删除或覆盖原照片和视频。发现传错时，由原提交人填写更正原因并补充新影像。
- 管家确认更正后，新影像作为当前资料；旧影像标记“已更正”并继续保留在历史记录中。

### 项目档案保存与删除权限【2026-09-21 补充确认】

- 项目完工后的档案保留 5 年。第 1 年保持正常在线查看，第 2～5 年转为低成本归档存储，需要时可以恢复查看或导出。
- 满 5 年后，仅负责人有权选择继续保存、导出或删除。
- 删除项目档案不需要主业主确认。系统可以提前通知主业主，但主业主没有审批或阻止删除的权限。
- 增项取消、终止和结算历史在项目存在期间不得单独删除或覆盖；项目完工满 5 年后，随整个项目档案由负责人决定继续保存、导出或删除。负责人选择继续保存项目时，这些历史也继续保留。

### 项目档案导出格式【2026-09-19 用户已确认】

- 负责人发起导出后，生成一个以“项目名称＋导出日期”命名的 ZIP 压缩包。
- 压缩包包含项目总报告 PDF，汇总项目人员、施工进度、问题、材料和阶段验收结果。
- 照片和视频按施工阶段及业务类型分类保存；效果图、施工图 PDF／DWG 原文件一并导出，720°全景以链接清单保存。
- 施工记录、问题、材料、验收和操作时间另提供 Excel 明细。
- 影像及资料的更正前后版本和更正原因保留在导出档案中。

### 首批真实项目试用范围【2026-09-19 用户已确认】

- 第一批只选择 1 个真实装修项目，不同时铺开多个项目。
- 试用人员包括 1 名负责人、1 名管家、1 名设计师、1 名主业主，可加入家庭成员；各工种师傅按真实施工进度逐步加入。
- 至少完整经历 2～3 个施工阶段，记录实际使用问题并完成调整后，再决定扩大项目数量和参与人员。

### 正式版技术方向【2026-09-19 用户已确认】

- 客户端采用微信原生小程序。
- 后端采用腾讯云 CloudBase：数据库保存项目、成员、施工、问题、材料和验收状态；云存储保存照片、视频、PDF、DWG 和导出档案；云函数处理权限校验、提醒、水印、压缩及档案导出等后台业务。
- 先按 1 个真实项目的试用规模设计数据和资源，试用后根据实际存储、流量和调用量选择合适套餐。
- 本项只确认技术方向，不代表已开通微信／腾讯云账号、购买服务、部署上线或授权正式开发。

### 首批真实项目的备份恢复目标【2026-09-21 用户委托助手确定】

- 针对施工中的第一个真实试用项目，发生需要从独立备份恢复的严重故障时，目标是**最多补录最近 1 小时的新记录和影像**，并在**24 小时内恢复项目核心资料访问**。这是正式试用前要验证的设计目标，不是本地原型或尚未开通的云环境已经提供的保证。
- 业务提交须在主存储成功后才显示“提交成功”；备份至少每小时复制新增或变更的业务数据和文件，保存独立副本，并监控是否按时完成。备份失败要及时告警和处理，不能继续声称满足 1 小时目标。
- 正式试用前须在隔离环境实际恢复一次，核对施工、问题、验收、增项金额和影像，确认在 24 小时内可恢复访问。低成本长期归档文件的取回时间另按最终存储方案核验。
- 具体服务、备份保存份数、费用与实际能否达标，仍需在账号和预算方案确定后核对；未验证达标时不把本目标标记为已实现。

## 12. 验收场景草案
