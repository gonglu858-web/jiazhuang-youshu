## 3. 当前执行前置：整棵测试进程树的收尾能力

实际代码 `Invoke-SelfTestEcho` 先ReadToEnd、后WaitForExit(5000)，所以内部5秒不是整个读取过程的时间上限。L1驱动只持有直接PowerShell进程，不能直接拿来执行L2并声称Node后代也已收尾。本轮局部搜索未发现可直接复用的完整进程树runner。

建议新增**仅用于核验的受控辅助层**，候选使用Windows Job Object管理本轮PowerShell及Node后代。此为实现要求，尚未验证本机可用性，不是已存在的能力：

1. 受控目标先挂起创建，加入本轮Job且核对限制设置成功后才恢复；拒绝加入、句柄/管道创建失败、恢复失败均停止，不退回普通spawn，不启用breakaway。
2. Job只涵盖本轮进程，配置关闭所有者句柄时终止成员；Job句柄不传给子进程。辅助层异常时走同一finally收尾；不按进程名批量杀、不扫描其他用户进程、不凭一个可复用PID推定所有权。
3. 同时、持续有界读取stdout和stderr，整体≤15秒、输出合计≤128KB；任何stderr、超限、超时即终止本轮Job。必须取得本轮目标退出及Job活动成员归零事实，才能标记收尾完成。失败后的收尾等待也有独立期限，不能无限等。
4. 外层驱动看管辅助层；辅助层未响应或被迫结束而没有完整收尾回执，报告失败/收尾未确认并停止，不把“已发终止请求”写成“进程树已退出”，不继续后置或业务测试。
5. 来源钉定和完整命令白名单应在最靠近系统调用的边界内；不能只检查exe名。辅助层只接受固定自检模式或本次固定L2向量，不能接受任意程序、脚本、路径、摘要、命令字符串。

优先检查已有本地能力；若需新增Win32互操作辅助代码，需在方案范围内明确宿主、来源、编译/临时文件及所有实际进程。**本页未批准安装依赖、运行编译器或无边界Add-Type。** 离线审查阶段若不能给出受控实现和实际执行清单，保持L2 blocked，提出最小缺口，不直接试跑产品。

纯替身测试不能证明OS级进程树收尾。实际L2执行包须先包含两个固定无害runner自检：正常退出对照，以及超时终止对照（固定Node仅等待，不读写文件或联网）。两者必须通过成员/句柄收尾检查；预期超时单独记账，不计作正常传输成功。自检本身失败则不启动产品L2。本页不启动这些自检；精确程序、参数、进程上限和回执格式由新驱动离线审查后冻结。
