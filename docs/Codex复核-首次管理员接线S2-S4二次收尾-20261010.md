## 2. N1：新增父进程核对漏掉执行期间的凭据时效（P1）

位置：`sandbox-primary-execution-host.cjs:928–956、1272–1311`。

`executeOnce` 只在核对前检查一次凭据。`runReadOnlyReconcile` 自建 adapter 时没有传 `deadlineCheck`，直接调用 P4 `observePrimary`，且没有核对完成后的时效检查。worker 的期限守卫已经修好，但新增父进程路径没有复用等效保护。

实测 `S3-default-reconcile-expires-mid-read`：合成超时 worker 后，进入默认核对（不注入返回对象）；在真实 SDK 第一条 primary 读取事件将时钟推进 31 分钟，越过本批凭据期限。仍读审计第二条，readOnlyGet=2，最后 `reconcileConfirmed=true/observationConfirmed=true` 并保存上述结论。终态仍是 RESULT_UNKNOWN，**没有升级成整轮成功**，但核对结论本身不成立。

最小收尾：在父进程固定核对路径的每次读前/读后及收尾复核同批凭据，统一传递时钟，过期不继续读、不确认。保留 worker 进程事实、已有提交事实与未知终态，不重新取凭据、不重新初始化。不要重做已关闭 worker 守卫、P4、SDK 适配器。

验收：第一读事件过期→只读 1 条且不确认；有效对照→读 2 条可按真实记录确认；最后一读完成至父层收尾之间过期也不确认。采用事件屏障，不依赖 now() 调用次数。

## 3. N2：字段各自合法，不等于组合结论成立（P1）

### 3.1 错误绑定没有实际进入保守核对

位置：host `1248–1255、891–898、918–926`。

绑定不匹配只置 `ok=false/observationConfirmed=false`，未将 `bindingMismatch` 纳入 mayHaveWritten，也没有撤销未经验证的 initialized/granted。正常退出的坏回执仍沿用自身 `resultUnknown=false/observeFailed=false`。

实测 `S4-wrong-binding-skips-reconcile-and-keeps-initialized`：他计划键与摘要→readOnlyGet=0、`resultUnknown=false`、`initialized=true/granted=true`，保存类型 FAILED，保存内容仍声称 initialized=true。**不再保存 COMPLETED 是进步，但交付声称“进入保守核对”不成立。** 现有 S4-1 用例未断言真正两读和这些冲突字段，因而漏检。

最小修正：无法绑定本计划的成功回执按不可信结果处理，保留执行是否发生的不确定性，在允许的同批上下文执行固定核对；不得把回执自报已初始化当成已证实事实。保留可信的本计划成功提交事实与“他计划/坏回执自报成功”的区别，不能把正常已提交分支一律抹为零写。

### 3.2 绑定正确但观察失败仍保存 COMPLETED

位置：host `1229–1256、1010–1026`。

`projectWorkerOutput` 仍独立接受顶层 ok/initialized/granted/observationConfirmed，没有结合已净化 bootstrap 与 observed 校验一致性。

实测 `S4-correct-binding-contradictory-observation-saves-completed`：键/摘要精确匹配，bootstrap.ok/initialized/granted=false，observed.state=unconfirmed、primaryStatus=disabled、两条存在性=false，但顶层自报成功。结果 `resultPersisted=true`，保存为 COMPLETED，报告同时保留 observed.state=unconfirmed。该样本没有任何数据库写入；证明的是坏 worker 协议可被父层误收，不声称真实平台发生过这种响应。

最小修正：在一个明确的聚合点判定“已提交且核对确认”，保证顶层、bootstrap、observed 与终态保存相互一致。矛盾或缺项降级，不靠单独布尔值放行。补到 executeOnce 和保存载荷的贯穿断言。

### 3.3 reconcile 存在性/摘要矛盾仍确认

位置：host `951–956、1327–1355`。

实测 `S3-injected-inconsistent-reconcile-confirmed`：注入返回 state=present、primaryStatus=active、正确 auditId，但 primaryPresent=false、auditPresent=false、错误摘要；摘要被净化为 null，仍 reconcileConfirmed=true。额外私密标记已正确丢弃，这部分关闭；剩余是合法字段组合未校验。

该反例属于受控测试注入，不声称客户端可直接调用，也不声称实际 P4 会生成矛盾记录。它验证父层净化与聚合的边界。实际 P4 `observePrimary` **不返回 inputDigest**，而是内部校验审计摘要后返回 state。因此不要机械新增“P4 必须输出摘要”要求导致真实正向路径全被拒：明确区分实际读取后形成的结论与注入对象，自洽校验需符合 P4 的真实返回契约。普通对象不得替代已验证两读事实，不需引入通用签名或框架。

N2 验收至少包括：错误绑定→真实两读/保守终态；正确绑定但观察不完整→不保存 COMPLETED；相互矛盾的 reconcile→不确认；真实 P4 present 正向不回归。测试不止断言敏感字段被丢弃或错误键变 null。
