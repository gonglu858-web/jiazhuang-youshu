## 3. R2 [P2] 输出未合并计数，结束后仍收集数据，终止状态表述不实

位置：同文件 `spawnBounded:262–321`、`runStage:641` 附近。

复现：
- 测试限额100字节，stdout60 + stderr60，实际120，返回 overflow=false、kill零次。
- 一次输出101字节全部拼入内存后才拒绝，结束后 data listener 仍存在；再来数据仍处理并再次 kill，未形成封闭收尾。持续输出会继续拼接字符串。
- kill()返回false且未出现close，仍返回 signal=SIGTERM；上层固定文案称“已终止”。这只证明尝试发送终止，不证明进程已退出。

**最小修法**：
1. 对 stdout+stderr 总原始字节累计上限；先计数再保留，保留缓冲不得越限。按字节处理并正确解码跨chunk UTF-8，不因逐chunk String转换破坏内容。
2. 一旦超时/超限/失败完成，停止追加/解析晚到数据，清理计时器和资源；晚到error也须安全处理。不要引入无限终止循环。
3. 区分终止请求、已观察退出、终止未确认。只把实际 close/exit 信号记为进程退出证据；不能凭发出kill合成“已终止”。不确认时仍失败且不发后续请求，不重试查询。

验收补总量越限、单个大chunk、finish后继续输出、kill返回false/抛错/未close、正常退出；断言终态稳定、内存保留有界、无后续查询。已有55秒上限保持，测试用小限额/短时间替身，不等待55秒。

## 4. R3 [P2] 提示行只能在 JSON 外，当前删除了 JSON 内的坏内容

位置：同文件 `parseCliJson:430–436`。

输入本来不是合法 JSON：

```text
{
"Type":
ℹ → STS.GetCallerIdentity
"CAMRole"
}
```

原始 JSON.parse 拒绝，而当前解析器删除中间提示行后成功返回 CAMRole。若这发生在完整响应内，会把异常输出“修好”后继续关联判断。

**最小修法**：仅在 JSON 根对象前/后处理已确认的动作提示；根对象内部逐字保留给 JSON.parse，内部混入任何提示都拒绝。无需扩建通用日志解析框架。保留纯JSON、真实提示+包装、字符串含花括号的正向例；增加中间插入提示的负例。

## 5. R4 [P2] 失败报告丢失已经调用的阶段，缺失错误码还被测试误判通过

位置：同文件 `runStage` 返回解析结果处、`ERR`、`assertDescribeEnvs:536/544`、`runReadOnlyObservation:709–733`。

复现：STS API进程已启动并退出，返回坏JSON。报告却为 cloudObservationPerformed=false、stoppedAt=unknown。它依据“是否已有合格callerIdentity”代替“是否尝试执行查询”。另外 EnvList=null 的 ObserverError.code 是 undefined，因为 ERR 中没定义 ENVS_FIELD_INVALID；现有测试用同一个 undefined 作比较，仍通过。

还缺任务要求的逐阶段开始/结束时间；非零退出码在构造错误时仅塞进message，而最终报告不带message，退出诊断也丢失。

**最小修法**：
- 在调用点记录阶段尝试/开始/完成或失败，并明确区分 API 子进程已尝试、响应已取得、校验已通过；不能据此宣称网络请求确已到达平台。可保留原字段，但须给 cloudObservationPerformed 一个不误导且清楚的语义，并增加必要的 attempted 事实。
- 解析错误绑定当前stage，所有失败码为定义过的固定字符串；补 ENVS_FIELD_INVALID 或使用已有明确码，测试不能用undefined通过。
- 输出净化的退出码/超时/终止是否确认和逐阶段时间，仍不得输出原始stdout/stderr或错误文本。

验收：首步坏JSON、首步字段错、次步非零退出、超时、全部成功分别保留真实阶段事实；后续未发即标未执行。云响应不合格绝不变成关联成功。
