## 3. T1 [P1] 无法列出终态目录不能等同于目录不存在

位置：`miniapp/scripts/lib/sandbox-primary-approved-run.cjs:175`。

`findExistingTerminalRecord`对所有 `readdirSync` 异常都 `return null`。这个返回值表示“没有同轮终态”，随后runOnce继续创建started、取凭据及执行事务。EACCES/EIO只能证明检查未完成，不能证明没有旧记录。

独立样本 `S2-terminal-scan-EACCES`：夹具目录已有本轮COMPLETED且无started，仅对该terminal目录的列举注入EACCES，其余文件操作照常。实测：目录检查1次、随后凭据1次/API4次、primary/audit各1写、commit1、started已创建；最后保存遇旧文件返回APR_TERMINAL_SAVE_FAILED/causeCode=APR_TERMINAL_EXISTS。旧文件未覆盖，e.execution此时已能保留提交事实。**后半段留证修好了，但前置检查失败仍放行。**

这是合成文件系统故障，不声称真实目录出现过权限故障或云端重复提交。目录可访问但不可列举、临时I/O故障均不应视为“检查通过”。

最小修正：仅明确的目录不存在（ENOENT）可按空目录处理；其他检查失败在started/凭据之前以固定、净化的本地错误停止。保留首次运行无terminal目录的正常路径，以及三类已有终态拒绝和排他wx。无需扫描旧文件内容、删除目录、扩大并发框架或修改P4。

新增完整入口断言：EACCES及EIO -> 零凭据、零worker、零set/commit、无started、旧文件字节不变；ENOENT/可读无同轮记录为正向。使用实际错误code分类，不依赖异常文字。

## 4. T2 [P2] 入口已完成保存，但返回的持久化字段仍是保存前的宿主值

位置：`sandbox-primary-approved-run.cjs:454-455`、`533-555`。

入口在落盘payload上修正两个标记，最后却直接返回原 `result`。宿主有提前返回和未知结果分支，不能假设它总会补齐入口自身保存事实。

| 完整链样本 | 磁盘(resultPersisted, unknownPersisted) | 返回result对应字段 |
| --- | --- | --- |
| 正常COMPLETED | true, false | true, 缺失 |
| 主体不匹配的FAILED（入口自行保存） | true, false | 缺失, 缺失 |
| worker超时RESULT_UNKNOWN | true, true | 缺失, true |

独立JSON以null表示原undefined便于展示。外层 `saved.saved=true` 是正确的，因此这不是“文件没保存”，也没有把FAILED升级成成功；问题是本轮宣称的文件/返回字段一致未实现。E-7只查resultPersisted，E-8对FAILED只检查磁盘、未知分支只查unknownPersisted，漏掉了交叉断言。

最小修正：入口在成功保存后，以实际保存状态和类型构造一致的返回字段（可复制报告再补两个值），失败异常仍保持净化事实和false；不要改宿主既有事务/未知结果聚合。对三种类型及保存失败检查两个字段，同时保留业务status、errorCode、commitFactEstablished等原事实。
