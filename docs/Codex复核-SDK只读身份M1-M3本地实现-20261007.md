## 2. R1 [P1] 修正可运行接线，不把缺实现写成只差生产观测

位置：observer:486、924–935；worker:243–252、327–349；observer本地准备:259–283。

1. `runCliAssociation`把无扩展名JS脚本 `bin/tcb` 直接当spawn可执行文件，参数从api开始；没有用固定Node。`spawnBounded`不会代为补Node。Windows应按已验收方式 `固定nodeBin + [固定cliEntry,...apiArgs]`、shell:false。当前测试只按argv[1]/[2]伪造响应，漏掉这个错误。
2. 已取得node-sdk 2.10.0的 `lib/index.js` 导出对象，公开入口是 `init(config)`；worker却 `new CloudBase(config)`。离线实际require得到object，new触发TypeError，真实worker会停在SDK_UNAVAILABLE。改用实际包公开入口，不另装SDK；相称测试须运行真实worker初始化路径，网络层拦截，不再只测buildSdkConfig。
3. buildSdkConfig未传region，报告却固定写ap-shanghai。必须实际固定region并验证传参；报告不能用常量冒充已核实请求地域。本地准备还应核对node-sdk/database的实际版本及真正入口/读取实现，不仅对存在文件计算哈希就算版本通过。
4. `fetchTemporaryCredential`生产路径始终抛SAME_BATCH_NOT_PROVEN；只存在deps.fetchCredential。`--read-only`因此不可能靠再执行一次就完成。保留停止是对的，但交付状态应为“获取宿主未实现/公共入口离线验证未完成”，不是完整实现后的平台验证缺口。

修复顺序：先完成受控公共CLI离线身份选择证明；通过后才在这四文件范围接入任务指定的公共secrets子进程获取实现。本地可实现而不执行真实命令，不能把“不执行”混同于“不实现”。若离线路径无法证明，明确停在此点，不以真实凭据试错；Codex不会通过注入临时函数绕过门槛。

验收：用真实包和真实入口边界（合成网络/进程可控）证明Node启动、SDK init、固定region及正常只读路径；错版本/失败先停。真实网络仍为0。

## 3. R2 [P1] worker进程必须有界失败，不能相信stdout替代退出事实

位置：observer:564–676。

- 新写的runWorker计时器只kill、不resolve；kill返回false、error后不close、exit后不close均可一直挂起。触发生产55秒回调的离线样本 `settledAfterTimer=false`。
- stdout先整块Buffer.concat、超限继续积累；stderr单独计数。700KB stdout+700KB stderr超过合并1MiB，实测仍ok:true、kill=0。重复chunk还可能重复kill。
- 忽略exit/close的code、signal；非零退出仍可凭JSON判成功。超时后close且stdout含ok:true也返回成功，WORKER_TIMEOUT没有被正确使用。
- interpretWorkerOutput的Object.assign(base,parsed)允许任意字段覆盖宿主终止事实或携带原始内容。

复用已验收收尾行为/内部能力设计，避免继续复制已关闭缺陷；不改旧CLI观测器。凭据stdin这一个差异须有最小受控实现：统一合并字节计数、先计再截断、只终止一次、独立有界完成、stdin错误失败、close前读完、晚到error吸收。保留真实退出码、signal、超时和终止未确认，不接受stdout自报覆盖。超时/溢出/非零/信号/通信失败均不能成功。

验收使用EventEmitter事件屏障验证正常、无exit/close、exit无close、kill失败、error、stdin失败、合并超限、重复chunk、非零带合法JSON、超时带合法JSON；不直接调用解释函数代替runWorker生命周期测试。

## 4. R3 [P1] 严格记录校验与顶层汇总，修复假通过及泄露

位置：worker:267–283、369–436；observer:697–764、875–913、929–932。

已复现：

1. primary缺userId/status时，worker标志为null；解释器仅拒绝 `===false`，得到OBSERVED。
2. users缺status/openid时同样得到OBSERVED，甚至报告derivationMatches=false但无失败原因。
3. 带错误code的 `{data:[]}` 被当NOT_FOUND，错误优先级缺失。
4. 非法userId字符串仍进入报告；合成敏感标记原样泄露。status、requestId、reason也必须按各自契约投影，不把任意字符串都当已净化。
5. 真实编排收到worker `{ok:false,errorCode:'SDK_UNAVAILABLE',writeAttemptsCount:0}`，primary/users均UNCONFIRMED，顶层却 `status=OBSERVED,incomplete=[]`。
6. 仅提供合成deps.fetchCredential即 `proven:true`；同批链还未执行就可标已证实。依赖注入不是生产证据。

必须先验证worker执行事实、输出形状、ok严格true、writeAttemptsCount严格0；错误或未知记录纳入总状态。worker的文档主键、完整userId、status及派生结果要求明确的有效值，缺失/null不算通过；原始错误响应不归零记录。两层须拒绝/净化非法值，不能仅信任worker的布尔标志。

NOT_FOUND作为一次有效的缺失观测可单列，但不得称为“有效管理员”；停用/冲突/缺字段/派生失败/读取失败均不能使整个核对为OBSERVED。缺目标维持未执行。审计NOT_APPLICABLE保持。

把“合成同批传参通过”“真实同批路径观测通过”分开，测试注入不可生成生产proven结论。保持writeAuthorized=false，不实现写授权器。

验收至少跑完整真实编排：正常记录、目标缺失、primary/user字段缺失、读取错误、worker失败、过期和敏感串污染；断言最终状态与实际字段，不只测试手工构造的摘要对象。

## 5. R4 [P1] 身份隔离和有效期必须覆盖实际运行边界

位置：observer:391–469、482–536、845–878；worker凭据输入与两次读取。

- Windows环境变量忽略大小写，新函数仅删除大写XDG键、覆写大写USERPROFILE，保留了 `xdg_config_home`、`UserProfile` 等别名；隔离目录真实性因此不能仅凭这两个赋值宣称成立。代理变量也全部继承。离线已证实这些键保留，未声称真实CLI已经读取它们。
- authStatePaths只检查两个路径；实际公共CLI的项目配置与全局存储取值链需验证完整。新建目录的父级/链接及实际homedir/config/cwd须在受控检查中对应，污染只拒绝、不删除用户文件；不要提取webpack内部模块作为生产接口。
- CLI任一步执行/解析失败后仍继续三阶段，样本第一步exit1仍启动全部三项；应立即停止后续，保留not-executed事实。
- assertCredentialFresh只有各阶段前调用，没有任务要求的后检查；worker收到的载荷根本不含到期时间，两条记录读取间不能检查，结束后也未复核。过期窗口仍可能被标成功。

按大小写无关方式清理/固定所有影响身份、路径、服务目标和代理的变量；不修改系统环境。来源证明用公共入口离线测试，未通过之前保持真实路径关闭。每次CLI请求前后、worker启动前、每条get前后及总结果前都核对同批有效期；不刷新、不重新获取、不混批。过期时已完成的观测可保留为带时间的部分事实，不能升级为完整核验。
