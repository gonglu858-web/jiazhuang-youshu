## 3. 官方可行路径与仍待验证处

官方 CLI 支持浏览器/设备码授权登录；官方临时凭据文档说明可供本地 SDK 使用。选择这条候选路线，避免让用户复制长期密钥进聊天。当前未安装、未登录、未提取凭据。

特别区分：

1. 新 CLI 登录会有自己的登录上下文，不自动继承当前 MCP；不清理或改写当前 MCP 连接。
2. 官方“临时凭据”输出含敏感值。未来必须由经审查的宿主在进程内部获取并净化；不能直接运行输出到聊天/终端录制的取凭据命令，也不能要求用户粘贴输出。
3. 临时凭据命令的环境参数按文档是附加环境信息，不是将云凭据权限限制到此环境。仍须 STS 身份匹配、目标环境关联核对和固定资源边界。
4. 文档示例的 token 参数不能直接套到已取得的 node-sdk 2.10.0：该版本本地源码使用 sessionToken。后续须核对实际 CLI 输出，再作显式字段映射，不修改已验收事务核心。
5. 临时凭据是否适用于 STS、如何取得可靠有效期、实际可用的官方 API 客户端与其重试行为、预期云账号/操作者名单仍未验证。拿到登录态不等于 N0/N1 全部通过。
6. 不把首次 STS 返回自动加入允许名单；名单仍需来自独立的受信管理资料及用户指定。副本用户记录缺失时仍不调用业务身份路由补建。
