## 2. S1：R1 只补两个遗漏分支（P2）

文件：`miniapp/scripts/package-sandbox.cjs:670–689`、`:429–501`。

### S1a 半成品无 manifest

预检已收集 byteMismatch/hashMismatch，但只在 `fs.existsSync(manifestPath)` 为真时抛出。无 manifest 的半成品目录有不同内容的 gate.js、缺少 index.js 时：工具先新增 index.js，写入循环走到 gate.js 才拒绝。**这就是上轮原反例，未真正覆盖。** 新测试 R1.7 先建完整包，保留 manifest 再篡改，只证明另一分支。

修法：既有包文件内容冲突不依赖 manifest 存在，发现即在预检拒绝；有 manifest 才额外核对其声明的完整性。补一项“仅有不同 gate.js、无 manifest、缺 index.js”的回归，断言拒绝后仍只保留原 gate.js、index.js/manifest 都未创建。不要把它归入不可预测 I/O 故障。

### S1b 来源记录

实测把 manifest `sourceDir` 改为 `miniapp/cloudfunctions/memberAccess`，`files[0].sourceKey` 改为旧 memberAccess/index.js，保持包字节和哈希不变，`--check` 仍通过。当前函数仅比较 path/bytes/sha256，没有核对任务要求的实际来源。

修法：与计算出的实际 `sourceDir`、`packageDir` 和各 `sourceKey` 精确核对；缺项也拒绝。不要把 manifest 自报来源当事实，不新增签名体系或自哈希。schema /2 如不需改变字段结构可继续沿用，原制品不覆盖。

顺手统一头部“失败时不写任何新产物”和 manifest 限制“以 manifest 是否存在判断完整性”：可预知失败须零写；真实 I/O 故障可能残留文件，**存在 manifest 不等于已完整校验通过**。

## 3. S2：R2 的 check 分支漏了白名单文件链接（P2）

文件：`package-sandbox.cjs:654–675`、`:692–698`。

`listFilesRecursive` 返回 `{rel:'index.js',symlink:true}` 时，因为该相对名在 PACKAGE_FILES 内，extraPackageFiles 过滤会把它丢掉。后续 facts 与 check 直接 `path.join + readFileSync`，没有 `resolveInside` 或 `lstat`。生成写入循环有保护，**检查模式没有同一保护**。

本次创建真实 file symlink 返回 EPERM，未声称实链穿透。额外用内存 fs 包装仅将 package/index.js 的 Dirent/lstat 标成链接，保留原字节：检查返回 `mode:'check'`，该文件 lstat 调用次数为 0。该证据只证明控制流遗漏，不代替 Windows 实链测试。

修法：包体每个读点复用统一安全解析，预检即拒绝任何链接条目，即使其名字属于白名单；确认普通文件类型后读。补 check 与生成共用的反例；无权限创建实链时，真实用例明确 skip，合成分支测试独立标注，不冒充平台验证。根与祖先已实现部分无需重写，不建设通用文件系统防护框架。

## 4. S3：R3 补齐已声明字段（P2）

文件：`package-sandbox.cjs:886–895`、`:979–984`。

实测三种单项变异均通过真实验证器：

1. `function.dependency.wxServerSdk='999.0.0'`；
2. `collections[0].created=true`；
3. 删除 `collections[0].ttlEnabled`。

依赖当前仅核对对象存在和 installThisRound，未核对所谓“锁定”的版本。按已审查清单固定 wxServerSdk=3.0.1、packageJson 指向当前副本；集合 created 与 ttlEnabled 必须显式 false。只补这几个字段及缺失/变更测试，不新增资源规格、不改候选 JSON 的正确值。索引有序/方向/unique 与 runtime 已通过，不再重做。

## 5. R4/R5 关闭主要问题；三处文案随改

1. 操作稿 §1.3 的“解除锁的唯一路径是标记”删去。标记不解锁；正常成功及已明确的首次拒绝会按 client 处理 envelope。V06-b/c **真正并发**当前不可达，不等于一笔成功之后永远不能发下一笔串行请求。不要再为这个说明修改已验收客户端。
2. §5.2 execute 调用 createProject 在真实入口先被 `assertActionAllowed` 拒绝，返回 `SANDBOX_ACTION_NOT_ALLOWED_IN_PHASE`；`SANDBOX_PHASE_LOCKED` 是后续专用 guard 的保护码，不是该入口首先返回的码。改表即可。
3. §5.3 `sandboxProjectId` 不只是展示：客户端 preflight 会用于目标匹配/缺目标拒绝；服务端仍独立决定授权范围。应同时写明这两层，不把客户端检查说成授权依据，也不说仅展示。

P4 循环已解除，原子条件写方向保留；本轮不开发初始化程序或驱动。
