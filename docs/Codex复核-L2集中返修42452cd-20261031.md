## 2. 统一剩余返修清单

### R1 / P1：把内部状态真正留在模块内，固定持有与启动的同一对象

定位：[驱动v2](证据/CodexL2单根产物绑定与单次驱动v2-20261031.cjs)第12、63–81、89–124行；PE映射第35–46行。

- 非导出Symbol不等于不可读取。`Object.getOwnPropertySymbols(binding)[0]`可取得品牌，`binding[symbol]`直接暴露可写internal。真实模块反例把`consumed`重置false后同一runner再次成功（spawn=2）；复制Symbol和状态到手造对象并替换config/sources/参数，仍ok=true且交付`not-rootOnly`参数。Object.freeze(binding)没有保护其Symbol所指对象。
- `boundary.productPath`在检查、持有、启动、后验分别重读。访问器反例让持有与后验指向A，启动指向B，仍ok=true。不能让调用方属性决定每次读取的目标；spawn参数也未内部固定shell/环境等能力选项，沿用主报告R1的边界要求仍未闭合。
- `bind(configRaw, productBytes)`仍缺与受审编译后记录、固定产物路径的关联。为任意自报字节计算摘要不是受审来源证明。此处只要求准备固定接口与替身自测，不批准真实编译或运行。
- CLR映射用`Math.max(vsize,rsize)`后只检查文件总长。将CLR RVA落在节的虚拟尾部（节raw长度512，CLR偏移768）并在文件别处放置头，仍接受；不能将别处文件字节算作该节的CLR。

**验收要求：** 用模块私有WeakMap或等价不可从返回对象反射得到的状态，将对象身份、固定配置、产物来源/路径/摘要、一次消费绑定。不要仅冻结泄露的对象或换Symbol名字。所有外部输入形成一次受控快照，持有、启动、后验消费同一对象，固定能力内部构造参数与环境。增加反射伪造/重置、路径访问器、来源记录不符、节raw范围外CLR等实际接口反例，拒绝时零启动。不得改旧核心或共享能力层来扩大执行权限。
