## 3. 实施顺序与约束

### C0：先确定原生输出的编码契约

在编码实现前，先交付同轮的简短“命令→原始输出字节→编码来源→严格解码方式”表。

1. 以受限新驱动捕获固定whoami/icacls查询的原始Buffer；仅查询当前身份与已约定私密根的ACL，不列目录、不读记录、不修改ACL。原始身份/ACL只驻内存，公开证据仅写代码页数值、程序版本/摘要、解析结论及错误类别。
2. 如需系统代码页信息，允许一条固定的只读系统查询；记录它究竟代表ANSI、OEM还是当前原生输出通道。**不能将任一个系统代码页值直接当作该命令输出编码的证明**。须说明与实际命令及重定向方式的关联，并用已知合成字节/文本验证解码实现。
3. 解码规则不能取自任意环境变量、计划或命令行覆盖。每种输出在本次调用前选定唯一受支持编码；不执行“UTF-8失败就试GBK，直到ACL通过”的回退。只实现已有本机依据的有限代码页，其余明确拒绝，不追求全语言兼容。
4. C0的本机只读取证可以有查询失败结果，但不得调用DPAPI、启动PS1或保存文件。若无法可靠确定编码与输出通道的对应关系，**停止实施编码放行路径**，只提交取证结果和缺口；不得猜编码或以权限解析成功反推编码正确。

这一步是编码方案的必要依据，不将本轮尚无证据的“ANSI/GBK”源码注释当成已证事实。

### C1：字节级限额和严格解码，权限语义保持

- spawnSync先返回Buffer；在解码前按真实字节检查stdout/stderr上限，继续保持固定程序、固定参数、shell=false、10秒/128KB约束及失败状态检查。Git、DPAPI的ASCII/UTF-8协议分别约束，不将Windows原生命令解码规则套到所有进程。
- 解码须拒绝非法/不完整序列、替换字符、无法确认的编码和异常输出；只支持严格解码能力已验证的现有运行时。若运行时没有所需严格能力，报告阻断，不引入宽松替换或联网装库。
- 原始行完整交给ACL解析器，不删除非ASCII内容、未知行或“看起来像统计”的任意行。允许的中英文成功统计行须完整锚定、失败数为0；如实际标点/措辞与既有规则不同，须有净化结构证据和精确反例，不用宽泛正则放行。
- 至少有可解析权限条目；全部主体均须属于既有当前用户/SYSTEM/Administrators集合。未知主体、会话主体、宽泛组、畸形行、缺权限条目仍拒绝；不因前一行合法而忽略后一行。
- 中文合成用户名应在正确解码后与同源whoami主体一致；不靠删除中文或改成宽泛SID前缀来匹配。现有SID规则不扩展。
- 错误只暴露固定代码/分类，不能包含原身份、ACL行、输入值或PowerShell原始stderr。可保留外层`PSR_LOCAL_TOOL_FAILED`/`PSR_PRIVATE_ACL`契约，内部分开记录解码不确定、命令失败和主体拒绝，避免把乱码写成“权限过宽”。

### C2：固定系统模块选择，失败不回退

- 静态列出PROTECT/UNPROTECT实际使用的cmdlet及所属系统模块。按固定Windows PowerShell程序的`$PSHOME`构造所需内置模块路径，初始化先于任何明文读取、加解密或管道创建；设置错误即停止。只加载实际必需模块，不能遍历所有模块尝试。
- 不按PATH、可覆盖的模块名或调用方提供路径选择模块；不改PSModulePath，不新增下载、安装或更新行为。模块缺失/加载失败返回固定错误，禁止回退到同名外部模块或另一PowerShell版本。
- 本轮仅改变已有固定本地DPAPI命令的模块准备，不更换加密算法、密文格式、CurrentUser范围、stdin/本机命名管道传输契约、超时/清理行为。不能改成明文文件、stdout输出明文或TCP通信。
- PS1只做静态依赖记录，不修改其窗口、调用参数或保存流程；若发现它需要独立修复，单列下一任务，不顺手扩修。
- 模块与编码查询若确需新增私有进程入口，必须固定完整命令/参数/输入结构、限额及错误出口；公共child_process仍全部默认拒绝。不通过暴露rawSpawn、任意PowerShell片段或shell/options配置来实现。

### C3：先合成验收，随后交Codex复查

本轮开发测试全部合成；不运行真实DPAPI、不启动实际输入窗口、不写真实私密根。唯一实际系统动作限C0固定只读查询。真实本机预检/加解密/UI是否恢复，由Codex复查后按原方案分阶段执行；当前Restricted下不试运行PS1。
