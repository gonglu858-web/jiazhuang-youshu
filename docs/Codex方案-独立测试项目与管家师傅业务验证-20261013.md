## 4. 按窗口执行，先小后大

以下均是**待执行计划**。每个窗口启动前需要具体执行包：完整参与账号及来源、业务 roundId、窗口编号、UTC 截止、允许动作、逐步输入、制品逐文件哈希、受限核对办法和配对关闭包；用户确认覆盖该窗口的部署、业务写入、只读核对及关闭。不能把本次“整理方案”当成上述批准。

建议单窗口预留 30～60 分钟操作时间，上限不超过既有两小时方案；实际日期另定。过期则关闭并盘点，未决请求不通过换轮次或清缓存绕过。同一虚构项目跨准备／执行／退出窗口继续用相同业务 roundId，另设窗口／证据编号；不能每换窗口就换项目 roundId 而误建第二个项目。

### 窗口 P：身份、唯一项目与成员

1. 启动前只读核对既有资源、primary、参与者来源、集合规则／索引、当前关闭制品及套餐余量；如需取真实凭据，纳入该窗口具体批准。不新建资源、不更改权限或套餐。
2. 两位新参与者各自使用本人微信进入受限测试版。确认已有登记则复用；未登记时仅执行批准的本人登记。本人管理员无需重新开通。
3. 负责人调用一次 createProject，核对项目、轮次唯一回执、初始负责人会员及审计。代码预测 ID 不替代真实创建回执。将真实回读 projectId 绑定后续制品。
4. 管家本人取绑定编号，负责人通过指定管家动作绑定。编号仅按页面流程使用，不存入 Git 或证据。
5. 管家为一个工种发出一次师傅邀请；师傅本人申请及取绑定编号，管家核对后批准。在批准前先验证师傅不能读取项目安排；批准后核对有效成员及工种。
6. 三方界面身份、云端成员与权限一致后关闭。出现未知结果立即停，先核对，不为了赶窗口重复点击。

候选服务端准备动作：identify、listMyProjects、requestBindingNumber、createProject、assignManager、createInvitation、applyInvitation、approveInvitation、getMembers、listInvitations、getScheduleContext、listSchedules、getSchedule、listScheduleRevisions（原 prepare 的子集，剔除 removeMember）。页面动作与服务端允许动作分别验收，隐藏按钮不能替代服务端限制。

### 窗口 E：正常安排与权限拒绝

在 P 通过后准备执行包，师傅先只获得一个明确工种。本轮建议最多新增 3 条安排，每条最多 7 个自然日；这是人工执行预算，**现有服务端并未实现该总数／天数限额**。逐步台账计数，达到上限即停，不能声称硬限额已生效。确切安排字段、次数及云端影响清单在执行包中固定。

| 用例 | 手机操作 | 通过依据 |
|---|---|---|
| E1 新增 | 管家给师傅安排一条短期施工 | 师傅和负责人读到同一安排；内容／日期／工种／责任人一致；云端安排、历史、审计、回执、目录与占用一致 |
| E2 调整 | 管家填写原因，按当前版本调整内容或日期 | 版本按契约增加，旧内容保留；师傅重新读取显示新版本，旧占用正确释放／新占用正确建立 |
| E3 规则 | 无原因、旧版本、相同工种相同实际施工日冲突；全为休息日；预计日期不一致未确认 | 按实际错误码明确拒绝，安排及对应成功历史不变；不把单纯错误弹窗当零写证据 |
| E4 身份权限 | 师傅、仅负责人分别尝试受限安排写入 | 云端拒绝，两者无新增／更改安排；不因按钮隐藏就算通过 |
| E5 查询 | 按本轮工种／日期／状态筛选并查看单条、历史 | 结果符合实际小样本及排序契约；未达到分页数量不声称平台分页已验证 |
| E6 取消 | 管家填原因取消，再由师傅读取 | 取消状态、版本、历史及占用一致；保留记录，不误报已完工或验收通过 |

若实际页面不能构造某项拒绝反例，由后续受审的固定测试方式执行；不让用户在控制台拼任意请求，不手工改微信上下文。无法安全达到的分支记未验证。

### 窗口 X：移出保护与退出后访问

单独准备 V07 受限驱动制品，目标为本轮唯一师傅，不沿用历史“师傅乙”提示作为绑定。现有普通菜单无移出入口；该制品未具备前不指导手机移出。

1. 保留一条有效安排，V07-A 移出应拒绝；核对成员仍有效、安排和任务目录不变。
2. 管家按确认的原因取消师傅全部有效安排，再核对无遗漏；日期已过不算任务清空。
3. V07-B 单次移出成功后核对 member.status=left。师傅重新发起项目列表／详情读取应被过滤或拒绝；管家仍可查原安排及历史。
4. 移出前后师傅仍在测试账号允许名单中，以证明是项目成员权限起效，不能用从允许名单删掉账号来代替验收。已展示在设备上的旧内容不等于可继续云端读取。
5. 关闭并留证，不删除用户、成员、安排、审计或缓存，不自动重新邀请。后续继续测试需要新的明确成员操作范围。

## 5. 未知结果、关闭和失败处置

- 首次尚未绑定的 identify 超时无持久防重保证：保留页面／时间，停止核对，不重发、不清缓存。
- 取号、指定管家、发邀请、申请、批准和移出没有服务端 requestId 幂等；结果不明直接停。已有追踪编号不等于可安全重发。
- 建项目及安排三写有回执机制；也要先保存原请求号／载荷并核对，再决定能否按同一请求恢复，禁止生成新号盲试。客户端持久锁不保证跨设备互斥；同一操作只用指定一台设备。
- 超时／非零退出不能推断零写。平台 SDK 可能重入事务；未保存逐请求证据时，不硬报 set／commit 次数。
- 每个窗口关闭服务端与客户端，分别核对制品文件／配置及手机关闭页。需要提前验证远端代码回读办法、关闭命令、权限和窗口外仍可使用的关闭包；仅关闭前端不算服务端关闭，等待期限也不算已部署关闭版。
- 关闭后不调用可能写 users 的 identify 来证明关闭；受控无业务副作用探针若需使用，也先纳入执行包。关闭回读失败记“关闭未确认”，保留现场、停止业务并处理关闭，不继续测试。
- 关闭代码不回滚数据库。保留已产生虚构记录以供核对，不能删除记录掩盖部分完成。
