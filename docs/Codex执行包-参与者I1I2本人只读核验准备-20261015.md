## 4. 单轮操作顺序（获该轮具体批准后才执行）

1. **只读预检**：确认 0号和本人在线，目标 AppID/环境/现有函数关闭状态；核对现有函数代码及回读能力。核对关闭来源 23 文件与可立即恢复的完整关闭制品。任何一项未知，停止开启。
2. **准备并锁定制品**：安全地产生本轮独立口令，只将摘要写入计划；在有效窗口按实际时钟运行 `node miniapp/scripts/package-participant-identity-check.cjs --plan <本轮计划绝对路径>`。只接受 `synthetic=false`、正确 `participantCode` 和固定目标。随后用 `--check <本轮候选绝对目录>` 与 `--check-close <同一候选目录> --close-source <已核验关闭来源绝对目录>` 独立核对；保存完整清单、文件大小与哈希。写后失败如实记 `written/partialWrites`，不称零写；不拿不完整产物上传。
3. **先保住关闭能力，再开服务端**：按已核实的同名函数部署方法，将候选 `server/` 精确映射到既有 `scheduleSandbox`；远端只读回查代码、配置、函数名与环境一致。远端回读未知或错位，立即用配对关闭包覆盖并核对，不能继续让手机发请求。
4. **本人只点一次**：仅给该轮本人打开核验页；0号现场或实时通话确认现实本人及其手机。加载/切前台不发请求。本人私下输入本轮口令；如需要后续绑定内部编号，由本人**主动勾选完整编号**后点一次。不要把口令、OPENID、原始平台日志放进截图。重复点、超时、网络异常或结果未知时停止，不自动重发、不清缓存。
5. **立即关闭**：无论 `ACTIVE/ABSENT/DISABLED/MISMATCH/UNKNOWN` 或调用失败，先以本轮已核验的 `close/` 字节关闭**服务端**，远端回读确认其拒绝动作；再核验手机端显示关闭页且零发送。只等窗口过期或只关手机页面均不算关闭。若服务端关闭未证实，结论写「关闭未确认」，优先处理关闭，不进入 I2 或 P。
6. **净化留证并归档**：记录本轮轮次、UTC、候选/关闭清单哈希、远端前后版本、本人确认来源、一次调用的净化结果、平台请求 ID（若提供）、实际读取尝试和实际套餐用量；原始口令/凭据/OPENID/完整内部编号不进入 Git。完整内部编号如后续确需使用，单独受控保存，并与轮次及时间绑定；手机截图只是辅助，不单独证明平台记录。

## 5. 状态判定与停止条件

| 返回 | 本轮结论 | 后续 |
| --- | --- | --- |
| `ok=true`、`identityConfirmed=true`、`ACTIVE`、`recordMatched=true` | 本人本轮读取到匹配的有效测试账号 | 关闭后另行核对来源记录；可为后续 P 提供身份线索，不自动授予管家/师傅或启动 P |
| 同样的有效核验但 `ABSENT` | 本人主键明确无记录 | 关闭；如需登记，另做只登记执行包与批准，不在 I 轮调用 `identify` |
| 同样的有效核验但 `DISABLED` | 读到停用记录 | 关闭并人工核对；不覆盖、不启用 |
| 同样的有效核验但 `MISMATCH` | 主键下记录与可信微信上下文不符 | 关闭、封存证据、查归属；不得改写旧记录 |
| `UNKNOWN`、`ok=false`、字段缺失、投影不可用、时钟/网络/权限/读取异常 | 状态或身份不可采信；`readAttempted` 仅表示是否走到 `get()`，不等于平台已完成读取 | 关闭、记录未知，不重发；另开只读核对须新轮次和批准 |

完整内部 `userId` 只可能在本人显式勾选、有效核验且状态为 `ACTIVE/ABSENT/DISABLED/MISMATCH` 时返回；默认只有 6 位尾号，`UNKNOWN` 和失败不能作为完整身份回执。**I1 成功也不能让 I2 跳过预检**；I2 要换口令、轮次和窗口，并重新确认 I1 已远端关闭。两轮均不创建用户/审计/项目，不配置工种，不启用入口，不清用户缓存，不处理 A/B/C。
