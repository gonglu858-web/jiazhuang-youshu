   这一点是**静态代码结论**，未运行故障场景，**不宣称该错误已发生**。

## 5. 「7 项均为实际故障注入」表述更正

上一轮我把 `WorkBuddyS3bE1复现-20261006` 的 7 项统称为「故障注入」，**表述过强**。逐项如实说明覆盖范围：

| 项 | 实际覆盖 | 是否完整故障注入 |
|---|---|---|
| e1-ETIMEDOUT-single-execution | 合成 spawn 返回 ETIMEDOUT，断言只启动 1 次且不 completed | 是（控制流级） |
| e1-EBUSY-no-in-process-fallback | 合成 spawn 返回 EBUSY，断言未触发任何 readFileSync（即未回退进程内） | 是（控制流级） |
| e1-nonzero-exit-not-completed | 合成 status=1 且结果文件存在，断言不 completed | 是（控制流级） |
| e1-zero-exit-no-result | 合成 status=0 但无结果文件，断言不 completed | 是（控制流级） |
| e1-partial-not-sealed | **仅在本地重写判定式**验证部分完成不等于 sealed，**并未真正调用 orchestrate** | **否 —— 覆盖有限** |
| e1-history-drift-voids | 合成 fs 使历史两次读取内容不同，断言作废结论 | 是（控制流级） |
| e1-orchestration-patch-guarded | **只验证当前正常源的匹配存在且唯一**，**未实际注入缺失/不唯一源** | **否 —— 覆盖有限** |

- 因此这 7 项**不构成完整的故障注入体系**，不为此重开业务返修。
