## 3. 定点返修项

### R1 [P1] 项目配置指向不存在的目录，仍被check接受

定位：`miniapp/scripts/package-participant-identity-check.cjs:391`。

生成文件位于`frontend/`与`server/`，根配置却逐字节复制旧项目的`miniprogramRoot=miniprogram/`、`cloudfunctionRoot=cloudfunctions/`。C02实测两个配置目录均不存在，`checkDir.ok=true`。因此当前包不能按声明作为完整项目直接导入；这不需要部署或真实SDK就能判断。

修复仅限本次装配：生成与实际目录一致的受审项目配置，并明确服务端函数目录布局/固定函数名的关系；不要修改原`miniapp/project.config.json`。独立断言配置根存在、唯一页面可解析、依赖可解析、固定函数目标正确，保留实际页面调用链。不能只证明文件被复制或VM可手动加载。

### R2 [P1] 核验成功后只有六位尾号，无法形成后续完整账号绑定

定位：`miniapp/scripts/lib/participant-identity-check.cjs:261`及模板Page第86行。

C03证明ACTIVE与ABSENT均`identityConfirmed=true`，但响应没有完整`userId`，只有六位尾号；Page也只保留尾号。任务目标是取得1/2号完整内部账号，后续允许名单、必要登记与P证据需要完整ID。尾号不可逆，也不能唯一定位账号，ABSENT时更无已落盘用户记录供反查。禁止通过扩大查询或猜历史尾号补救。

按原任务§4/§5补受控完整内部ID交付路径，保留轮次/时间/本人对应来源；默认页面可只显示尾号，但负责人必须能从本次有效结果可靠取得完整ID。完整userId不是OPENID，不要求公开交接全文展示。仍禁止返回OPENID/UNIONID/口令/凭据，失败结果不能成为可采信绑定，不能冒充已满足P登记证据。

### R3 [P1] 独立来源未钉定，源漂移可构建并自检通过

定位：打包器第200、210、391行。

源码读取只有文件类型判断，没有模板/核心/项目配置的独立内容基线；`SOURCE_DRIFT`虽声明却未用于哈希检查。唯一锚点只保护那几个配置替换点，不保护其余逻辑。C04给核心读取返回追加一行合成注释，build仍写38文件，check仍为true；磁盘原核心哈希保持不变。该反例仅证明漂移未拒绝，不声称发生恶意代码执行。

钉定本轮受审输入清单与完整字节摘要，构建前和check重建都按独立基线校验。源码改变应先受审更新基线，不能把当下源码自算值或manifest自报值当作已受审。核心、全部实际模板与装配配置均覆盖；锚点保留。漂移反例须写前拒绝且零产物，正常/复用/续建对照仍成立。

### R4 [P2] check早退触发未初始化变量错误，丢失原始拒绝原因

定位：打包器第518–550行早退、554行声明及616–620行`finish`。

`finish()`引用尚未执行声明的`manifestFiles/manifestCloseFiles`。C05分别让真实模式check启动时已过期、NaN、时钟抛错，以及修改计划字节使哈希不符，全部抛`ReferenceError: Cannot access 'manifestFiles' before initialization`，没有返回原本的净化原因。当前仍失败，未误放行，但不能可靠区分过期、时钟未知与制品损坏。

修复所有早退（含缺计划、非法计划、来源重建失败），保证库与CLI提供原定失败分类/问题列表，不被二次异常遮盖；check无写入。新增反例须直接到达这些出口，并保留合法成功对照。

### R5 [P2] 时间和轮次输入契约仍有缺口

定位：核心第142、173行；打包器第282、319行；Page第52行及client请求投影。

- C06：截止相等时核心仍确认并读取1次，真实模式build仍写38文件且check成功。任务要求“已到截止”拒绝，核心和工具须统一`now >= expires`。
- C07：合成计划0分钟、负1分钟均build/check成功；核心构造器却拒绝非正窗口，工具产生不可运行包。严格计划校验应在任何写入前要求`expires > starts`，不能仅查上限。
- C08：缺轮次、空字符串、数字轮次均被当成不需要比对，身份确认且读取1次；只有非空错误字符串会拒绝。实际Page/client没有发送绑定轮次。补计划→前端→client→服务端的明确轮次契约，缺/错/非法类型写前拒绝（此处指业务读取前）；不得通过猜测当前服务端轮次绕过。口令仍只证明持有，不证明现实本人。

新增对照覆盖未到、恰开始、有效、恰截止、超过、NaN/抛错、异步读后推进，以及合法轮次完整页面链。无须重开旧工具或修改历史证据。

### R6 [P2] 读取边界与错误净化未完全符合原任务

定位：核心第185–209、249、275–277行。

1. **异常净化**：C09的合成SDK错误使用`PIC_READ_FAILED`代码，原始message被原样返回；换成未列举`PIC_UNREVIEWED`仍对外输出。字符串前缀不证明错误是本模块生成。应使用可靠的内部错误标识与固定代码/文案映射，外部异常统一净化；不能透传原文。
2. **读取事实**：C10在collection构造阶段抛错，`get=0`但`readAttempted=true`。应只在实际调用get之前设置标记，get本身同步抛错/异步失败仍为true；构造失败或无get方法应false。
3. **状态分类**：C11分别缺`_id`、缺`openid`，都返回MISMATCH；原任务明确字段缺失为UNKNOWN。完整字段且明确不匹配才MISMATCH，保留ACTIVE/DISABLED/ABSENT合法分支。
4. **最小读取**：C12实际get1次、字段投影0次，直接取得整份用户文档；旧业务用户记录可能带bindingCodeHash等与本任务无关字段。依照任务只读取`_id/openid/status`，用已取得SDK支持的本地接口证明选择字段；不要求安装SDK或平台实调，也不能把返回时丢字段说成读取字段最小化。

以上四点各自加入直接断言和正常对照，保持至多一次本人文档get、零业务写、零全表查询。不得为留证增加云端写入。
