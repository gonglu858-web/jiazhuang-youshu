## 2. R1 [P1] 修正三个组合根因，并补真实事务传输夹具

### 已复现的原因

1. 测试 `syntheticCliSpawn`（约140–171行）：`respond()` 返回 `setImmediate()` 的 **Immediate句柄**；两处 `return respond(...)` 将它作为子进程返回，而不是返回构造的 EventEmitter `c`。实测返回值没有 `.on`，凭据宿主当然归为SPAWN_FAILED。与Node版本、凭据刷新无关。
2. worker约262–310行：先 `validatePlan(raw)` 取得含 `deadlineMs` 的内部计划，再把它传给 `initializePrimary`。P4内部会重新验证原始字段白名单，**deadlineMs是未登记字段**，必然PLAN_INVALID。`observePrimary`同样要求原始计划。保留rawPlan与normalizedPlan两个用途；不要改P4白名单接纳内部字段。
3. 测试 `syntheticWorkerSpawn`约460行：`out = await worker.run(... emit: v => out=v)`；run通过emit输出，返回undefined，await后的赋值又覆盖out。下一步 `Buffer.from(JSON.stringify(undefined))` 抛ERR_INVALID_ARG_TYPE。本轮以过期早退响应独立复现该覆盖。
4. `installSyntheticSdkTransport`只有 `send()` 且所有响应均为列表；没有事务所需 `request()`、事务ID、事务get的单对象形状、set/commit/rollback响应与持久化回读。修掉前三项后，这个夹具仍不能证明3读2写1提交。复用已验收适配测试里的固定SDK请求形状，不能把事务开始/提交统算成集合写。

### 最小修正与验收

- 只改本轮新worker和测试；参数由原始计划进入P4，内部计划只用于绑定target/audit等。
- CLI替身发事件后返回c；worker替身 `await run(...);`，通过emit收集输出，不从void返回赋值。
- 真实 SDK init/database/transaction/文档转换经合成传输完成一条完整成功链，并逐项断言：实际用户get发生、primary/audit各set一次、commit一次、回读两条匹配；异常路径明确断言到达哪个阶段。
- 恢复相关skip。D-1当前transportCalls=0、实际PLAN_INVALID，不能称“验证目标用户不存在”；D-4在SDK加载前退出，也不能称触发真实SDK。删除/纠正这两项过强表述，不删除历史记录。

## 3. R2 [P1] 额外STS没有收到同一快照，隔离目录未经确认

host约244行实际调用：

`readOnly.buildIsolatedEnv(baseEnv, d.profileDir, d.cwd)`

已验收签名是 `(baseEnv, snapshot, isolationDir)`。第二参数被错传成字符串profile；离线捕获最终环境中 **SECRETID/SESSIONTOKEN均undefined**。修为同一snapshot，不能靠mock响应忽略凭据后通过。

同时：

- 额外STS手写 `['api','sts','GetCallerIdentity']`，没有按任务复用固定 `buildStageArgs`；恢复固定STAGES对应参数、版本和相同校验器，不重复手写字段校验。
- `executeOnce`接受传入isolationDir但未调用既有创建/完整性检查。关联阶段须用本次新建、经`assertIsolationClean`核对的目录；不能允许cwd受项目认证或旧缓存影响。
- 生产路径仍应保持关闭至获准；不要把仅按字符串比较“不是authSessionDir”当认证隔离证明。离线注入和未来受审真实入口分清，不能让测试通过后凭随意路径绕过。

验收：凭据命令1次，三关联+额外STS共4次固定API；逐请求检查同批sessionToken及固定env/cwd/参数，污染目录零API。这里只验证本地传参，不声称平台选择身份已验证。

## 4. R3 [P1] worker不是可运行的子进程，且另写了一套不可靠收尾

- worker仅导出函数，没有`process.stdin`读取或main分派。host真实启动该文件只会加载后退出，没有执行run或输出结果；测试直接调用run不能覆盖此断点。
- `run()`直接调用 `d.now()`，未提供测试时钟时抛TypeError。缺失/NaN/Infinity的expiresAtMs被跳过校验；只检查入口一次，后续P4使用固定nowMs，不能发现执行过程中真实时效变化。
- host `runExecutionWorker`约509–572行重新实现计时器/输出监听，**未复用任务指定的spawnBounded**：不读取stderr、不做合并限额；close不检查code/signal；stdout直接JSON.parse后透传；错误/溢出路径计时器不一定清理；stdin异步失败被忽略。
- 离线已证实 **close(7,'SIGTERM')＋stdout ok:true 被接受成功**；未知extra字段原样返回。timeout虽输出errorCode=RESULT_UNKNOWN，却无resultUnknown，父层再降为普通WORKER_FAILED。
- `FIXED.isolationRoot`取自旧CLI观测器不存在的字段，worker cwd不能据此认定固定；需绑定实际已核对的隔离目录。

最小修正：实现有界私有stdin入口（严格固定载荷、无任意sdkRoot/脚本路径），默认本地检查入口与内部worker入口清楚分开；真实时钟默认Date.now、测试可注入，凭据和批准期限有限且在事务前/首写前/回读前后检查，不用审计固定时间替代当前时钟。只在新宿主包装既有adapter需要的时效检查，不改旧核心。

复用已有spawnBounded与严格父层投影；代码/信号/超时/合并溢出/输入失败优先于stdout。写worker已发出后不能排除提交的失败归结果未知，保留auditId与轮次；未知必须走只读核对或明确待核对。正常、非零、信号、晚到error、stderr超限、缺stdin、实际子进程入口至少有离线验证；不再重写生命周期库。

## 5. R4 [P1] 批准绑定与单次执行记录没有落实完整契约

host约162–226、365–366、458–478行：

- `approvalSource.controlled=true` 是可序列化自报标志，独立放在另一个对象并不自动成为受控来源。实测JSON复制后仍可通过。这不意味着同权限本机攻击者被纳入防御范围，而是操作稿“不能伪造”没有实现依据。
- 仅绑定P4 inputDigest的六字段；它本就**不覆盖期限、operatorRef及完整批准上下文**，不应改它承担另一个职责。实测延长期限、替换operatorRef、加allowed字段仍通过宿主批准检查。宿主甚至没有在取凭据前调用P4完整计划/批准校验。
- 文件指纹只比较source里两项CLI常量，未绑定新host/worker、P4/适配器及实际制品；`fileFingerprint`阶段仅push名称，没有读取实际文件做完整核对。预期主体摘要也未绑定到受控批准。
- persistRoundStarted是可选回调，未提供仍push“roundStarted”并启动worker；o.roundId可不同于plan.roundId；返回异步Promise未await。内存隔离前序后实测这两种绕过同时出现、worker启动1次。结果文件保存路径也未实现。

最小修正：先验证原始计划和批准；由未来受审入口在私有执行上下文中绑定不可变的完整计划/批准/预期主体/实际文件指纹，模块不能单凭普通JSON标志认定已批准。无须新签名平台；如采用本地闭包/非序列化对象能力，明确创建者是已受审管理入口，测试入口不可成为生产授权。真实批准本轮仍不生成。

P4摘要/审计算法保持不变；完整执行范围的对照属于宿主。started持久化必须存在、await成功且轮次完全匹配；记录包含确定性auditId/计划绑定。保存失败/重复轮次零写worker。结果新建保存、保存失败保留started并停止，禁止重试初始化。批准在异步耗时后也须复核，不能只在开头检查一次。

验收包括：未批准普通对象、完整计划字段/批准人/主体/宿主指纹被换、过期、started缺失/异常/异步失败、轮次不符、结果保存失败。零请求或零写的阶段边界须实测，不仅匹配正则。

## 6. R5 [P2；结果未知部分P1] 返回结果、回读和净化与实际契约不符

worker约91–159、302–358行，host487–504行：

- observePrimary会正常返回state=unconfirmed/inconsistent而非总是throw，当前observeFailed只看异常不足以表达回读失败。`PLAN_READY`不能作为初始化成功分类；分别记录本地计划、提交事实、回读state以及是否已授予。

验收：已有其他人必须sameAsTarget=false；正常32位摘要保留；未知大写码与extra敏感字段丢弃；commit未知→固定两条回读；提交成功但回读失败不丢提交事实；缺字段/不一致不报成功，不发生第二次写。
