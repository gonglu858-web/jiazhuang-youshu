## 3. 本轮发现的实际附加行为

**公共API命令不等于底层只发生一条API请求。** 本例原始入口在STS查询前两次调用 `tcb.CheckTcbService`。它们也使用同一组合成凭据；本地替身返回Initialized=true后，入口才继续STS。没有调用InitTcb或任何初始化/资源创建操作。

初次探查仅允许STS模拟响应，因额外CheckTcbService未获模拟响应而停止；该次已看到A/B签名身份切换，但未把它记为完整目标查询通过。后续仅扩充**离线响应替身**接受已观察到的CheckTcbService，未放通任何真实网络。

初次还拦截到 `otheve.beacon.qq.com/analytics/v2_upload` 遥测尝试。按固定bundle中实际存在的 `TCB_DISABLE_REPORT` 分支，在最终子进程明确设置 `TCB_DISABLE_REPORT=1` 后，最终三例均未再观察到遥测HTTP调用。未改官方安装文件。

每例另有1次外部子进程调用被拦截；本轮未识别其用途，未执行。它没有阻止A/B主命令完成，但结论限定在这一受控宿主条件，不能写成“未经拦截的CLI没有外部子进程或附带行为”。

## 4. 证明边界

- 证明的是无项目/全局既有凭据污染的隔离条件下，环境注入的三字段被选用；没有证明在污染目录中的全部优先级，也没有允许省略隔离检查。
- HTTP/HTTPS请求替换为本地Readable/Writable；net/tls/dns/dgram/http2/global.fetch及外部子进程设置阻断。没有启动本地网络服务器，替身没有调用底层原始网络函数。**这是Node运行时拦截，不是操作系统防火墙或任意代码的安全沙箱。**
- 签名用钥证据观察TC3初始HMAC输入与合成secretKey相符，不等于腾讯云验证签名成功。平台响应全部合成，不证明IAM、账号/环境真实归属、服务开通状态或费用。
- 主测试命令仅STS。不能把该结果扩张为DescribeEnvs/DescribeEnvInfo/数据库SDK的真实同批链已通过。
- 空隔离目录可由CLI生成自己的默认配置；不等于完全零本地文件操作。全部写入限定在新建测试目录，原登录资料不被修改。
- 本地工具仍显示 `credentialFetchHostImplemented=false` / `publicEntryIdentityProven=false`，没有修改这些产品字段。审查证据已通过这一离线前置，不表示生产宿主已接上；未来代码应引用这份证据并保留版本/哈希约束。
