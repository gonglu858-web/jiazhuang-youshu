## 2. 唯一阻断项：S1 缺文件清单不再填充（P2）

位置：`miniapp/scripts/package-sandbox.cjs:773`，其下完整性检查位于第 796 行。

当前 `safeReadPackageFile` 返回 `exists:false` 时直接 `continue`，没有把路径加入 `facts.missing`。随后“有 manifest 时额外核对其声明的完整性”循环永远收不到缺文件。

独立复现只使用本次新建的隔离样本，未删除交付包文件：

1. 用当前工具生成完整 /2 样本；仅删除样本的 `package/index.js`，保留 manifest。
2. `checkOnly:true` 正确拒绝“产物缺失”；生成模式却返回 `mode:'created'`，重新创建 index.js。
3. 同样缺文件的样本再将 manifest 的 purpose 改动：生成先创建 index.js，最后才报“manifest 已存在且内容不同”；原 manifest 保持，但已新增一个文件。

第三种是可预知失败后发生写入，不是磁盘中途故障。上一轮第 2 节已要求“有 manifest 才额外核对其声明的完整性”，本轮重写安全读点时丢了该分支。**这不是施工安排业务失败，也不是新增架构需求。** 当前完整 /2 交付包仍通过检查，未发现其字节损坏。

最小修法：缺文件时记录 `facts.missing`；有 manifest 就在任何写入前拒绝；无 manifest 的合法半成品仍可补齐。保留已有内容冲突与来源校验，勿扩成签名/迁移系统。

一次补齐下列回归即可：

- 有 manifest、缺 index.js：生成与检查均拒绝，index.js 仍不存在，manifest 逐字节不变。
- 上例附加 manifest 文本冲突：同样预检拒绝且零写。
- 无 manifest、仅有内容正确的 gate.js：仍可生成，既有 gate.js 不改动。

## 3. 非阻断测试盲点：S2.2 的 junction 夹具

`miniapp/tests/sandbox-package.test.cjs:518` 把原 vendor 移到 **package 内**的 vendor-real，又允许错误正则匹配“白名单外文件”。因此即使删除链接防线，也可能仅因 vendor-real 是额外文件而通过该测试。它不能单独证明 vendor junction 检查有效。

本次真实 junction 创建为 EPERM，该例实际跳过；**不据此否定 S2 实现**，因为独立的 lstat-only 合成检查已在生成/检查两条路径确认链接拒绝。修测试时可把 vendor 备份放到该样本输出目录之外、专用临时根之内，错误断言只接受链接拒绝。权限不足仍明确跳过，不为此安装或提权。

现有 S2.3 标题同时声称“拒绝链接与非普通文件”，实际该例直接测试的是普通文件/字节差异/不存在/目录，链接覆盖在 S2.1 及本次独立证据。可顺手收准确标题，无需修改实现。
