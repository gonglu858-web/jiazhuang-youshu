### 2.2 真实包的离线接口核对

执行上述离线脚本：**8 项通过，networkAttempts=0**。加载已存在 node-sdk，替换进程内请求传输为合成响应，并拦截网络。没有调用任何云端初始化或真实 SDK 网络请求。

1. 实际入口是 database `dist/commonjs/index.js` 引用的 `./transaction/index`，不是旁边旧的 `transaction.js`。不要按未加载的残留实现写适配层。
2. `db.startTransaction()` → `tx.collection(name).doc(id).get()/set()` → `tx.commit()/rollback()`。
3. 合成成功空列表经真实 SDK 转换后，事务读取为 `{data:null}`，非事务读取为 `{data:[]}`。这是转换实测，**不是平台缺记录实测**。
4. `doc(id).set(fields)` 使用裸字段对象；不能传 `{data: fields}`。`_id` 必须与独立 id 参数核对一致，再从新复制的写对象去掉，不能改动核心传来的对象。
5. 真实 SDK 的 `set({_id:...})` 在发到传输层前拒绝。本地薄适配层负责转换，不能为此改 P4 业务数据结构。
6. 文档方法可能返回含 `code` 的错误对象；不能用 `result.data || null` 把拒绝或异常变成“记录不存在”。传输异常与 SDK 错误必须保留失败语义并净化输出。
7. commit 的含 code 错误会抛出，rollback 调用 abortTransaction；未知提交结果不能描述为已回滚，不能自动再次初始化。
8. 当前手动事务路径可匹配核心，不改成自动重试 `runTransaction`。底层真实传输的重试与认证行为仍未核实。

本轮仅检查新的接口缺口，没有重跑未变化的全量业务测试。源文件读取已定位 set/get 和实际事务路径；合成传输不证明 IAM、平台事务或费用。
