## 1. 本轮固定决定

1. **V06/V07 运行载体：现有小程序 schedule-sandbox 测试页的专用卡片。** 在真实小程序运行时通过 `wx.cloud.callFunction` 调固定 `scheduleSandbox`，由服务端 `getWXContext` 验真。Node 仅运行离线测试，不扮演真实微信账号。

3. **P4 载体：管理端本地一次性事务工具，先完成离线事务核心。** 不新增云函数、不向小程序暴露授权按钮或新业务路由。当前没有已核实可用的真实管理 SDK 事务适配器；本轮不猜接口、不安装依赖。CLI 只做本地计划校验；真实执行分支必须拒绝并明确未就绪。事务核心通过注入模拟适配器完成原子性测试，为后续核实真实 SDK 后接入保留明确接口。
4. 新测试配置默认关闭、动态值空、嵌套冻结。原前后端配置保持原值，不生成 prepare/execute 启用包。
5. A/B/C、原 memberAccess/connectionCheck、vendor、env-gate、已验收打包器及旧凭据不改。三组测试只作用于未来获批的独立副本唯一项目。

## 4. 双向互斥与未知结果

协调器不得依赖 Page 的 busy 布尔值。用 **当前环境+业务 roundId** 的持久批次键并包含完整 actorUserId，另有同运行时同步占用，避免同一 tick 两个入口同时过预检；换账号不能隐藏同轮次未完成批次。失败关闭，不清缓存、不重置轮次。

必须覆盖两种方向：

1. 普通 `callSandbox`、`resumePending`、独立身份刷新已在途或已有旧/新 envelope → 驱动拒绝。占用必须在首次 await 之前建立，不能只等普通请求写 envelope 后再检查。
2. 驱动正在核验/发送/等待结果或已停止 → 普通客户端网络入口拒绝；普通页面 onShow 自动身份刷新也不能旁路发请求。采用内部所有权/私有封装，不能给普通 API 增加 `ignoreLock:true` 之类开关。

正常没有驱动批次时旧流程不变；旧恢复路径只新增互斥限制，不改变谁能恢复、恢复什么内容。协调器不得删除或改写原普通 envelope，也不能把 `resolvePendingAfterExternalCheck` 变成解锁按钮。

驱动用例状态：`ready → preflight → armed → inFlight → candidate / stopped → reviewed`。

- 在任何业务请求前持久化并回读：计划摘要、身份/项目/轮次、testCaseId、完整非敏感快照、两个请求号、一次执行标记。持久化失败零业务发送。
- 身份/成员预检返回后、armed 前再核对当前配置与截止时间；预检期间过期或计划改变不发业务请求。原 consumed 记录不因配置关闭或改动而清除，开关切换不作解锁机制。
- armed 后用例即已占用：重进页面、响应丢失、进程退出均不自动重发；可能尚未发出也宁可停机。禁止清标记或换号重新运行同一用例。
- 只在单一同步段发起两笔固定业务请求，不先 await 第一笔再发第二笔。独立保存两边响应；一边同步抛错/网络拒绝/超时，已经发出的不能取消，记录事实，不自动补发。SDK 自动重试不是驱动可控制的 exactly-once 网络保证。
- 超时采用可注入时钟的有限等待，建议 UI 30 秒；与云函数当前 3 秒配置不是同一个概念。本轮不改云函数超时。超时后的晚响应可追加证据，但不能自动把 stopped 改为通过或重开写入。
- 所有未知/异常组合进入 stopped，不重试、不启动下一例。只允许查看本地报告；云端后置核对走管理端，不强求被锁住的普通客户端查询。
- 精确预期结果得到后标 candidate，仍不能自动串联下一例。可提供“已完成本例管理端核对”接续按钮，必须填写核对记录 ID，只针对 candidate；它仅记录**人工声明**，不能把 verifiedByCloudBaseline 改 true，不能处理 stopped/unknown，不能解开普通 envelope。保留 consumed 用例历史后允许下一固定用例或必要普通筹备动作。
- 这只是同一设备/运行时的操作互斥，不是跨设备锁。未来云端执行时指定管家只用一台设备、其他账号仅按步骤参与；真实权限/一致性仍靠服务端事务。

## 8. 本轮验收用例（按行为验收，不要求固定总数）

### 驱动与页面

- 禁用/缺项/release/未知版本/错环境/AppID/过期/错项目/受保护 A/B/C：零请求；错误身份/非管家：零测试写请求。
- 普通 envelope（含旧格式、损坏、writeLocked）、普通在途、存储读写/回读失败、账号变化：阻止驱动；驱动占用反向阻止 call/resume/自动身份刷新，不改原 envelope。
- 两个入口同 tick、重复点击、两驱动实例、跨页重建：同用例只一对；reload 后 armed/inFlight 停止不补发；配置换号/换计划不能重置 consumed 历史。
- V06 两请求在第一个完成前都已调用；模拟双向完成顺序；a 完全相同请求、b 不同号且同占用、c 同版本且不同内容；只接受各自精确响应组合。
