## 2. R1 [P1] 固定本人、受审来源和字符串组包没有真正约束

位置：`miniapp/scripts/package-sandbox-registration.cjs:213`（名单）、`:252`（源读取）、`:290`/`:406`（源码生成）、`:369`（变换）。

### 已确认的问题

1. 名单只拒绝空值、格式错误和重复元素。两个不同完整 userId 可以通过；synthetic=false 时单个其他 userId 也通过。`CANDIDATE_USER_ID` 未参与验证。因此“仅一个本人”目前是样本属性，不是工具契约。
2. `readReviewedSources` 对当前磁盘内容现算哈希，`computeArtifacts` 又把同一条目的现算哈希传给 `applyTransform`；不存在对独立受审基线的比较。`sourceVersion` 只检查非空/非占位，`unverified-source-label` 也可生成制品。内存模拟 index 锚点之外新增注释、重新计算当前哈希后，真实变换函数仍接受；磁盘源未改。
3. roundId/sourceVersion 等被直接拼入单引号 JavaScript。合成 roundId `x' + (globalThis.__reviewMarker = 1) + '` 通过计划校验；加载生成前端覆盖文件时，隔离 VM 中 marker 被执行为 1。不是简单显示字符的问题，也不需要改变既有业务源码。

### 最小返修和验收

- 真实候选必须恰好一个用户且精确等于本任务固定候选；合成测试如需替代用户，只走明确标记的测试契约，同样保持单用户。不能让 self-reported synthetic 产生未标明的真实制品或复用为真实结果。
- 复用旧工具的基线能力或固化本任务已验收 8 文件哈希，实际比较；来源版本与该基线绑定，不信当前文件自算或任意标签。其余 6 文件也要检查来源漂移。
- 动态值安全序列化为 JavaScript 数据，或采用与实际轮次要求一致的严格格式；不能把计划文字作为表达式执行。不需要新签名体系。
- 正向保留；新增多用户/换人、锚点外漂移、未变换文件漂移、引号/换行等用例。所有前置失败在任何产物写入前结束。

## 3. R2 [P1] 无 manifest 的既有内容未预检

位置：同文件 `:780–826`。

### 实测

- 新夹具目录只有内容冲突的 `package/gate.js`，没有 manifest：build 返回成功，原 gate 被覆盖且 index 被创建。
- 新夹具 `package/vendor` 是真实 Windows junction：旧工具逐文件的 `resolveInside` 最终拦住它，**没有写入联接目标**；但前面的 index 等文件已经写入，返回写盘失败/半成品。这是生成前已经存在、可预检的目录异常，不能归为不可预见的 I/O 故障以满足“预检零写”。

### 最小返修和验收

生成之前完整枚举目标根及子目录，先拒绝任何链接/额外项/非普通文件/既有冲突，再进行写入。合法无 manifest 半成品可以续建，但已有文件必须与期望逐字节一致并复用；不得覆盖冲突。已存在 manifest 时继续拒绝缺失文件，不能补写后才发现冲突。保留真实写入期 I/O 失败的半成品，不递归清理。

分别断言原内容/文件数/manifest 字节不变、新文件零创建，以及 junction 目标未被写入。无需修改旧打包器；本轮是在新工具中正确调用其现有安全能力。

## 4. R3 [P1] 检查仍信任前端自报哈希，manifest/复用比较不完整

位置：同文件 `:652–733`、`:786–793`。

### 实测

- 在新夹具前端覆盖文件末尾追加错误 functionName 的导出，并同步更新 manifest 的前端哈希/字节数，`checkRegistration.ok=true`。服务端重算正确不能代替前端重算。
- 将 manifest 的 deploymentAuthorized/cloudExecuted 改为 true、effectiveActions 改为 createProject，删除 reviewedSource/closedPackage 信息、清空 differences、置 bytes=-1、追加伪文件记录，check 仍返回 true。它们本就不是授权句柄；问题是校验成功不能证明清单记载真实一致。
- 制品顶层添加 unexpected.txt，check 返回 true；当前只枚举 package 内。
- 同一 outId 改 windowStartsAt，并把 synthetic=true 改为 false，build 仍 reused=true，返回旧合成计划。比较漏字段，不能称“完整同计划复用”。

### 最小返修和验收

从可信来源和完整已校验计划重算服务端及两份前端内容；manifest 需检查文件集合、重复/多余/缺失、字节数/哈希、来源、变换、动作/用户、关闭绑定和固定状态。顶层也按明确白名单检查。复用比较完整语义计划（含 synthetic、开始记录和截止时间），不能把旧合成制品作为真实请求的复用结果。

每类反例调用实际 build/check，不用只检查字符串或手写比较式代替。清单不是安全授权，勿因此新增授权系统或声称清单通过即可部署。

## 5. R4 [P1] 配套关闭文件和前端来源记录未交付

位置：同文件 `:406–473`、`:481–540`、`:772–774`；操作稿第 4、5 节。

### 已确认的问题

- 只生成 `frontend/config/schedule-sandbox-proof.js`（enabled=true），没有同轮次 enabled=false 的关闭覆盖文件，manifest 也未绑定第二份文件。
- 没有列出实际 Page/client/协调器及所依赖前端配置的来源哈希；覆盖文件中的任意 sourceVersion 字符串不等于这些哈希。操作稿“已记录当前前端源码版本与哈希”不成立。
- `describeClosedPackage` 只是读取 8 文件并算哈希，不验证旧 manifest /2、已验收字节、配置关闭、目录安全及完整性；build 不要求 present=true，check 也不重验关闭包。通过局部 fs.existsSync 替身只模拟旧关闭文件不可见，真实 build 仍成功且 manifest.closedPackage.present=false；历史关闭包未改。

### 最小返修和验收

落实原任务 L2：两份对应目标/轮次的前端覆盖文件；实际依赖版本/哈希；生成与检查均绑定并校验受审 closed-20261005-r2fix。可以复用旧打包器对**旧关闭包**的检查，但不能拿它替代登记包的独立校验。旧关闭包缺失/坏 manifest/字节漂移/链接/非关闭状态须在生成前停止。

关闭前端加载真实 client 后零请求；关闭服务端 main 继续拒绝且数据库访问零。此阶段仍只是本地制品，不组装完整预览包、不上传、不启用、不为核对关闭调用真实 identify。
