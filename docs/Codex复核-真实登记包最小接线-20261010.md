## 2. R1（P1）：复核重复使用启动时刻，过程中到期仍成功

位置：assemble-sandbox-registration.cjs:1098–1107、1139、1167–1184、1218。
assertCandidateNotExpired 本身比较数值是正确的，但其调用方只在开始取得一次 now/nowMs，之后每个阶段都重复传同一个值；CLI build 也提前传入 Date.now() 的数值。增加比较次数不等于重新读取当前时间。

独立样本不传 nowMs：只在本进程替换 Date.now 为受控历史时钟，在实际来源文件读取或输出文件写入完成的事件处推进到截止时刻。实际生产函数被调用，未修改业务源、未用 sleep、未替换过期判断：
- R1-prewrite-deadline：来源读取中到期，之后仍写49文件并 ok=true。
- R1-postwrite-deadline：首个输出文件写完到期，最终仍 ok=true，未标 expiredAfterWrite。
- R1-check-deadline：检查来源期间到期，仍 ok=true。
- R1-reuse-deadline：复用检查期间到期，仍 reused=true / ok=true。
- R1-resume-deadline：续建检查期间到期，仍补文件并 ok=true。
五例均事件命中、最终到期、Date.now 调用仅1次。

**最小修正**：让真实候选在每个要求的边界取得新时钟快照，每次快照先验证有限数值；同一阶段向原生成器传相同数值。保留模块级离线时钟注入但不开放 CLI 时钟参数；CLI 不得提前固定数值使后续边界永远使用旧时间。合成复验继续兼容。写后到期须保留产物并报告已写和失效；任何已写之后的时钟异常也不能被外层统一返回 wroteFiles=false。

测试必须真实推进时钟：
- 当前 C4（测试1341行起）第一分支从调用前就过期，第二分支始终有效，不覆盖题名“预检后/写后过期”。
- 新增上述5路径、边界相等拒绝和未过期对照，必要时记录边界事件；不得以调用次数猜阶段或仅用恒定 nowMs 自证。
- 说明和顶部“预检后过期零写／写后保留”的已通过声明应待真实断言通过后再恢复。交付证据时效组11项并未证明运行中跨期。

## 3. R2（P2）：同为 /1 却改变必需字段，真正旧包不兼容

位置：assemble-sandbox-registration.cjs:851–852、1041–1046。
buildManifest 无条件给两种模式加入 artifactKind/verificationKind，validateManifest 又无条件要求 artifactKind。旧受审 /1 清单没有这两个键。

独立样本从 `git show b274da4:miniapp/scripts/assemble-sandbox-registration.cjs` 加载真实旧模块（保持原模块解析位置），用它在新忽略夹具目录生成 /1 包，并先用旧模块 check 成功。未手工拼一个“旧清单”：
- 新版 check 返回 ASM_ARTIFACT_KIND_CONFLICT，原因 artifactKind 为 undefined。
- 新版 build 同输入复用返回 ASM_ARTIFACT_CONFLICT。
- 原清单字节保留，未覆盖；但不能称“历史 /1 正常复用”。

**最小修正**：恢复受审合成 /1 的原完整清单契约与确定性字节，不要求新增字段；候选 /2 的字段与严格检查独立处理。不能靠修改旧产物、补字段、仅容忍缺字段却继续完整比较新版清单，或弱化全部清单校验来“兼容”。

当前 C6（测试1510行起）所谓历史包实际由当前 asm.buildAssembly 新建，并断言 artifactKind=synthetic，因此只证明新版自洽。应改用真实旧版本模块或可追溯、固定字节的已验收旧夹具，证明旧包 check、完整复用、清单零重写及默认/显式synthetic均成立；/2→/1冒充仍拒绝。
