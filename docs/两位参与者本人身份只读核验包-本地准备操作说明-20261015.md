## 2. 核心设计（对应任务 §3/§4）

- **固定目标**：AppID `wxfb4db1615ac15531`、环境 `cloud1-d8gcq5ag39d847723`、函数
  `scheduleSandbox`、集合 `schtest_v1_users`；计划里的这四项必须与固定值逐字一致。
- **可信输入**：APPID/OPENID 只来自 `cloud.getWXContext()`，环境来自受审运行环境；
  `userId = u_ + sha256(APPID + ':' + OPENID)[0:40]`（与未改业务算法逐字一致）。
  请求里的 `openid/appId/userId/role/collection/docId` 一律按未知字段拒绝。
- **单一动作**：`inspectSelf`。identify/createProject/requestBindingNumber/… 等业务动作
  全部 `PIC_ACTION_REJECTED`，且拒绝发生在**任何数据库访问之前**。
- **只读一次**：门槛全过后才执行一次
  `collection('schtest_v1_users').doc(userId).field({_id,openid,status}).get()`——**只投影这三个字段**；
  不 list/where、不跑事务、不写审计、不创建用户、不授予角色、不取号。
- **错误净化**：只有本模块产生的错误（内部 Symbol 标记）才输出白名单代码与固定文案；外部异常
  （含伪造 `PIC_` 前缀或第三方 code）一律净化，不透传原始 message。
- **最小读取硬约束（S2）**：字段筛选能力缺失（句柄无 `field` 方法、`field` 调用抛错、`field`
  返回无 `get` 的对象）时**保守返回 UNKNOWN**（`PIC_FIELD_PROJECTION_UNAVAILABLE`）、**不发 get**、
  `readAttempted=false`、完整 ID 为空——**绝不回退读取整份用户记录**。
- **口令**：只限制持有者，**不证明持有者是现实中的1号/2号**；服务端只存 sha256 摘要，
  明文口令不进入制品、日志与证据。设计支持 ≥128 位熵（实际口令本轮不生成）。
  **零持久写 ⇒ 不能承诺一次性口令、跨实例计数或全局限流。**
- **状态闭集**：`ACTIVE / ABSENT / DISABLED / MISMATCH / UNKNOWN`。明确无记录才是 ABSENT；
  读失败、权限错误、超时、未知 status、多条、**字段缺失**一律 UNKNOWN；字段齐备但与当前上下文
  不一致才是 MISMATCH。`readAttempted` 只在**实际调用 get()** 前置真（集合构造失败为 false）。
- **读后守卫**：读取完成后与成功返回前重读当下时钟；到期/NaN/抛错一律不可确认。
- **净化输出**：固定 schema + 核验轮次 + 服务端时间 + `userId` 尾号；不回传 OPENID、
  UNIONID、口令、凭据或原始 SDK 异常。
- **受控完整 ID 交付（R2+S1）**：默认响应只给 6 位尾号；**本次有效核验结果**（页面显式勾选后）
  可携带完整内部 `userId`（`u_` + 40 hex），与 `checkRoundId` + `serverTimeIso` 一起构成后续执行包的
  绑定事实。完整 userId 是**标识不是密码**，不是 OPENID/UNIONID，也**不构成 P 登记证据**；
  失败结果一律不交付完整 ID。
  展示时点（S1 收尾）：取消勾选事件当下即清空 result.userId 与 fullUserIdAvailable（尾号保留、零新请求）；
  重新勾选不恢复旧编号，只有新一次有效核验返回后才随新结果展示。**取消勾选即撤回请求**：页面按复选框选中值是否含 `full` 判定
  （不对数组直接转布尔），取消后不请求、不显示，重新勾选才恢复；在途期间复选框禁用。
- **轮次绑定（R5）**：`checkRoundId` 由计划同时写入**服务端配置与前端配置**，页面→client→服务端
  逐层原样带回；缺失/空值/非字符串/与本窗口不符一律在数据库访问前拒绝。

## 3. 工具用法（只做本地准备）

```bash
# 生成候选（window 由 participantCode 与 checkRoundId 决定；--out 可指定输出目录）
node miniapp/scripts/package-participant-identity-check.cjs --plan <计划绝对路径> [--out <输出目录>]

# 校验既有候选（从独立受审来源 + 目录内严格计划重建，逐字节比对）
node miniapp/scripts/package-participant-identity-check.cjs --check <候选目录绝对路径>

# 独立校验配对关闭包（不读 manifest/计划/时钟，不受开启候选损坏或窗口过期影响）
node miniapp/scripts/package-participant-identity-check.cjs --check-close <候选目录绝对路径> --close-source <已受审关闭包目录>

# 提前准备未来窗口候选（2026-10-17 新增；真实模式 now<starts 允许，now>=expires/NaN/时钟异常仍拒绝）
node miniapp/scripts/package-participant-identity-check.cjs --prepare <计划绝对路径> [--out <输出目录>]

# 核对已准备候选（允许未来窗口；成功也 executionReady=false，不能替代 --check 的执行前核对）
node miniapp/scripts/package-participant-identity-check.cjs --check-prepared <已准备候选目录绝对路径>
```

- 输出目录固定在 `artifacts/schedule-sandbox/business-test/` 下且必须以
  `participant-identity-` 为前缀；schema 为 `participant-identity-check-candidate/1`，
  不冒充也不复用 P/E/X 输出目录（已 gitignore）。
- **关闭窗口**：建议 15 分钟，工具上限 30 分钟；真实候选逐边界重读当下时钟，
  不接受调用者用历史 nowMs 跳过到期；合成模式清楚标记且不被真实模式认领。
- **关闭包来源**：必须是**已受审**的本地业务关闭包目录，且先经**未改**
  `package-business-test.checkCloseDir` 独立校验通过后才复制 `close/` 内容；
  复制前钉定完整清单与字节，拒绝链接、漂移、额外文件与冲突。旧生成器零改动。
  - **写入纪律**：全量预检（目录占位/多余目录/额外文件/符号链接）后零写拒绝；排他新建不覆盖；
  合法复用/续建保留；部分写与竞态事实如实记录（`written` / `wroteFiles` /
  `partialWrites:[{rel,bytesOnDisk}]` / `sideEffect`）。
- **受审来源基线（R3）**：打包器内置 13 个受审来源（核心模块 + 全部模板 + 项目配置模板）的
  完整 SHA-256 基线；**build 与 check 都按该基线校验**，漂移即 `PIC_SOURCE_DRIFT` 且**写前零产物拒绝**。
  基线不是「当下源码自算值」也不是 manifest 自报值；源码变更须先受审更新基线。
- **装配布局校验（R1）**：装配后立即校验 `project.config.json` 的两个根目录真实存在、`app.json`
  只声明唯一页面且四件套齐备、页面→client→config 依赖闭包可解析、前后端固定函数/环境目标一致。
- **时间契约（R5）**：核心与工具统一 `now >= expires` 即拒绝；计划要求 `expires > starts`（0 或负
  窗口写前即拒绝）。
- **check 早退（R4）**：`finish()` 依赖的量在函数入口初始化，缺计划/计划哈希不符/非法计划/来源重建失败/
  过期/NaN/时钟异常等**每条早退都返回原定分类的 problems**，不再被二次异常遮盖。
