# 管理员稳定身份与执行会话绑定：官方语义核对与最小方案

## 1. 结论与状态

依据用户“核实这些身份字段的官方含义，再确定如何可靠绑定执行身份”，本轮访问腾讯云公开文档，并静态核对当前代码及既有脱敏证据。基线 6335ff1。没有运行真实 secrets、STS、数据库或初始化；没有签发批准，没有改实现或重跑未变代码测试。

结论：当前 CAMRole 的 UserId 包含角色会话名称。把包含它的完整四元组当作跨凭据批次固定预期，会把会话变化也视为主体变化。应分开绑定“事先批准的云角色及凭据申请账号”和“当次执行会话”。这属于拟采用的新接线契约，尚未实现、验收或放行真实执行。

不能从这一官方语义倒推此前失败一定只有会话变化；旧证据不足以证明旧、新角色 ID 与 PrincipalId 完整相同。不得直接把最新四元组摘要替换成允许值，也不得只核对主账号或尾号。

## 2. 官方字段含义

核对日期：2026-10-12；以下两页显示更新于 2025-09-12。

| 字段 | 官方语义的简述 | 本项目用途 |
|---|---|---|
| Type | 云调用者的身份类别；官方角色示例为 CAMRole | 只接受本轮受审类别，其他类型停止 |
| AccountId | 调用者所属主账号 UIN | 绑定完整值的摘要；不能独自代表具体执行主体 |
| UserId | 角色类型时由 roleId 与 roleSessionName 两部分组成，以冒号分隔 | 解析角色 ID；完整值用于本次会话连续性核对 |
| PrincipalId | 对角色调用者，表示申请该角色凭据的账号 UIN | 独立绑定；不能当角色 ID，也不能直接当微信本人身份 |
| Arn | 云调用者的资源标识；角色示例包含主账号和角色 ID | 核对内部一致性；不能凭字符串名字推定权限 |
| RequestId | 单次 API 请求的追踪标识 | 诊断留证，不作身份或权限依据 |

来源：[STS GetCallerIdentity 输出参数及角色示例](https://cloud.tencent.com/document/product/1312/66098)。

RoleSessionName 是申请角色临时凭据时指定的会话名，不是永久人员编号。官方限定长度 2–128，并给出字符规则。其变化具有契约上的可能性；文档没有承诺本项目 CLI 每次登录或刷新必然更名。[STS AssumeRole 输入参数](https://cloud.tencent.com/document/product/1312/48197)。

上述是腾讯云管理侧身份。小程序用户的微信 OPENID 和本项目派生 userId 属于另一条身份链；本次已经登记的目标尾号 2d3aa4 不因 STS UserId 变化而需要重新登记。

## 4. 拟定绑定契约

### 4.1 事先批准的稳定主体

定义新版本 cloud-role-binding/1，严格解析 CAMRole。稳定主体摘要输入采用固定顺序、带版本标识的 JSON 数组：

`["cloud-role-binding/1", Type, AccountId, PrincipalId, RoleId, Arn]`

这里“稳定”指不把会话名称纳入跨批次批准；不是官方对账号、角色或权限永不变化的保证。角色被替换、申请账号变化、ARN 改变，都必须重新核对并重新批准。

- 所有原始身份字段必须是非空字符串，不 trim、不转数字、不改大小写、不按尾号比较。
- 本地初版只接受文档角色示例对应的 ARN 形状 `qcs::sts:<AccountId>:assumed-role/<RoleId>`；从 UserId 解析的 RoleId 必须与 ARN 对应部分逐字相等，主账号也须逐字相等。此为本工具收窄契约，不声称官方只存在这一种 ARN。
- RoleId 和 UIN 使用十进制字符串严格校验并保留原字节，不用 JS Number（角色 ID 可能超过安全整数范围）。不把前导零数值化后当作相同。
- UserId 只接受一个冒号、合法角色 ID 和合法非空会话名。会话名按 AssumeRole 的字符规则及长度校验；文档文字与正则对加号存在表达差异，本地选择明确白名单并用测试固定，不能任意字符串放行。候选采用 `[A-Za-z0-9_+=,.@-]{2,128}`，这是本地接收规则。
- 未识别形状即停止，不从截断摘要、旧尾号、昵称或运行时当前响应补齐预期。

预计值须来自单独受审的只读准备记录：核对完整 RoleId、PrincipalId、AccountId 与 ARN 的一致性及其来源，再由管理者确认该云角色及申请账号是本次允许使用的执行身份。控制台 CAM 角色详情可用于独立核对角色及资源描述；如果无法确认 PrincipalId 对应谁或哪一受信服务，保持未批准，不能把它自动认定为用户本人。

本轮没有取得此基线。现有整体哈希无法反推出 RoleId；不能生成生产 expectedStableIdentityDigest。

### 4.2 当次执行的会话连续性

取得一份临时凭据后，先核对事先批准的稳定主体，匹配后才建立本次内存见证：

`SHA-256(JSON(["cloud-role-session/1", Type, AccountId, UserId, PrincipalId, Arn]))`

启动写 worker 前再次固定 STS 查询：稳定主体仍须匹配批准，完整会话摘要须与本次见证相同。同一轮会话变化也停止；不得自动取第二批凭据或刷新后继续。

本次见证只用于同轮比较，不是新的允许名单，不替代签发前的预期主体。相同 STS 会话也不证明密钥字节相同：凭据获取必须仍只有一次，CLI 环境与 worker 私有 stdin 必须来自同一不可变内存快照，禁止覆盖/混源。会话核对与凭据传递约束缺一不可。

### 4.3 目标与批准保持独立

微信目标完整 userId、固定 AppID/环境/地域、计划、轮次、审计键、文件指纹、批准人、写范围、批准期限全部继续绑定。稳定云角色不等于目标微信账号，更不等于已获数据库写权限。

新增明确的 bindingPolicyVersion/expectedStableIdentityDigest，不改变旧 expectedSubjectDigest 的含义。旧路径维持原严格行为；新路径缺字段、未知版本或混用旧/新摘要即拒绝，不做默认升级或回退。新身份模块及所有修改实现均纳入批准指纹。

## 5. 最小接线取舍（待本地实现）

不修改已关闭的只读编排模块输出契约。由 execution-host 复用既有固定 STS 调用能力：

1. 原批准、来源模式、指纹、终态/started 预检仍在取凭据前完成；不移动既有排他记录门槛。
2. 一次取得凭据并建立原有隔离目录。
3. 新增首次完整 STS：先匹配稳定身份，再捕获本轮完整会话摘要。
4. 原三阶段身份/环境关联原样执行。
5. 原额外 STS 改为第二次完整核对：稳定身份与会话均须匹配，然后按既有 started/时效/指纹门槛启动 worker。

此选择比当前四条显式 API 增加一条固定 STS，即五条显式 API（STS 共三条、环境查询两条），换取不重开只读链。不是网络总请求数：凭据命令内部请求和 SDK 内部行为需另计。必须在未来真实执行包中明确列出这一变化，本轮没有执行它。

最小代码范围：可新增一个纯身份解析/摘要模块；修改 execution-host 与 approved-run 的批准绑定、双次核对、净化投影和对应测试。worker/P4/适配器/凭据宿主/只读链/计时器/页面/云函数/vendor 不改。仍保留现有未知结果、禁止重试、排他保存和两条新增记录边界。

## 6. 离线验收要求

- 同角色/主账号/申请账号，跨批次不同会话：稳定摘要相同、会话摘要不同；单轮两次相同会话可通过。同轮中途换会话必须在 worker 前拒绝。
- 同主账号不同角色、同角色不同 PrincipalId、ARN 与 UserId/AccountId 不一致、坏类型、空值、多冒号、超长/非法会话、数字精度风险均拒绝；尾号相同不能放行。
- 预期缺失、版本混用、普通 JSON/复制批准、批准/计划过期、指纹漂移、外来来源模式仍按原门槛拒绝；缺预期须在取凭据前停止，实际身份不匹配须在取得对应 STS 后停止，如实区分时点。
- 真实 host/worker/P4/SDK 本地转换正向，底层传输合成：一次凭据、五条固定 API、同批传递、两写一提交与核对；不得手造成功回执代替。实际网络/真实认证目录触达计数为零，探针能命中守卫。
- 不匹配零 worker/零事务；身份原值、会话名、凭据、异常文本均不进入报告。仅固定枚举、完整摘要、尾号和允许的诊断事实。
- 同轮终态提前拒绝、wx 新建、保存失败不二次保存、resultPersisted/unknownPersisted、未知结果保守核对及期限守卫不回归；不重跑未改模块的全部历史测试。
