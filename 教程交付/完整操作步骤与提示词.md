## 第 3 页：最终要做出哪些东西

来源：视频 00:25–02:03 ＋ 整理补充

1. 需求文档：明确给谁用、有哪些页面、按钮做什么。
2. 微信小程序：用户在手机上查看商品、添加购物车、提交演示订单。
3. 云开发：保存商品、订单、地址，让数据刷新后仍然存在。
4. 网页管理后台：管理员维护商品和订单，并部署成可访问的网址。

教程演示的是开发与数据链路。真实微信支付、退款、库存并发、正式商家经营规则需另行实现与核验；本教程的下单为演示订单，不冒充支付成功。

## 第 4 页：先认识 6 个常见名词

来源：视频 00:50–02:59 ＋ 补充解释

1. Codex：帮你阅读文件、写代码和排查问题的助手。
2. 原型 / OpenDesign：先把页面和操作做出来，确认长什么样。
3. 微信开发者工具 / AppID：调试小程序的软件，以及小程序的唯一编号。
4. CloudBase：提供云数据库、云函数、文件存储和登录等后端能力。

**完成标志：遇到 PRD 时，把它理解为“产品需求说明书”。**

云函数就是运行在云端的一段程序，例如核对用户身份后保存订单。数据库集合可先理解为一类资料的清单。后台管理系统是给管理员使用的网页，与给用户使用的小程序是两个入口。

- 参考资料：https://docs.cloudbase.net/quick-start/frameworks/wechat-miniprogram
- 参考资料：https://cloud.tencent.com/document/product/876/56375

## 第 5 页：账号和工具清单

## 第 6 页：Windows 安装与检查

来源：视频 02:50–03:39 ＋ Windows 补充

1. Node.js 官网选择 LTS 和 Windows 安装包，安装后重开终端。
2. 在 PowerShell 分别运行 node -v 和 npm -v，记录显示的版本。
3. 打开微信开发者工具，用管理员或已授权开发者的微信扫码登录。
4. 打开 Codex 并登录，选择一个专门用于练习的本地文件夹。

**完成标志：两个版本命令有输出，Codex 和微信开发者工具都能打开。**

PowerShell 可从开始菜单搜索打开。如果 npm.ps1 被系统执行策略阻止，先试 npm.cmd -v，避免为了练习修改全局策略。命令无法识别时先重开终端，再检查安装路径，不反复重复安装。已有 Node.js 时先检查是否满足当前项目要求。

- 参考资料：https://nodejs.org/en/download
- 参考资料：https://learn.chatgpt.com/docs/windows/windows-app

## 第 7 页：获取自己的 AppID

来源：视频 02:43–02:54、06:05–06:33 ＋ 补充

1. 打开微信公众平台，注册或登录“小程序”账号。
2. 完成后台要求的账号信息，进入“开发管理 / 开发设置”。
3. 找到 AppID 并保存到自己的项目说明中。
4. 给协作开发者添加权限，确保扫码登录者能看到这个小程序。

**完成标志：创建项目时，能选择或填写自己的 AppID。**

不同版本的后台入口名称可能变化。AppID 是身份编号，AppSecret 是密钥，两者不要混淆。测试号可用于部分练习，但不能据此判断完整云开发和发布能力都可用。

- 参考资料：https://docs.cloudbase.net/quick-start/frameworks/wechat-miniprogram
- 参考资料：https://mp.weixin.qq.com/

## 第 10 页：第二步：准备 OpenDesign

## 第 11 页：新建原型项目

2. 加入 prd.md，确认设计工具能读取需求。
3. 选择移动端目标与高保真原型，先使用一种简洁风格。
4. 视频当时用 iOS 外观模拟手机页面，生成结果仍需后续转换。

**完成标志：项目中能看到需求文档，并能开始生成手机页面。**

“高保真”指接近实际产品的界面效果。当前版本有移动端或小程序原型选项时优先选择相符项；不要把 iOS 原型选项理解为已经生成原生 iOS App 或微信小程序。

## 第 13 页：逐页调整并保存

来源：视频 04:50–05:38

1. 打开原型，走一遍“商品详情、购物车、订单”的路径。
2. 发现问题时，圈选对应位置或截图，说明期望效果。
3. 一次只修改一个明确问题，例如按钮太小、文字遮挡。
4. 效果确认后保存版本，避免后续转换时参照不一致。

**完成标志：页面可读、按钮可点、主要路径能够走通。**

反馈示例：在购物车页面，结算按钮被底部导航遮挡，请增加底部安全间距。保留当前颜色和其他页面。视频演示了局部标记、截图反馈和修改原型的过程。

## 第 14 页：导出原型，交给 Codex

## 第 15 页：第三步：新建微信小程序

- 参考资料：https://docs.cloudbase.net/quick-start/frameworks/wechat-miniprogram

## 第 16 页：项目文件分别负责什么

来源：视频 06:45–08:03 ＋ 整理补充

1. prd.md：功能和业务规则，遇到分歧先看这里。
2. prototype-reference：页面参考，保留原文件。
3. miniprogram：手机页面、交互、样式和图片。
4. cloudfunctions：运行在云端的业务逻辑；docs 存放设计说明。

**完成标志：Codex 和微信开发者工具打开的是同一个项目根目录。**

项目根目录是能同时看到 project.config.json、miniprogram 等文件的那一层。不要一个工具打开父目录、另一个工具打开了不同副本，否则修改不会在模拟器中出现。

## 第 19 页：底部导航和两套图标

## 第 22 页：第四步：创建并记录云环境

AppID 标识小程序，环境 ID 标识云资源，两者不能互填。开发练习使用独立环境，避免初始化脚本影响真实数据。如果小程序已有可用环境，先核对再复用。

## 第 23 页：可复制：接入自己的云环境

来源：视频 14:20–15:10 ＋ 官方补充
